# 开源软件与专有软件

## 定义 {/*#definitions*/}

**开源软件（Open Source Software）**：源代码公开可得。任何人都可以在其许可证条款（如 MIT、GPL、Apache）的约束下查看、修改和分发该软件。

**专有软件（Proprietary Software）**：源代码由供应商保密。使用受许可协议约束，通常禁止修改和再分发。

## 开源 {/*#open-source*/}

### 优点 {/*#advantages*/}

- **免费使用**：在大多数情况下无需许可费用即可使用
- **透明性**：可以审查代码中的安全漏洞和缺陷
- **社区驱动**：可由社区继续开发，而无需完全依赖原始开发者
- **灵活性**：个人可根据自身需求进行定制

### 缺点 {/*#disadvantages*/}

- **支持**：社区支持可能不可靠，对于小型社区甚至可能不存在，或需要额外付费
- **易用性**：与商业替代品相比，界面往往不够精致
- **安全风险**：公开可见的代码同样可能被攻击者分析
- **许可复杂性**：不同的开源许可证可能附带限制（如 copyleft）
- **维护负担**：自行托管需要内部专业知识和时间

### 示例 {/*#examples*/}

- Firefox
- Linux
- React
- VSCode

## 专有软件 {/*#proprietary-software*/}

### 优点 {/*#advantages-1*/}

- **专业支持**：供应商提供带有 SLA 的专门支持
- **精致度与用户体验**：通常在用户体验和文档上投入更高
- **可靠的更新与维护**：经过定期测试的更新和补丁由提供方提供，无需内部专业知识来执行更新。
- **集成**：通常与同一制造商的其他软件具有良好的兼容性

### 缺点 {/*#disadvantages-1*/}

- **成本**：许可费用可能相当可观，尤其是在大规模使用时
- **供应商锁定**：依赖于供应商的路线图和定价
- **缺乏透明性**：无法审查源代码的安全性或质量
- **限制**：除供应商允许的范围外，定制或扩展的能力有限

### 示例 {/*#examples-1*/}

- Microsoft Office
- Windows、iOS、MacOS
- Discord
- Google Chrome

## 比较 {/*#comparison*/}

| | 开源 | 专有 |
| --------------------- | ---------------- | --------------- |
| 源代码 | 公开 | 保密 |
| 成本 | 通常免费 | 许可费用 |
| 支持 | 社区 / 付费 | 由供应商提供 |
| 可定制性 | 高 | 低 |
| 供应商锁定 | 低 | 高 |
| 安全透明性 | 高 | 低 |
