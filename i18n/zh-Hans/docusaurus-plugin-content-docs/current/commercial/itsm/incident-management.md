# 事件管理

## 概述 {/*#overview*/}

**事件管理（Incident Management）** 是 **ITSM 的第一层级**，其重点是帮助用户在 IT 故障后尽快恢复工作。

## 配置项（CI） {/*#configuration-items-ci*/}

**配置项（Configuration Item，CI）** 是一个宽泛的概念，基本涵盖所有硬件和软件。CI 由属性描述，并与其他 CI 相互关联。

| 类别 | 示例 |
| ------------------- | ------------------------------------------------------ |
| 硬件系统 | PC、笔记本电脑、服务器、瘦客户机 |
| 硬件组件 | 显卡、网卡、硬盘、处理器 |
| 软件组件 | 操作系统、应用软件 |
| 网络组件 | 路由器、交换机、集线器、中继器、配线架、NAS |
| 外围设备 | 打印机、扫描仪、网络摄像头 |
| 移动设备 | 平板电脑、智能手机、数据采集设备 |

## 事件的定义 {/*#incident-definition*/}

**事件（incident）** 是指 IT 服务发生的任何计划外中断或质量下降。即使某个事件只是在将来有可能影响 IT 服务，同样属于事件。这也包括更换空墨粉盒之类的小事件。

**首要目标：尽快恢复受影响的服务。**

## 分类 {/*#categorisation*/}

事件在首次记录到问题跟踪系统（Issue Tracking System）时进行分类：

- **HW** = 硬件问题
- **SW** = 软件问题
- **NW** = 网络问题

目的：确保由正确的团队负责，并能正确评估严重程度。

## 优先级排序 {/*#prioritisation*/}

优先级由两个因素决定：

- **紧急度（Dringlichkeit）**：故障对用户目标的影响有多严重？
- **影响范围（Auswirkung）**：有多少人受到故障影响？

[紧急度与影响范围](./priorities.md#itil-priority-matrix)的组合决定了新进工单的处理顺序。

## 支持级别 {/*#support-levels*/}

| 级别 | 说明 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **一线支持（First Level Support）** | 帮助台 / SPOC；借助知识库处理简单问题，并通过直接与客户沟通，充当二线支持的“防火墙” |
| **二线支持（Second Level Support）** | 负责根因分析的专家（[问题管理](./problem-management.md)）；重新评估一线支持设定的初始优先级 |
| **三线支持（Third Level Support）** | 二线支持无法解决问题时，由厂商支持或外部专家介入 |

## 事件记录 {/*#incident-record*/}

**事件记录（Incident Record）** 是包含某一事件全部信息的文档，记录事件从初次登记到解决的整个生命周期。它是一份信息文档，流程实例关闭后不得再修改。

17 个标准组成部分：

1. ID / 标识符
2. 初次登记（日期/时间）
3. 通知类型
4. 服务台坐席
5. 报告人/用户数据
6. 沟通渠道
7. **症状描述**（最重要的字段；有助于诊断并查找解决方案）
8. 受影响的用户、地点和/或业务领域
9. 受影响的服务
10. 优先级
11. CI 引用
12. 事件类别
13. 与其他事件记录的链接
14. 与问题记录的链接
15. 事件状态历史
16. 活动历史 / 任务
17. 解决与关闭数据

**必须始终记录的 5 个关键字段：** 优先级、事件类别、ID、受影响的用户/服务、沟通渠道。

## 重大事件 {/*#major-incident*/}

**重大事件（Major Incident）** 是指高优先级、高影响的事件，会导致关键服务中断或大范围故障，对业务运营造成重大影响。通常被赋予“紧急（Critical）”或“高（High）”优先级。

特征：

- 大量客户或重要客户群体受到影响
- 客户和/或服务组织的成本与损失相当可观
- 服务提供方的声誉很可能受损
- 解决事件所需的工作量和时间很可能很大，现有的 [SLA](./sla.md) 协议很可能被违反

## 服务请求与事件的对比 {/*#service-request-vs-incident*/}

| | 服务请求 | 事件 |
| -------------- | ---------------------------------------------------------- | ------------------------------------------ |
| **触发方式** | 用户主动联系支持人员，提出问题或需求 | 计划外的服务中断 |
| **示例** | 忘记密码、软件使用问题、新工位设置 | 打印机故障、ERP 无法访问、勒索软件 |
| **处理方** | 通常在一线支持中完全解决 | 可能需要升级至二线/三线 |
| **流程** | 请求履行（Request Fulfillment） | 事件管理 |
