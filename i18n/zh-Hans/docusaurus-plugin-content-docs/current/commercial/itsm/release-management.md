# 发布管理

## 概述 {/*#overview*/}

**发布管理（Release Management）** 是 ITSM 的第四层级，也是变更管理的延续。变更管理负责批准和规划变更，而发布管理则负责**执行变更**，目标是实现顺畅、无中断的上线。

## 与变更管理的关系 {/*#relationship-to-change-management*/}

| 变更管理 | 发布管理 |
| ---------------------------------------------------------------- | ------------------------------------------------------------------- |
| 批准并规划变更 | 执行变更 |
| 创建 [RFC](./change-management.md#request-for-change-rfc) | 实施 [RFC](./change-management.md#request-for-change-rfc) |
| 决定做什么以及何时做 | 决定如何做并负责上线 |

## 发布包 {/*#release-package*/}

在上线之前，会创建一个包含所有计划变更的**发布包（release package）**。测试最好在从运行中的生产环境取出的 [CI](./incident-management.md#configuration-items-ci) 上进行，更新后再放回测试环境。经过规定的无问题测试期后，即可将该发布上线到所有目标系统。

软件分发系统有助于将发布高效地分发给大量 [CI](./incident-management.md#configuration-items-ci)。

## 上线方式 {/*#rollout-approaches*/}

### 大爆炸式（Big Bang） {/*#big-bang*/}

所有接收方同时获得该发布。

**优点：**

- 整体实施更快
- 所有系统同时获得相同的更新
- 故障排查更高效（不存在版本差异）

**缺点：**

- 一旦出错，风险很高（所有系统同时受到影响）
- 上线期间对基础设施的负载很高

### 分阶段（Phased） {/*#phased*/}

发布首先在接收方的**一个子集**上线，然后逐步扩展到更多接收方。

**优点：**

- 风险较低（仅部分系统受到影响）
- 能更早发现错误，而不会造成大范围中断

**缺点：**

- 实施耗时更长
- 过渡期间多个软件版本同时运行

## 回滚 {/*#rollback*/}

如果发布在生产环境中意外失败，应始终具备**回滚**到先前状态的能力。上线完成后，通过流程实例将更新情况通知用户。

## 发布管理中的虚拟机 {/*#virtual-machines-in-release-management*/}

**虚拟机（Virtual Machine，VM）：** 对计算机系统的软件封装，在宿主计算机上模拟一台真实的 PC。

**优点：**

- 可以轻松且无风险地创建、启动和修改副本
- 物理系统可以转换为虚拟机（P2V = Physical to Virtual）

**对发布管理的益处：** 新版本、更新和应用程序可以在虚拟机环境中安全地测试。旧版本可以继续并行运行（资源效率）。

## ITSM 流程概览 {/*#itsm-process-overview*/}

ITSM 的四个层级以链条形式协同运作：

| 流程 | 作用 |
| --------------------------------------------------- | ------------------------------------------------------------ |
| [**事件管理**](./incident-management.md) | 记录故障，筛出问题 |
| [**问题管理**](./problem-management.md) | 识别根本原因，尽可能提供临时解决方案 |
| [**变更管理**](./change-management.md) | 批准并规划合理的变更 |
| [**发布管理**](./release-management.md) | 安全地执行变更 |

**这种划分的原因：** 对流程进行编排，旨在实现可持续性，并为复杂的工作流带来结构。

## ITSM 流程与 [IMAC/R/D 阶段](./service-types.md#imacrd-lifecycle) {/*#itsm-processes-and-imacrd-phases*/}

| IMAC/R/D 活动 | 相关 ITSM 流程 |
| -------------------------- | ------------------------------------------------------------------------------ |
| Wartung（维护） | 变更管理、发布管理 |
| Inspektion（检查） | 问题管理、变更管理、发布管理 |
| Instandsetzung（修复） | 事件管理、问题管理、变更管理、发布管理 |
| Verbesserung（改进） | 变更管理、发布管理 |
