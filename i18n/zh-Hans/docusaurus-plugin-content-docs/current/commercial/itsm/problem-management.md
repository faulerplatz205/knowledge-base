# 问题管理

## 概述 {/*#overview*/}

问题管理是**事件管理的第二层级**。事件管理侧重于尽快恢复服务，而问题管理则识别并消除根本原因，以防止未来再次发生事件。

## 事件、问题与已知错误的对比 {/*#incident-vs-problem-vs-known-error*/}

| 术语 | 定义 |
| --------------- | --------------------------------------------------------------------------------------- |
| **事件（Incident）** | 计划外的服务中断；原因可能未知；优先恢复服务 |
| **问题（Problem）** | 一个或多个**根因未知**的事件；由专家调查 |
| **已知错误（Known Error）** | 根因已知，且已有临时解决方案或修复方法的问题 |

如果在一线支持中找不到解决方案，则工单将被**升级**：该事件成为由二线支持管理的问题。

## 问题管理的三项活动 {/*#the-three-activities-of-problem-management*/}

### 1. 问题控制 {/*#1-problem-control*/}

系统地分析并记录所有问题。目标是将未知原因转变为**已知错误**。

步骤：

1. 记录问题，并与已知错误数据库进行比对
2. 如果已存在临时解决方案/解决方案 => 已知错误，更新发生次数计数器
3. 对问题进行分类（类别、子类别、优先级、业务影响）
4. 分析根因（参见[分析方法](./analysis-methods.md)）
5. 将结果作为新的已知错误记录到 KEDB 中

### 2. 错误控制 {/*#2-error-control*/}

已知错误一旦存在，错误控制便负责管理从临时解决方案到永久修复的过程。

- 立即提供**临时解决方案**（Workaround）以恢复服务
- 通过 [**RFC**](./change-management.md#request-for-change-rfc) 启动永久修复
- 变更实施后，问题管理通过[**实施后评审（PIR）**](./change-management.md#closing-a-change-pir)收到确认
- 通知一线支持，以便其向客户更新情况

### 3. 主动问题管理 {/*#3-proactive-problem-management*/}

在事件发生之前加以预防：

- 分析频繁复发的已知错误（发生次数计数器较高 = 主动问题管理的候选对象）
- 评估厂商关于即将出现的软件/硬件问题的提示
- 监控自动警告和异常

## 临时解决方案 {/*#workaround*/}

**临时解决方案（workaround）** 是对问题的规避、替代或过渡性方案（即“绕过”问题），用于在处理根本原因期间快速临时恢复服务。

**重要：** 临时解决方案必须在系统中明确标记为临时措施，以免这种临时修复成为永久状态。

**示例：**

| 故障 | 临时解决方案 |
| ------------------------------------ | ---------------------------------------------- |
| 内置摄像头损坏 | 连接 USB 摄像头 |
| 移动数据采集设备损坏 | 使用借用设备 |
| 有线网络端口损坏 | 使用 WLAN 网卡或 LAN 适配器 |
| DVI 显示器接口损坏 | 如有条件，使用 DisplayPort 或 HDMI |
| 激光打印机无法启动 | 断开电源后重新启动 |
| 浏览器显示空白页 | 清除浏览器缓存或改用其他浏览器 |

## 已知错误数据库（KEDB） {/*#known-error-database-kedb*/}

KEDB 存储所有已知问题及其临时解决方案或解决方案。一线支持借助它提供快速帮助，而无需升级到二线。

每个条目都有一个**发生次数计数器**（Vorfallszähler），用于记录该问题复发的频率。计数器数值较高，表明该条目是主动问题管理的候选对象。

## 关键 KPI {/*#key-kpis*/}

| KPI | 含义 |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **新问题数量** | 某一时期内登记的问题总数；主动问题管理旨在通过在错误演变为事件之前加以解决，使该数量降至最低 |
| **每个已知问题的事件数量** | 与同一问题相关联的事件平均数量；显示影响的广泛程度，并识别出主动问题管理的候选对象 |
| **问题解决工作量** | 解决一个问题的平均工作量，按类别细分；显示哪些类别需要最多的工作量 |

## 问题定位与问题解决的分离 {/*#separation-of-problem-localisation-and-problem-resolution*/}

问题管理负责定位根本原因；[变更管理](./change-management.md)负责解决。这种分离：

- 使人能够一次专注于一项任务
- 能够在根因调查完成之前先恢复服务（临时解决方案）
- 不一定涉及不同的团队，但将各流程步骤区分开来
