# 事态管理

## 概览 {/*#overview*/}

**事态**不需要用户直接报告。它们由监控系统自动生成，是关于系统状态的状态消息。"事态"一词可理解为触发器或传入的通知，并按相关性分类。

软件支持可实现过滤，并可配置为将异常消息尽快转发给责任方。

## 事态类型 {/*#event-types*/}

### 信息 {/*#information*/}

**无需采取任何行动的系统状态消息**。

系统运行正常，无需干预。

**示例：** 网络利用率在 45 % 至 48 % 之间。

### 警告 {/*#warning*/}

**表明需要更密切监控的状态消息**；可能很快需要采取行动。警告表明问题正在逼近。

**示例：** RAID 数据阵列报告剩余容量为 20 %。

### 异常 {/*#exception*/}

**需要立即采取行动的状态消息**。系统或服务已发生故障或超过临界阈值。异常通常会引发[事件](./incident-management.md)（Incident）。

**示例：** 48 端口网络交换机发生故障。

## 事态分类示例 {/*#event-classification-examples*/}

| 事态                                       | 类型 | 原因                                     |
| ------------------------------------------ | ---- | ---------------------------------------- |
| 硬盘容量达到 80 %                          | 警告 | 目前还不是问题，但可能很快成为问题       |
| 网络在 40 % 负载下稳定运行                 | 信息 | 正常系统状态                             |
| 基于 Web 的 ERP 系统无法访问               | 异常 | 需要立即采取行动的中断                   |
| Web 服务器在 85 % 负载下稳定运行           | 警告 | 负载高，接近临界                         |
| 50 个 User CAL 许可证中已使用 48 个        | 警告 | 即将达到许可证上限；超出则成为异常       |
| 已连接 52 台设备，但只有 50 个 Device CAL 许可证 | 异常 | 已超出许可证上限                   |
