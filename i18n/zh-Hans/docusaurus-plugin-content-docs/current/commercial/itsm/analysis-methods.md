# 问题分析方法

## 概览 {/*#overview*/}

这些方法用于[问题管理](./problem-management.md)，以系统地查找问题的根本原因。

## 5-Why 法（5-W-Methode） {/*#5-why-method-5-w-methode*/}

**目标：** 通过反复追问"为什么？"来查找问题的根本原因，每个答案成为下一个问题。通常五轮即可。

**示例（打印机问题）：**

| 步骤   | 问题                         | 答案                                   |
| ------ | ---------------------------- | -------------------------------------- |
| 问题   | 打印机打印不清晰             |                                        |
| 为什么？ | 为什么打印机打印不清晰？   | 没有清晰显示所有字符 / 输出难以辨认    |
| 为什么？ | 为什么没有清晰显示所有字符？ | 墨水/碳粉质量差                      |
| 为什么？ | 为什么墨水/碳粉质量差？    | 会洇开，有时完全不出墨                 |
| 为什么？ | 为什么会洇开且有时不出墨？ | 碳粉质量低                             |
| 为什么？ | 为什么碳粉质量低？         | **购买了最便宜的碳粉**（根本原因）     |

## 石川图（鱼骨图） {/*#ishikawa-diagram-fishbone-diagram*/}

**石川图**（也称**因果图**或**鱼骨图**）由日本学者石川馨于 20 世纪 40 年代提出，用于将问题的原因可视化。

**结构：**

- 指向右侧的水平箭头 => **箭头尖端为问题描述**（结果）
- 从水平线伸出的斜向箭头 => **主要影响类别**（"鱼骨"）
- 从斜向主骨伸出的较小箭头 => **次要原因**（Nebenursachen）

**箭头含义：** 每个箭头都"促成"尖端所描述的结果。

### 主要影响类别（8M） {/*#main-influence-categories-8m*/}

- Category（类别）
- Material（材料）
- People（人员）
- Machine（机器）
- Method（方法）
- Management（管理）
- Environment（环境）
- Measurement（测量）
- Money（资金）

根据问题的不同，也可以采用其他影响类别。

### 绘制石川图 {/*#creating-an-ishikawa-diagram*/}

1. 在水平箭头的尖端（最右侧）写下问题描述
2. 确定主要影响类别（8M）
3. 通过团队头脑风暴找出主要原因（绘制为与水平轴平行的箭头）
4. 为每个主要原因找出次要原因（绘制为从主要原因箭头分出的斜向箭头）

## DMAIC 循环 {/*#dmaic-cycle*/}

**DMAIC 循环**用于复杂的问题和项目。该缩写代表五个阶段：

| 阶段                  | 关键问题                 | 方法 / 工具                                                                                              |
| --------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------- |
| **Define（定义）**    | 问题是什么？             | 客户反馈、问题定义、范围、KPI 分析、RACI 矩阵                                                            |
| **Measure（测量）**   | 问题有多大？             | IST 现状分析、[SLA](./sla.md) 审查、明确升级级别                                                         |
| **Analyse（分析）**   | 根本原因是什么？         | 5-Why 法、客户调查、[错误数据库](./problem-management.md#known-error-database-kedb)、石川图              |
| **Improve（改进）**   | 能否制定解决方案？       | 模拟、试运行、解决方案矩阵、石川图                                                                       |
| **Control（控制）**   | 能否巩固改进成果？       | 监控、服务管理系统                                                                                       |

## 问题解决矩阵 / 因果矩阵（Problemlösungsmatrix / Ursachen-Wirkungs-Matrix） {/*#problemlösungsmatrix--ursachen-wirkungs-matrix*/}

**因果矩阵**（基于 Kepner-Tregoe 方法）沿四个维度分析问题，通过比较"是"什么情况与"不是"什么情况，系统地缩小根本原因的范围：

| 维度                  | 是（问题）                 | 不是（问题）             | 偏差                       | 可能的原因         |
| --------------------- | -------------------------- | ------------------------ | -------------------------- | ------------------ |
| **识别（什么）**      | 问题是什么？               | 什么不是问题？           | 现状与目标状态有何差异？   | 可能的原因是什么？ |
| **定位（哪里）**      | 问题发生在哪里？           | 在哪里没有发生？         | 该位置有何不同？           | 可能的原因是什么？ |
| **时间（何时）**      | 问题何时出现？             | 何时没有出现？           | 当时有何不同？             | 可能的原因是什么？ |
|                       | 问题是在哪个时间段发现的？ | 在哪个时间段没有出现？   | 该时间段内有何不同？       |                    |
| **程度（多大）**      | 问题有多大 / 多广泛？      | 有多小或多有限？         | 范围上有何差异？           | 可能的原因是什么？ |
|                       | 有多少（单元）受影响？     | 有多少（单元）未受影响？ |                            |                    |
|                       | 哪个部分受影响？           | 哪个部分未受影响？       |                            |                    |
