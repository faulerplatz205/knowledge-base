# IT 支持中的优先级排序

## 概述 {/*#overview*/}

IT 支持中主要使用两种优先级排序工具：**ITIL 优先级矩阵**和**艾森豪威尔矩阵**。

## ITIL 优先级矩阵 {/*#itil-priority-matrix*/}

### 紧急度等级 {/*#urgency-levels*/}

| 等级 | 说明 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **高（H）** | 事件造成的损害迅速扩大。无法完成的任务时间要求极为紧迫。迅速采取行动可防止次要事件演变为[重大事件](./incident-management.md#major-incident)。多名 VIP 用户受到影响。 |
| **中（M）** | 损害随时间推移而增加。无法完成的任务仅有中等程度的时间要求。一名 VIP 用户受到影响。 |
| **低（N）** | 损害不会随时间推移而增加。无法完成的任务没有时间要求。 |

### 影响范围等级 {/*#impact-levels*/}

| 等级 | 说明 |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **高（H）** | 大量员工受到影响和/或无法完成其任务。大量客户受到影响或严重受损。可能造成的财务损失 > 10,000 EUR。可能造成大范围的声誉损害。危及生命和健康。 |
| **中（M）** | 中等数量的员工受到影响和/或无法按计划完成任务。中等数量的客户受到影响或使用舒适度受限。可能造成的财务损失为 1,000–10,000 EUR。可能造成中等程度的声誉损害。 |
| **低（N）** | 极少数员工受到影响；仍可完成任务，但需额外付出努力。极少数客户受到影响；仅有轻微的舒适度限制。可能造成的财务损失 < 1,000 EUR。预计仅有极小的声誉损害。 |

### 优先级矩阵 {/*#priority-matrix*/}

**紧急度 x 影响范围矩阵**得出从 1（最紧急）到 5（最低）的优先级等级：

| | **影响范围 H** | **影响范围 M** | **影响范围 N** |
| ------------- | ------------ | ------------ | ------------ |
| **紧急度 H** | **1** | 2 | 3 |
| **紧急度 M** | 2 | **3** | 4 |
| **紧急度 N** | 3 | 4 | **5** |

### 优先级代码与 [SLA](./sla.md) 响应/解决时间 {/*#priority-codes-and-sla-responseresolution-times*/}

| 优先级 | 说明 | 响应时间 | 解决时间 |
| -------- | ----------------------- | ------------- | --------------- |
| **1** | Kritisch（紧急） | 立即 | 1 小时 |
| **2** | Hoch（高） | 10 分钟 | 4 小时 |
| **3** | Mittel（中） | 1 小时 | 8 小时 |
| **4** | Niedrig（低） | 4 小时 | 24 小时 |
| **5** | Sehr niedrig（极低） | 1 天 | 1 周 |

## 艾森豪威尔矩阵 {/*#eisenhower-matrix*/}

**艾森豪威尔矩阵**是一种时间管理方法，用于区分重要任务与紧急任务。以美国总统德怀特·D·艾森豪威尔（1953–1961 年在任）命名。又称四象限法、艾森豪威尔法或艾森豪威尔盒。

**目标：** 不是把事情做对，而是做对的事情（强调有效性，而不仅是效率）。

每项任务对应两个问题：

1. 该任务有多重要？
2. 该任务有多紧急？

### 四个象限 {/*#the-four-quadrants*/}

| | **紧急** | **不紧急** |
| ----------------- | --------------------------------- | ----------------------------------------- |
| **重要** | **A：立即做**（亲自处理） | **B：计划**（制定计划并设定截止日期） |
| **不重要** | **C：委派**（或自动化） | **D：舍弃**（归档或删除） |

### 原则 {/*#principles*/}

- 重要任务是与既定目标直接相关的任务
- 紧急任务不容拖延，最好立即处理
- 既重要又紧急的任务：亲自处理，尽快完成
- 紧急但不重要的任务：尽可能委派或自动化；若无法做到，则在 A 类任务之后处理
- 重要但不紧急的任务：制定计划并安排时间；优先级低于 A 类任务
- 既不重要也不紧急的任务：不予处理；视情况归档或删除

## 对比：ITIL 矩阵与艾森豪威尔矩阵 {/*#comparison-itil-matrix-vs-eisenhower-matrix*/}

| 标准 | ITIL 优先级矩阵 | 艾森豪威尔矩阵 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| **用途** | 为 IT [事件](./incident-management.md)/[问题](./problem-management.md)/[变更](./change-management.md)排定优先级 | 为个人或团队任务排定优先级 |
| **维度** | 紧急度 x 影响范围（面向业务） | 紧急度 x 重要性（面向目标） |
| **等级** | 5 个优先级，带有明确的 [SLA](./sla.md) 时间 | 4 个象限，各对应相应行动 |
| **最适用于** | IT 服务台、结构化团队 | 自我管理、一般任务组织 |
| **实用性** | 客观、标准化、可扩展 | 更简单、更灵活、结构性较弱 |
