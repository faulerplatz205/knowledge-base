# 数据库概述

## 概述 {/*#overview*/}

数据库是由数据库管理系统（DBMS）管理的有组织的结构化数据集合。两种主要范式是**关系型**（SQL）数据库和**非关系型**（NoSQL）数据库。

## 关系型数据库（SQL） {/*#relational-databases-sql*/}

数据存储在由行和列组成的**表**中。每条数据记录可通过**主键**唯一标识，表之间通过**外键**关联，从而形成结构化的模式。

- 使用 **SQL**（Structured Query Language，结构化查询语言）查询数据
- 模式预先定义，并由数据库强制执行
- 最适合具有明确关系的结构化数据

**常见系统**：PostgreSQL、MySQL、SQLite、Microsoft SQL Server、Oracle DB

### 关键概念 {/*#key-concepts*/}

**[规范化](./normalization.md)**：组织表结构以减少数据冗余：

- **1NF**：原子值，无重复组
- **2NF**：对复合键无部分依赖
- **3NF**：无传递依赖

**ACID 特性**：可靠事务的保证：

- **原子性（Atomicity）**：事务要么完全成功，要么完全失败
- **一致性（Consistency）**：数据始终从一个有效状态转移到另一个有效状态
- **隔离性（Isolation）**：并发事务互不干扰
- **持久性（Durability）**：已提交的更改即使在崩溃后依然保留

## 非关系型数据库（NoSQL） {/*#non-relational-databases-nosql*/}

旨在灵活、可扩展地存储非结构化或半结构化数据。不需要固定的模式。

| 类型          | 描述                                 | 示例系统  |
| ------------- | ------------------------------------------- | ---------------- |
| 文档型      | 存储类 JSON 文档                  | MongoDB、CouchDB |
| 键值型     | 简单的键 => 值对                   | Redis、DynamoDB  |
| 列族型 | 针对按列读写进行优化         | Apache Cassandra |
| 图型         | 用节点和边表示关系密集的数据 | Neo4j            |

## 关系型与 NoSQL 对比 {/*#relational-vs-nosql*/}

|                | 关系型                     | NoSQL                                      |
| -------------- | ------------------------------ | ------------------------------------------ |
| 模式         | 固定、预定义              | 灵活 / 无模式                     |
| 查询语言 | SQL                            | 各不相同（例如 MongoDB 查询语言）      |
| 扩展方式        | 纵向（向上扩展）            | 横向（向外扩展）                     |
| 一致性    | 强一致（ACID）                  | 通常为最终一致性                 |
| 最适合       | 结构化数据、复杂连接 | 大规模、灵活或层级化的数据 |
