# 数据库开发阶段

数据库开发通常分为四个相继的阶段，每个阶段产出的成果都比上一阶段更具体。

## 1. 外部阶段 {/*#1-external-phase*/}

收集并分析所有未来用户和相关方群体的需求。目标是弄清系统必须管理哪些数据、必须支持哪些操作，而暂不考虑数据库将如何构建。

典型成果是需求文档以及对数据和业务规则的非正式描述。

## 2. 概念阶段 {/*#2-conceptual-phase*/}

将需求转化为抽象的、与实现无关的数据模型。其标准工具是[**实体-联系模型（ERM）**](./er-model.md)，它描述实体、实体的属性以及实体之间的联系。

概念模型与技术无关：它描述数据*是什么样的*，而不是数据*如何*存储。

## 3. 语义阶段 {/*#3-semantic-phase*/}

通过精确定义完整性约束、基数和业务规则，对概念模型进行细化和形式化。随后 ERM 被转换为[**关系数据库模式**](./database-schema.md)（表、列、主键、外键）。

该阶段还包括[**规范化**](./normalization.md)，用于消除冗余和异常。

## 4. 物理阶段 {/*#4-physical-phase*/}

在具体的 DBMS（例如 PostgreSQL、MySQL）中实现关系模型。该阶段包括：

- 编写带有适当数据类型的 `CREATE TABLE` 语句
- 定义索引以优化查询性能
- 配置所选 DBMS 特有的存储参数
- 设置访问控制和安全策略

物理模型与目标系统紧密耦合，不同 DBMS 产品之间可能有所不同。
