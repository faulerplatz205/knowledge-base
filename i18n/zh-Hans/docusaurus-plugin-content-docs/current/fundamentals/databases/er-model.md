# ER 模型

实体-联系（ER）模型是一种概念数据模型，在高层次上描述数据库的结构，且独立于任何具体的数据库系统。它由 Peter Chen 于 1976 年提出。在下一个设计步骤中，ER 模型被转换为由表、主键和外键构成的[数据库模式](./database-schema.md)。

## 核心概念 {/*#core-concepts*/}

### 实体 {/*#entities*/}

实体，也称为**实体实例**，是现实世界或思维中可被唯一标识的对象，例如某个特定的客户或某个特定的订单。同类实体被归入**实体类型**（例如 `Customer`、`Product`、`Order`）。

### 属性 {/*#attributes*/}

属性描述实体类型的特性。

| 类型        | 描述                     | 示例                         |
| ----------- | ------------------------------- | ------------------------------- |
| 简单      | 原子的、不可再分的值       | `FirstName`、`Age`              |
| 复合   | 由子属性组成       | `Address` = (Street, City, ZIP) |
| 多值 | 可以包含多个值        | `PhoneNumbers`                  |
| 派生     | 由另一个属性计算得出 | `Age` 派生自 `BirthDate`  |

**键属性**唯一标识每个实体实例，例如 `CustomerID`。它随后成为数据库模式中的主键。

### 联系 {/*#relationships*/}

联系描述两个或多个实体类型之间的关联。与实体一样，联系被归入**联系类型**（例如，一个 `Customer` *下达* 一个 `Order`）。联系类型本身表达了这种关联，因此 ER 模型中不含外键。外键只在模型被转换为数据库模式时才会出现。联系也可以有自己的属性（例如，`WorksFor` 联系可以带有 `StartDate`）。

## 基数 {/*#cardinality*/}

基数定义一个实体的多少个实例可以与另一个实体的实例相关联。

| 类型 | 描述                               | 示例                                                             |
| ---- | ----------------------------------------- | ------------------------------------------------------------------- |
| 1:1  | 一个实例恰好与另一个实例相关联 | 一个人持有一本护照                                         |
| 1:N  | 一个实例与多个其他实例相关联       | 一个客户下达多个订单                                     |
| N:M  | 多个实例与多个其他实例相关联      | 学生选修多门课程；课程有多名学生 |

**参与度**进一步规定是否每个实体实例都必须参与某个联系：

- **全部参与**（必须）：每个实例都必须处于至少一个联系中，例如每个订单都必须属于某个客户。
- **部分参与**（可选）：部分实例可以不参与，例如并非每个客户都下过订单。

## 弱实体 {/*#weak-entities*/}

**弱实体**无法仅凭自身属性被唯一标识。其标识依赖于**强（所有者）实体**。

- 弱实体具有**部分键**（鉴别符），仅在其所有者的范围内唯一。
- 将弱实体与其所有者相连的联系称为**标识性联系**。
- 弱实体在其标识性联系中始终是全部参与。

**示例：**`OrderItem` 是弱实体。其部分键 `LineNumber` 仅在特定的 `Order` 内唯一。完整标识是 `(OrderID, LineNumber)`。

## 表示法 {/*#notation*/}

| 元素                         | 表示                                 |
| ------------------------------- | ------------------------------------------ |
| 矩形                       | 实体类型                                |
| 双线矩形          | 弱实体类型                           |
| 菱形                         | 联系类型                          |
| 双线菱形            | 标识性联系                   |
| 椭圆                         | 属性                                  |
| 名称带下划线的椭圆 | 键属性                              |
| 带虚线下划线的椭圆 | 弱实体的部分键               |
| 双线椭圆            | 多值属性                      |
| 虚线椭圆                  | 派生属性                          |
| 带有更多椭圆的椭圆   | 复合属性及其子属性 |
| 单线                     | 部分参与                      |
| 双线                     | 全部参与                        |
| 线旁的 `1`、`N`、`M`    | 基数                                |

**重要：**与[表图](./database-schema.md#table-diagram)或 [UML 类图](../uml/class-diagram.md)不同，实体的属性不写在其矩形内部。每个属性都有自己的椭圆，并通过线与实体相连。

## 常见错误 {/*#common-mistakes*/}

1. **属性写在实体矩形内部：**带有列清单的矩形是数据库模式的表，而不是 Chen 实体类型。
2. **将外键作为属性：**`Order` 的属性 `CustomerID` 重复了 `places` 联系，只应作为外键出现在数据库模式中。
3. **在 Chen 图中使用 UML 多重性：**Chen 不使用 `1..*` 或 `0..1` 之类的 UML 范围，而是使用 `1`、`N` 和 `M`，并通过单线或双线表达最小值。
4. **没有标识性联系的弱实体：**双线矩形需要一个双线菱形将其与所有者相连。
