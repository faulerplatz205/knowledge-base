# 编译器与解释器

## 概述 {/*#overview*/}

处理器只能执行机器码。因此，用高级语言编写的源代码必须先经过翻译。存在两种基本方式：

- **编译器**：在执行**之前**将整个程序翻译为独立的、机器可读的产物
- **解释器**：在执行**期间**读取源代码，并立即执行每条语句

一种语言是编译型还是解释型，是**实现**的属性，而不是语言本身的属性。C 通常被编译，但也存在 C 解释器；JavaScript 在历史上是解释执行的，而现代引擎会在运行时对其进行编译。

---

## 编译器 {/*#compiler*/}

### 翻译过程 {/*#translation-process*/}

翻译通常分为若干阶段：

1. **词法分析**：将字符流拆分为词法单元（关键字、标识符、运算符）
2. **语法分析**：按照文法检查词法单元，并生成语法树
3. **语义分析**：验证类型兼容性、声明和作用域
4. **优化**：改进中间表示（例如消除死代码、循环展开）
5. **代码生成**：输出机器码，通常为目标文件

随后，**链接器**将目标文件与所需的库组合成可执行程序。

```text
Source Code => [Compiler] => Object Code => [Linker] => Executable => [CPU]
```

错误在编译时报告，因此存在语法或类型错误的程序永远不会进入执行阶段。

### 优点 {/*#advantages*/}

- **执行速度**：翻译后的机器码直接在处理器上运行
- **尽早发现错误**：语法错误和许多语义错误在程序交付之前就会暴露
- **优化**：整个程序可见，因而可以进行大量优化
- **源代码保护**：只需分发编译后的产物
- **无运行时依赖**：目标系统无需安装编译器工具

### 缺点 {/*#disadvantages*/}

- **编译时间**：每次修改都需要重新构建后才能测试
- **平台依赖**：机器码与处理器架构和操作系统绑定，因此每个目标平台都需要单独构建
- **调试成本**：执行的机器码与源代码已不相似，需要调试符号

## 解释器 {/*#interpreter*/}

解释器逐条读取源代码，对其进行分析并立即执行。不会生成单独的可执行文件。目标系统上必须存在解释器。

```text
Source Code => [Interpreter] => Statement analysed and executed => [CPU]
```

只有执行到相关代码行时，错误才会显现。因此，很少使用的分支中的语法错误可能长期不被发现。

### 优点 {/*#advantages-1*/}

- **开发周期短**：修改后的代码可以立即执行，无需构建步骤
- **平台无关**：同一份源代码可在任何有解释器的地方运行
- **调试更容易**：错误报告会指向原始源代码行
- **灵活性**：代码可以在运行时生成并执行

### 缺点 {/*#disadvantages-1*/}

- **执行速度**：每次运行都会产生翻译开销，循环内的代码还会重复产生
- **错误发现较晚**：错误只在运行时出现
- **运行时依赖**：目标系统上必须安装解释器
- **源代码泄露**：程序通常以可读的源代码形式交付

## 字节码与虚拟机 {/*#bytecode-and-virtual-machines*/}

大多数现代平台结合了这两种方式。源代码被编译为**字节码**，这是一种不依赖特定处理器的紧凑中间代码。随后由**虚拟机**（VM）在目标系统上执行该字节码。

```text
Source Code => [Compiler] => Bytecode => [Virtual Machine] => Machine Code => [CPU]
```

| 平台  | 编译器 | 中间代码                  | 运行时                       |
| --------- | -------- | ---------------------------------- | ----------------------------- |
| Java      | `javac`  | 字节码（`.class`）                | JVM（Java 虚拟机）    |
| C# / .NET | `csc`    | CIL（通用中间语言） | CLR（公共语言运行时） |
| Python    | 内置 | 字节码（`.pyc`）                  | Python VM                     |

这样就分离了两个与平台相关的环节：编译器只运行一次并生成可移植的字节码，而只有虚拟机需要针对每个平台实现。由此形成*一次编写，到处运行*的原则，代价是程序与硬件之间多出一层。

## 即时编译 {/*#just-in-time-compilation*/}

**即时编译器**（JIT）是虚拟机的一部分。字节码起初被解释执行，运行时会记录各部分被执行的频率。频繁使用的部分，即所谓的*热点*，会在运行时被编译为本机机器码并缓存，使后续调用以本机速度运行。

```text
Bytecode => [Interpretation + Profiling] => hot code => [JIT Compiler] => cached Machine Code
```

### 优点 {/*#advantages-2*/}

- **接近本机的速度**，同时保留字节码的可移植性
- **运行时信息**（如实际数据类型和分支频率）使得静态编译器无法进行的优化成为可能

### 缺点 {/*#disadvantages-2*/}

- **预热阶段**：最初几次执行较慢，这对短时间运行的程序较为明显
- **内存消耗**：性能剖析数据和已编译代码会占用额外内存
- **时序较难预测**：执行期间的编译使运行时间产生波动，这对实时系统是个问题

与之相对的是**提前编译**（AOT），即在执行前将字节码完全翻译。这消除了预热阶段并缩短了启动时间，但会失去运行时信息，因此用于命令行工具或无服务器函数等短生命周期的进程。

### JIT 与 AOT {/*#jit-vs-aot*/}

| 标准                 | 即时编译（JIT）                           | 提前编译（AOT）                          |
| ------------------------- | -------------------------------------------- | -------------------------------------------- |
| 翻译时间点      | 运行时，针对频繁使用的代码         | 完全在执行之前                  |
| 启动时间              | 慢，有预热阶段                          | 快，无预热                             |
| 峰值性能          | 高，通过运行时优化           | 有限，仅有静态优化            |
| 优化依据    | 实际运行时剖析数据（热点、类型）    | 仅有静态代码分析                    |
| 内存消耗        | 较高，剖析数据和代码缓存        | 较低                                        |
| 时序可预测性     | 有波动                                  | 可预测                                  |
| 动态语言特性 | 不受限制                                 | 受限，需要配置           |
| 典型用例         | 长时间运行的服务器和桌面应用 | 短生命周期进程、CLI 工具、无服务器 |

## 转译器 {/*#transpiler*/}

**转译器**（源到源编译器）将源代码翻译为同一抽象层级的另一种语言的源代码，而不是机器码。典型示例是被转译为 JavaScript 的 TypeScript，以及被转译为 CSS 的 Sass。

```text
TypeScript => [Transpiler] => JavaScript => [Engine with JIT] => Machine Code
```

---

## 比较 {/*#comparison*/}

| 标准                    | 编译器                    | 解释器                              |
| ---------------------------- | --------------------------- | ---------------------------------------- |
| 翻译时间点         | 完全在执行之前 | 执行期间，逐条语句 |
| 结果                       | 可执行文件             | 无单独产物                     |
| 执行速度              | 高                        | 低                                      |
| 错误检测              | 编译时                | 运行时，仅限已执行的代码        |
| 开发周期            | 较慢，需要构建      | 较快，立即执行              |
| 平台无关性        | 低，每个平台一次构建 | 高，需要解释器            |
| 对目标系统的要求 | 无                        | 必须安装解释器            |
| 源代码保护       | 有                       | 通常没有                         |

## 典型代表 {/*#typical-representatives*/}

- **编译为机器码**：C、C++、Rust、Go、Delphi
- **解释执行**：Shell 脚本、Perl、PHP、Ruby、Python
- **字节码加 VM 与 JIT**：Java、Kotlin、C#，以及 V8 等引擎中的 JavaScript
