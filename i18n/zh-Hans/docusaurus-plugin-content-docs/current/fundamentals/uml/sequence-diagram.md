# 序列图

## 概述 {/*#overview*/}

序列图是一种**行为型** UML 图，属于*交互图*一类。它展示哪些通信参与者交换哪些消息，以及这些消息的先后顺序。参与者并排排列，时间自上而下流动。

典型应用：

- 细化[用例](./use-case-diagram.md)的单个场景，通常是主流程加一个异常流程
- 记录对象或组件为实现某项功能而进行的协作
- 描述系统之间的协议，例如客户端、服务器和数据库
- 双向对照[类图](./class-diagram.md)审查设计草案：没有任何类提供对应操作的消息暴露出缺失的操作，没有收到任何消息的生命线则暴露出无法到达的类

序列图始终只展示*一次*具体的运行。备选和重复可通过组合片段表达，但试图一次覆盖所有情况的图会变得难以阅读。因此多张小图优于一张大图。

## 符号 {/*#notation*/}

| 元素         | 符号                                                   | 含义                                           |
| ------------ | ------------------------------------------------------ | ---------------------------------------------- |
| 框架         | 带五边形标签的矩形，标签内为 `sd` 加名称            | 交互的边界和名称                               |
| 生命线头部   | 含 `name : Class`、`:Class` 或 `name` 的矩形                  | 一个通信参与者、对象、组件或参与者（actor）    |
| 生命线       | 头部下方的垂直虚线                                     | 该参与者随时间的存在                           |
| 执行规约     | 生命线上的窄矩形（激活条）                             | 参与者处于活动状态或正在处理调用的时间段       |
| 同步消息     | 实线，实心箭头 `──▶`                                 | 发送方等待直到收到回复                         |
| 异步消息     | 实线，开放箭头 `──>`                                 | 发送方立即继续，不等待                         |
| 回复消息     | 虚线，开放箭头 `<- - -`                                 | 控制权返回，可选择标注返回值                   |
| 自消息       | 离开并重新进入同一条生命线的箭头                       | 参与者调用自身的某个操作                       |
| 创建消息     | 指向生命线头部的虚线箭头，带 `«create»`                   | 接收方在交互过程中产生                         |
| 销毁事件     | 生命线下端的叉号 `X`                               | 对象被销毁，生命线在此结束                     |
| 组合片段     | 左上角标有操作符的矩形                                 | 控制结构，例如 `alt`、`opt`、`loop`、`par` |
| 操作数       | 片段的一部分，以虚线分隔                               | 片段内的一种情况或一个分支                     |
| 守卫         | 操作数开头的 `[condition]`                                   | 该操作数适用的条件                             |
| 交互使用     | 操作符为 `ref` 的片段                                | 引用另行绘制的交互                             |
| 状态不变式   | 生命线上的 `{condition}`                                     | 在该时间点必须成立的条件                       |
| 注释         | 虚线连接的折角矩形                                     | 无语义的说明                                   |

保持图可读的命名规则：

- 消息带有被调用操作的签名，例如 `reserve(seatNo)`，而不是 `the seat is reserved` 这样的句子
- 回复标注返回值，而不是再次标注操作名
- 生命线以对象命名，而不是以动作命名：`:SeatRepository` 是参与者，`Save seat` 不是
- 匿名对象写作 `:Class`，具名对象写作 `seat : Seat`，角色仅写其名称

## 构成要素 {/*#building-blocks*/}

### 生命线、执行规约与回复 {/*#lifeline-execution-specification-and-reply*/}

从一个参与者发往另一个参与者的消息会在接收方上开启一个执行规约，回复则将其结束。同步消息适用于调用方在继续之前需要结果的调用，例如方法调用或等待响应的 HTTP 请求。

```text
   :Client                  :AuthService
      │                           │
     ┌┴┐                          │
     │ │─── login(user, pw) ────▶┌┴┐
     │ │                         │ │
     │ │<- - - - - token - - - - └┬┘
     │ │                          │
     └┬┘                          │
      │                           │
```

如果回复不携带任何信息，可以省略。

### 异步消息 {/*#asynchronous-message*/}

异步消息发出后，发送方无需等待即可继续。它适用于事件、通知、发往队列的消息，以及在独立线程中运行且发送方不需要结果的调用。发送方的激活条独立于接收方的激活条，并且可以先于后者结束。

```text
:OrderService                   :MailService
      │                               │
     ┌┴┐                              │
     │ │──── sendMail(order) ───────>┌┴┐
     └┬┘                             │ │
      │                              │ │
      │                              └┬┘
      │                               │
```

### 自消息 {/*#self-message*/}

自消息是离开某条生命线并在稍下方重新进入同一条生命线的箭头。当参与者的内部步骤（例如校验或计算）对理解流程有意义时才绘制。与此无关的私有辅助调用则省略。严格绘制的自调用会得到嵌套的执行规约，即叠加在第一个激活条上、略微偏移的第二个激活条。

```text
:OrderService
      │
     ┌┴┐
     │ ├───┐ validate()
     │ ┌─┐◀┘
     │ │ │
     │ └─┘
     │ │
     └┬┘
      │
```

### 对象的创建与销毁 {/*#creation-and-destruction-of-objects*/}

仅在交互过程中才产生的对象，其头部绘制在创建它的垂直位置。创建消息指向头部，而不是生命线。销毁以生命线末端的叉号标记。

```text
  :Session
      │
     ┌┴┐
     │ │        «create»
     │ │- - - - - - - - - ->┌─────────┐
     │ │                    │  :Cart  │
     │ │                    └────┬────┘
     │ │──── addItem(item) ────▶┌┴┐
     │ │                        └┬┘
     │ │──── «destroy» ────────▶ X
     └┬┘
      │
```

## 组合片段 {/*#combined-fragments*/}

组合片段是包围交互某一部分的矩形。左上角的操作符决定对所含消息适用哪种控制结构，例如选择或循环。水平虚线将片段划分为多个操作数，在 `alt` 片段中每个操作数都带有守卫。

| 操作符     | 含义                                                              | 对应于                         |
| ---------- | ----------------------------------------------------------------- | ------------------------------ |
| `alt`    | 备选，恰好执行一个操作数，其余情况标记为 `[else]`                  | `if / else if / else`                        |
| `opt`    | 单个操作数，仅在守卫成立时执行                                    | 不带 `else` 的 `if`        |
| `loop`    | 重复，写作 `loop(min,max)` 或带守卫                                       | `while`、`for`、`do … while`      |
| `break`    | 该操作数取代所在交互的其余部分                                    | 提前 `return`，异常             |
| `par`    | 各操作数并发执行，其消息可以交错                                  | 线程、任务、并行调用           |
| `ref`    | 引用另行绘制的交互                                                | 方法调用，子流程               |
| `critical`    | 该操作数不得被并发运行的操作数打断                                | 临界区，锁                     |
| `neg`    | 所含序列无效，不得出现                                            | 反向测试用例                   |
| `assert`    | 所含序列是唯一有效的后续                                          | 断言                           |

实际中，`alt`、`opt` 和 `loop` 已涵盖绝大多数图。

### 选择 {/*#alternative*/}

```text
      :Client                        :Booking
         │                               │
        ┌┴┐                              │
        │ │──── reserve(seatNo) ───────▶┌┴┐
        │ │                             │ │
 ┌──────┼─┼─────────────────────────────┼─┼────────┐
 │ alt  │ │ [seat is free]              │ │        │
 │      │ │<- - - - reservationId - - - │ │        │
 ├╌╌╌╌╌╌┼╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┼╌┼╌╌╌╌╌╌╌╌┤
 │      │ │ [else]                      │ │        │
 │      │ │<- - - SeatTakenError - - - -│ │        │
 └──────┼─┼─────────────────────────────┼─┼────────┘
        └┬┘                             └┬┘
         │                               │
```

`alt` 片段的守卫必须互斥，并且应覆盖所有情况。

### 循环 {/*#loop*/}

```text
      :Order                         :LineItem
         │                               │
        ┌┴┐                              │
 ┌──────┼─┼──────────────────────────────┼─────────┐
 │ loop │ │ [more items]                 │         │
 │      │ │──── subtotal() ────────────▶┌┴┐        │
 │      │ │<- - - - amount - - - - - - -└┬┘        │
 └──────┼─┼──────────────────────────────┼─────────┘
        └┬┘                              │
         │                               │
```

`loop(1,n)` 表示次数而非条件，不带附加内容的 `loop` 表示无界重复。

## 示例：细化用例*预订座位* {/*#example-detailing-the-use-case-book-seat*/}

此处细化的场景是用例*预订座位*的主流程：客户预订特定座位，系统查找该座位，如果仍然空闲，则将其标记为已预订。该图按以下步骤由用例的文字描述推导而来：

1. 选择用例的一个场景，通常是文字描述中的主流程。
2. 触发的参与者成为最左侧的生命线。
3. 加入内部参与者，通常沿架构的各层：用户界面、控制、领域对象、持久化。
4. 文字流程的每一步成为一条消息，其名称与接收方的某个操作相对应。
5. 文字描述中的异常成为 `alt` 或 `break` 片段，或分别绘制单独的图。

```text
┌────────────────┐
│ sd BookSeat    │
├────────────────┴─────────────────────────────────────────────────────┐
│                                                                      │
│       :Customer            :BookingService         :SeatRepository   │
│           │                       │                       │          │
│          ┌┴┐                      │                       │          │
│          │ │── bookSeat(id) ────▶┌┴┐                      │          │
│          │ │                     │ │── findSeat(id) ────▶┌┴┐         │
│          │ │                     │ │<- - seat - - - - - -└┬┘         │
│          │ │                     │ │                      │          │
│          │ │              ┌──────┼─┼──────────────────────┼───────┐  │
│          │ │              │ opt  │ │ [seat is free]       │       │  │
│          │ │              │      │ │── markBooked(id) ──▶┌┴┐      │  │
│          │ │              │      │ │<- - - - ok - - - - -└┬┘      │  │
│          │ │              └──────┼─┼──────────────────────┼───────┘  │
│          │ │<- - confirmation - -└┬┘                      │          │
│          └┬┘                      │                       │          │
│           │                       │                       │          │
└──────────────────────────────────────────────────────────────────────┘
```

此示例说明以下内容：

- `opt` 片段的失败情况未在此绘制，它将通过 `alt` 或在单独的图中建模。
- 支付步骤将作为 `ref` 片段插入，使该图保持可读，并让支付拥有自己的交互。

## 序列图、活动图还是通信图 {/*#sequence-activity-or-communication-diagram*/}

三者都是行为图。

| 标准       | 序列图                         | 活动图                         | 通信图                         |
| ---------- | ------------------------------ | ------------------------------ | ------------------------------ |
| 关注点     | 随时间的消息交换               | 流程的控制流                   | 协作的结构                     |
| 时间       | 显式，作为垂直轴               | 隐式，通过流向                 | 仅通过消息编号                 |
| 参与者     | 生命线并排                     | 可选，以分区表示               | 对象自由放置，以链接相连       |
| 分支       | 组合片段，很快变得拥挤         | 判定节点与合并节点，可读性好   | 几乎无法阅读                   |
| 并发       | `par` 片段                   | 分叉与汇合                     | 可行，但难以阅读               |
| 典型用途   | 细化单个场景                   | 为整个流程建模                 | 展示哪个对象认识哪个对象       |

经验法则：

- 分支和循环多、参与者少 => [活动图](./activity-diagram.md)
- 分支少、参与者多且顺序重要 => 序列图
- 关注*谁与谁相连*而非*按什么顺序* => [通信图](./further-uml-diagrams.md#communication-diagram)
- *单个*对象在其整个生命周期中的行为 => [状态机图](./state-machine-diagram.md)

## 常见错误 {/*#common-mistakes*/}

1. **忽略时间轴：** 时间在所有生命线上自上而下流动。因此向上绘制的箭头会颠倒预期的顺序。处于同一高度的两条消息没有确定的顺序。
2. **回复画成实线箭头：** 回复绘制为带开放箭头的虚线。带实心箭头的实线会被理解为反方向的新调用。
3. **混淆同步与异步：** 实心箭头表示发送方等待回复。事件、通知和发往队列的消息是异步的，使用开放箭头。
4. **执行规约未闭合：** 调用方的激活条至少要延伸到回复到达为止。更早结束的激活条表示调用方已经完成。
5. **生命线上放置活动而非对象：** 生命线代表 `:SeatRepository` 这样的通信参与者。`Check availability` 这样的步骤不是参与者，而应成为消息。
6. **alt 操作数缺少守卫：** 没有守卫时，图无法显示 `alt` 片段的每个操作数适用于何种条件。
