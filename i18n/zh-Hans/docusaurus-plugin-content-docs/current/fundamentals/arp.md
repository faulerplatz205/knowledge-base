# ARP（地址解析协议）

## 概述 {/*#overview*/}

ARP（Address Resolution Protocol，地址解析协议）工作在 [OSI 模型](./osi-model.md)第 2 层（数据链路层）与第 3 层（网络层）的交界处。它将已知的 **IP 地址**解析为在本地网段内投递帧所需的对应 **MAC 地址**。

## 两种地址 {/*#two-types-of-addresses*/}

以太网局域网中的每台设备通过两种不同的地址进行访问：

- **MAC 地址：**用于同一网段内网卡之间的通信，是第 2 层以太网帧的寻址方式。
- **IP 地址：**用于将数据包从原始源发送到最终目的地，无论中间经过多少个网络，是第 3 层 IP 数据包的寻址方式。

以太网帧封装在 IP 数据包外部。IP 数据包端到端传输，而外层的以太网帧始终只存在于单一网段内。

## 为什么需要 ARP {/*#why-arp-is-needed*/}

IP 数据包包含源 IP 地址和目的 IP 地址，而以太网帧在本地网段内使用 MAC 地址进行投递。设备要发送数据时，已知目的 IP 地址，但必须先获知帧应寻址到的 MAC 地址。

## 本地与远程投递 {/*#local-vs-remote-delivery*/}

发送设备首先通过子网掩码（将自身 IP 与目的 IP 分别与掩码进行逻辑与运算）判断目的地是否位于**同一网络**。判断结果决定帧需要使用哪个 MAC 地址：

- **同一网络：**目的 MAC 地址是目的主机本身的 MAC 地址。设备通过 ARP 解析目的 IP。
- **不同网络：**目的 MAC 地址是**默认网关**（路由器的网络接口）的 MAC 地址。设备通过 ARP 解析网关的 IP。

两种情况下，数据包中的源 IP 地址和目的 **IP 地址都不会改变**。只有帧中的 MAC 地址会被重写：路径上的每台路由器会剥离收到的帧，并用下一跳的源 MAC 地址和目的 MAC 地址构建新帧。

## ARP 表查找 {/*#arp-table-lookup*/}

发送前，设备在其 ARP 表（保存在 RAM 中）中查找需要解析的 IP：

- 如果目的 IP 位于**同一网络**，则查找**目的 IP 地址**。
- 如果目的 IP 位于**不同网络**，则查找**默认网关的 IP 地址**。

如果存在匹配条目，则使用缓存的 MAC 地址构建帧。如果不存在条目，设备发送 **ARP 请求**。

## ARP 请求/应答过程 {/*#arp-request--reply-process*/}

1. **检查 ARP 缓存**：如果所需 IP 的 MAC 地址已被缓存，则无需发送请求
2. **ARP 请求（广播）**：如果未缓存，发送方向网段内所有设备广播 ARP 请求：*"谁拥有 IP X.X.X.X？请告知 IP Y.Y.Y.Y"*。该广播帧的目的 MAC 地址为 `FF:FF:FF:FF:FF:FF`
3. **ARP 应答（单播）**：IP 匹配的设备直接向发送方回复其 MAC 地址；其他所有设备忽略该请求
4. **更新缓存**：发送方将 IP 到 MAC 的映射存入 ARP 缓存，供后续使用
5. **发送帧**：发送方现在使用解析得到的 MAC 地址构建以太网帧

## ARP 缓存 {/*#arp-cache*/}

ARP 缓存保存近期的 IP 到 MAC 映射，以避免重复广播。

- 条目具有 TTL（Time to Live，生存时间），并会自动过期
- 常用命令（Windows/Linux）：

| 命令 | 用途 |
| -------- | ------------------------ |
| `arp -a` | 显示 ARP 表 |
| `arp -d` | 删除 ARP 表条目 |

## 安全：ARP 欺骗 {/*#security-arp-spoofing*/}

由于 ARP 没有认证机制，攻击者可以发送伪造的 ARP 应答来污染其他设备的缓存，使流量经由攻击者的机器转发（中间人攻击）。

对策包括：

- 托管交换机上的**动态 ARP 检测（DAI）**
- 为关键设备设置**静态 ARP 条目**
- 网络监控与异常检测
