# NAT（网络地址转换）

## 概述 {/*#overview*/}

若没有更高效地利用 IP 地址的机制，互联网的快速增长很快就会耗尽可用的 IP 地址池。NAT（Network Address Translation）通过允许私有网络中的众多设备共享少量公有 IP 地址来解决这一问题。

NAT 运行在边界设备（通常是防火墙或路由器）上。数据包经过该设备时，NAT 会将源 IP 地址（私有的、不可路由的地址）替换为公有的、可路由的 IP 地址。应答数据包中的公有地址随后被转换回私有地址，使数据包能够送达正确的内部主机。

## 优点 {/*#benefits*/}

- **更简单的重新编号**：更换 ISP 时，内部主机无需新的 IP 地址，仅需更改由新 ISP 分配的公有地址。
- **节约地址**：[PAT](#nat-overloading-pat) 让众多内部主机共享同一个公有 IP 地址，大幅减少所需的公有地址数量。
- **提高安全性**：由于外部网络只能看到公有地址，内部地址和网络拓扑被隐藏。

## NAT 的工作方式 {/*#how-nat-works*/}

1. 内部主机（例如 `10.0.0.3`）发送数据包，目的地为外部主机（例如 `128.23.2.2`）
2. 边界路由器（RTA）识别出该数据包要前往互联网，并选择一个可用的全局 IP 地址（例如 `179.9.8.80`）
3. RTA 将数据包中的源地址替换为该全局地址，并将映射记录到 NAT 表中
4. 数据包被转发至目的地
5. 当目标地址为 `179.9.8.80` 的应答到达时，RTA 查询 NAT 表，找到对应的内部地址，替换目标字段，并在内部转发数据包

NAT 表记录三种类型的地址：

- **内部本地 IP**：内部主机的私有 IP 地址
- **内部全局 IP**：NAT 路由器分配的、用于在外部代表该内部主机的公有 IP 地址
- **外部全局 IP**：外部网络中目标主机的 IP 地址

**NAT 表示例：**

| 内部本地 IP | 内部全局 IP | 外部全局 IP |
| ----------------- | ------------------ | ------------------ |
| 10.0.0.3          | 179.9.8.80         | 128.23.2.2         |

## NAT 重载（PAT） {/*#nat-overloading-pat*/}

NAT 重载（NAT Overloading）也称为 PAT（Port Address Translation，端口地址转换），通过额外跟踪端口号，将多个私有 IP 地址映射到单个公有 IP 地址。每个内部连接在公有侧获得唯一的端口号，使路由器能够将传入的应答分发到正确的内部主机。

**使用重载的 NAT 表：**

| 内部 IP | 内部端口 | 全局 IP  | 外部端口 |
| ----------- | ------------- | ---------- | ------------- |
| 10.0.0.2    | 1555          | 179.9.8.80 | 1555          |
| 10.0.0.3    | 1331          | 179.9.8.80 | 1331          |
| 10.0.0.4    | 1444          | 179.9.8.80 | 1444          |

## 端口转发 {/*#port-forwarding*/}

默认情况下，NAT 会阻止所有由外部发起的入站连接。端口转发通过将公有 IP 上的目标端口号映射到特定的内部 IP 地址，允许特定的外部流量到达内部主机。

示例流程：

1. 客户端向 `https://knowledge.moritz-grimm.dev`（公有 IP `209.165.200.225`，端口 `443`）发送请求
2. 路由器收到数据包，因为 `209.165.200.225` 是其自身的公有 IP
3. 端口转发规则将外部端口 `443` 映射到内部主机 `192.168.1.254:443`，因此路由器重写目标地址并在内部转发数据包

:::info
外部端口号与内部端口号不必相同。
:::
