# 大 O 表示法

## 概述 {/* #overview */}

大 O 表示法描述算法的工作量如何随输入增长。它给出的不是以秒为单位的时间，而是这种增长的形态。

输入规模记为 **n**：它表示列表中的元素个数、字符串中的字符数或表中的行数。每个复杂度类别都回答这样一个问题：**当 n 翻倍时，步数会发生什么变化？**

| 表示法   | 名称         | 当 n 翻倍时，工作量…… | 示例                                      |
| ---------- | ------------ | ------------------------------ | -------------------------------------------- |
| O(1)       | 常数     | 保持不变                 | 按索引访问数组                        |
| O(log n)   | 对数  | 增加一步                | 二分查找                                |
| O(n)       | 线性       | 翻倍                        | 线性查找                        |
| O(n log n) | 线性对数 | 略多于翻倍     | 归并排序                           |
| O(n²)      | 平方    | 变为四倍                     | 冒泡排序、对同一列表的嵌套循环 |
| O(2ⁿ)      | 指数  | 变为平方                        | 尝试集合的每一个子集                 |

对于 O(2ⁿ)，仅多一个元素，工作量就已翻倍。

---

## 增长的具体数值 {/* #growth-in-numbers */}

每个复杂度类别在输入为 n 个元素时所需的步数（log 以 2 为底，四舍五入）：

| n         | O(1) | O(log n) | O(n)      | O(n log n) | O(n²)     | O(2ⁿ)         |
| --------- | ---- | -------- | --------- | ---------- | --------- | ------------- |
| 10        | 1    | 3        | 10        | 33         | 100       | 1,024         |
| 100       | 1    | 7        | 100       | 664        | 10,000    | ≈ 1.3 x 10³⁰  |
| 1,000     | 1    | 10       | 1,000     | 9,966      | 1,000,000 | ≈ 1.1 x 10³⁰¹ |
| 1,000,000 | 1    | 20       | 1,000,000 | ≈ 2 x 10⁷  | 10¹²      | ≈ 10³⁰¹⁰³⁰    |

假设每步一微秒、元素一百万个，O(log n) 算法需要 20 µs，O(n) 算法需要一秒，O(n log n) 算法需要约 20 秒，O(n²) 算法需要 10⁶ 秒，约合 11.6 天。

## 形式化定义 {/* #formal-definition */}

f(n) 是算法所需的步数，g(n) 是 n 或 n² 之类的简单比较函数。如果从某个输入规模开始，f 的增长至多与 g 乘以一个固定因子一样快，则 f(n) 属于 O(g(n))。

形式化表述：存在常数 c > 0 和阈值 n₀，使得对所有 n ≥ n₀ 都有 f(n) ≤ c x g(n)。

示例：f(n) = 3n + 5 属于 O(n)。取 c = 4 且 n₀ = 5，则对所有 n ≥ 5 都有 3n + 5 ≤ 4n。

- 常数因子被 c 吸收。`3n`、`n / 2` 和 `100n` 都属于 O(n)。
- n₀ 以下的行为无关紧要，因为大 O 只描述大规模输入。
- O 是上界。严格来说，二分查找同样属于 O(n) 和 O(n²)。实践中给出的是最小的适用类别。
- 下界写作 Ω（Omega）。既是上界又是下界的界写作 Θ（Theta）。

## 确定复杂度类别 {/* #determining-the-complexity-class */}

确定复杂度类别的方法是：把最频繁的操作（通常是最内层循环中的一次比较或赋值）的次数表示为 n 的函数，并对结果进行化简。

### 单条语句：O(1) {/* #single-statements-o1 */}

赋值、算术运算、比较、按索引访问数组以及 `RETURN` 的执行次数是固定的，与 n 无关。

```text
first = list[0]
sum = a + b
```

### 遍历输入的循环：O(n) {/* #loop-over-the-input-on */}

```text
FOR i = 0 TO n - 1
    sum = sum + list[i]
END FOR
```

`FOR` 运行 n 次。运行 `n / 2` 或 `2n` 次的循环同样是 O(n)。

### 嵌套循环：相乘 {/* #nested-loops-multiply */}

嵌套循环的迭代次数相乘。当两个循环都遍历输入时，得到 n x n 步，即 O(n²)：

```text
FOR i = 0 TO n - 1
    FOR j = 0 TO n - 1
        ...
    END FOR
END FOR
```

当内层循环的迭代次数固定时，得到 n x 7 = 7n 步，因此是 O(n)：

```text
FOR i = 0 TO n - 1
    FOR day = 1 TO 7        // 7 iterations, independent of n
        ...
    END FOR
END FOR
```

### 连续的代码块：保留最大项 {/* #consecutive-blocks-keep-the-largest-term */}

当代码块依次运行时，它们的步数相加。只有和中增长最快的部分决定类别：

```text
FOR i = 0 TO n - 1              // n steps
    ...
END FOR
FOR i = 0 TO n - 1              // n x n steps
    FOR j = 0 TO n - 1
        ...
    END FOR
END FOR
```

n + n² 步得到 O(n²)。n 越大，较小的部分就越不重要。

### 折半：O(log n) {/* #halving-olog-n */}

当每一步都将剩余问题减半时，步数等于 n 可被折半直至只剩一个元素的次数。这个次数是 log₂ n。大 O 省略底数，因为 log₂ n 与 log₁₀ n 只相差一个常数因子。

```text
1,000,000 => 500,000 => 250,000 => ... => 1      20 halvings
```

二分查找在有序列表上就是这样工作的：

```text
low = 0
high = n - 1
WHILE low <= high
    mid = (low + high) DIV 2
    IF list[mid] == target THEN
        RETURN mid
    ELSE IF list[mid] < target THEN
        low = mid + 1
    ELSE
        high = mid - 1
    END IF
END WHILE
RETURN -1
```

### 分治：O(n log n) {/* #divide-and-conquer-on-log-n */}

归并排序不断将列表折半，直到只剩单个元素。这会产生 log n 层。每一层上，所有 n 个元素各被合并一次。log n 层 x 每层 n 步，得到 O(n log n)。

### 两个输入：两个变量 {/* #two-inputs-two-variables */}

当算法处理规模分别为 n 和 m 的两个独立输入时，两者都会出现在结果中：

```text
FOR EACH customer IN customers          // n customers
    FOR EACH product IN products        // m products
        ...
    END FOR
END FOR
```

嵌套循环得到 n x m 步，即 O(n x m)。先后执行的两个循环得到 O(n + m)。与 n + n² 不同，这里任何一项都不能舍去，因为无法得知两个输入中哪个更大。

## 最好、平均和最坏情况 {/* #best-average-and-worst-case */}

同一算法所需的步数因输入而异：

- **最好情况：**最有利的输入。对于线性查找，这是位于第一个位置的值，一次比较即可找到。最好情况描述的是一种幸运的巧合，很难说明典型行为。
- **平均情况：**对所有输入的期望工作量。对于线性查找，这是 n / 2 次比较，即 O(n)。
- **最坏情况：**最不利的输入。对于线性查找，这是位于最后一个位置的值或不存在的值，需要 n 次比较。最坏情况是算法永远不会超出的保证。

未加限定的复杂度指的是最坏情况。平均情况和最坏情况在类别上可能相差悬殊：快速排序平均需要 O(n log n)，但当枢轴元素始终是最小值或最大值时需要 O(n²)。

## 空间复杂度 {/* #space-complexity */}

同样的表示法也描述算法在输入之外所需的内存。

- **O(1)：**固定数量的变量，例如在列表内交换元素（原地）的冒泡排序。
- **O(log n)：**将问题折半的递归会让 log n 个调用同时保留在栈上。
- **O(n)：**随输入增长的辅助结构，例如归并排序中的临时列表或存放所有已见值的集合。

时间和内存往往可以相互折中。[示例](#worked-example-finding-duplicates)展示了这样一种折中。

## 常见算法的类别 {/* #classes-of-common-algorithms */}

### 查找 {/* #searching */}

| 算法     | 最好情况 | 平均情况 | 最坏情况 | 额外空间 | 前提条件                     |
| ------------- | --------- | ------------ | ---------- | ----------- | -------------------------------- |
| 线性查找 | O(1)      | O(n)         | O(n)       | O(1)        | 无                             |
| 二分查找 | O(1)      | O(log n)     | O(log n)   | O(1)        | 可按索引访问的有序数据 |

### 排序 {/* #sorting */}

| 算法      | 最好情况  | 平均情况 | 最坏情况 | 额外空间 | 稳定 |
| -------------- | ---------- | ------------ | ---------- | ----------- | ------ |
| 冒泡排序    | O(n)¹      | O(n²)        | O(n²)      | O(1)        | 是    |
| 选择排序 | O(n²)      | O(n²)        | O(n²)      | O(1)        | 否     |
| 插入排序 | O(n)²      | O(n²)        | O(n²)      | O(1)        | 是    |
| 归并排序     | O(n log n) | O(n log n)   | O(n log n) | O(n)        | 是    |
| 快速排序      | O(n log n) | O(n log n)   | O(n²)      | O(log n)    | 否     |

¹ 仅在带有提前退出机制时成立，即某一趟没有任何交换就停止。没有该机制时，冒泡排序始终需要 O(n²)。

² 对于已排序的列表，每个元素只与其前驱比较一次，并留在原位。

当键相等的元素保持其原有顺序时，排序是**稳定**的。键是列表据以排序的值。已按姓名排序的人员列表再按年龄做稳定排序，同龄的人仍按字母顺序排列。

一次只比较两个元素的排序，在最坏情况下至少需要约 n log n 次比较。因此归并排序达到了基于比较的排序所能达到的最佳类别。只有直接利用值本身的排序，例如针对小整数的计数排序，才可能更快。

| 按值或键查找  | O(n)，有序时 O(log n) | O(n)        | 按键平均 O(1)³ |

## 示例：查找重复项 {/* #worked-example-finding-duplicates */}

一个函数检查列表中是否有任何值出现两次。

### 方案 1：比较每一对 {/* #variant-1-compare-every-pair */}

```text
FUNCTION hasDuplicates(list)
    n = LENGTH(list)
    FOR i = 0 TO n - 2
        FOR j = i + 1 TO n - 1
            IF list[i] == list[j] THEN
                RETURN true
            END IF
        END FOR
    END FOR
    RETURN false
END FUNCTION
```

最坏情况是没有重复项的列表，因此每一对都要比较：

```text
i = 0        n - 1 comparisons
i = 1        n - 2 comparisons
...
i = n - 2    1 comparison

Total:  (n - 1) + (n - 2) + ... + 1  =  n x (n - 1) / 2  =  0.5n² - 0.5n
n = 5:  4 + 3 + 2 + 1                =  5 x 4 / 2        =  10
```

舍去较小的项 `0.5n` 和常数因子 `0.5` 后，得到 **O(n²)**。内层循环每一趟都会变短，但平均仍要遍历半个列表。n = 1,000 时是 499,500 次比较，n = 2,000 时是 1,999,000 次，是前者的四倍。

### 方案 2：先排序，再比较相邻元素 {/* #variant-2-sort-first-then-compare-neighbours */}

```text
FUNCTION hasDuplicates(list)
    n = LENGTH(list)
    sort(list)                          // O(n log n)
    FOR i = 0 TO n - 2                  // O(n)
        IF list[i] == list[i + 1] THEN
            RETURN true
        END IF
    END FOR
    RETURN false
END FUNCTION
```

排序后相等的值彼此相邻，只需对相邻元素对遍历一趟即可。O(n log n) + O(n) 得到 **O(n log n)**。除非函数对副本排序，否则它会改变所传入列表的顺序。副本需要 O(n) 内存。

### 方案 3：记住已见的值 {/* #variant-3-remember-seen-values */}

```text
FUNCTION hasDuplicates(list)
    seen = empty set
    FOR EACH value IN list              // n iterations
        IF seen CONTAINS value THEN     // O(1) average
            RETURN true
        END IF
        ADD value TO seen               // O(1) average
    END FOR
    RETURN false
END FUNCTION
```

基于哈希的集合平均可在常数时间内回答“是否包含”。n 次迭代、每次 O(1)，得到 **O(n)**。该集合需要 O(n) 额外内存。

### 对比 {/* #comparison */}

| 方案       | 时间       | 额外空间            | n = 1,000,000 时的步数 |
| ------------- | ---------- | ---------------------- | ----------------------- |
| 1：每一对 | O(n²)      | O(1)                   | ≈ 5 x 10¹¹              |
| 2：先排序 | O(n log n) | O(1)，使用副本时 O(n) | ≈ 2 x 10⁷               |
| 3：集合       | O(n)       | O(n)                   | ≈ 10⁶                   |

该示例说明：

- 只有换一种思路才能改进类别。优化方案 1 的内层循环只会改变常数因子。
- 方案 3 以内存换取速度。

## 常见错误 {/* #common-mistakes */}

1. **每个嵌套循环都算作 O(n²)：**类别取决于每个循环运行的次数。内层循环的迭代次数固定，例如遍历一周的七天，只会乘以一个常数因子，结果仍为 O(n)。
2. **两个不同的输入都写成 n：**对 n 个客户的循环与对 m 个产品的循环嵌套，结果是 O(n x m)。O(n²) 假定两个输入规模相同，并掩盖了究竟哪一个决定工作量。
3. **保留常数和较小的项：**O(2n + 5) 和 O(n² + n) 形式上正确，但没有化简。它们的类别分别是 O(n) 和 O(n²)，因为常数和较小的项对大 n 时的增长没有影响。
4. **将大 O 理解为以秒计的运行时间：**该表示法隐藏了常数因子，因此对于较小的 n，O(n²) 算法可能比 O(n log n) 算法更快。插入排序在短列表上胜过归并排序，因此 Timsort 等实际的排序实现对短区段使用插入排序。
5. **对无序数据使用二分查找：**O(log n) 只对可按索引访问的有序数据成立。事先排序需要 O(n log n)，只有对同一数据多次查找时才划算。
6. **混淆 log n 与 n log n：**O(log n) 的增长慢于线性，所需步数远少于元素个数。O(n log n) 的增长快于线性，对每个元素都要执行 log n 步。
7. **将最好情况当作复杂度：**线性查找的最好情况是 O(1)，对典型输入没有说明力。未加限定的复杂度指的是最坏情况。
