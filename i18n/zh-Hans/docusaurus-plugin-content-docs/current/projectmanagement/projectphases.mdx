# 项目阶段

## 概述 {/* #overview */}

5 个项目阶段提供了一个结构化的框架，帮助团队有条不紊地规划、执行和完成项目。每个阶段都建立在前一阶段成果的基础之上。

各阶段会略有不同，取决于项目是具有明确结束日期的一次性工作，还是在已投入生产使用的同时持续开发的产品。

## 阶段 {/* #phases */}

### 1. 启动/分析 {/* #1-initialization--analysis */}

在启动阶段，对项目构想进行评估，并评估其可行性。目标是在投入大量资源之前，确定该项目是否值得推进。

- 定义项目目标和预期成果
- 开展可行性研究
- 识别关键相关方
- 进行初步风险评估
- 编制粗略的成本效益分析

该阶段通常以项目章程或是否继续（go/no-go）的决策作为结束。

### 2. 规划 {/* #2-planning */}

在规划阶段，团队为项目的执行方式制定详细的路线图。这是预防后续问题最重要的阶段。

- 定义项目范围和交付物
- 创建工作分解结构（WBS）
- 估算时间、成本和资源
- 制定进度计划（例如使用甘特图  {/* (./gantt.md) */} 或网络图 {/* (./network-plan.md) */}）
- 定义里程碑和质量标准
- 规划风险缓解策略
- 分配角色和职责

### 3. 实施/执行 {/* #3-implementation--execution */}

在实施阶段，按照计划开展实际工作。项目经理协调团队，并确保项目保持在正轨上。

- 执行项目计划中定义的任务
- 协调团队成员和外部合作伙伴
- 向相关方沟通进展
- 通过变更控制流程管理变更
- 记录决策以及与计划的偏差

### 4. 测试/监控 {/* #4-testing--monitoring */}

测试和监控阶段通常与[实施阶段](#3-implementation--execution)并行进行。其目的是确保交付物符合既定的质量标准。

- 对照验收标准验证交付物
- 使用关键指标（预算、时间线、范围）跟踪进度
- 及早识别并处理偏差
- 开展质量保证和测试
- 定期向相关方报告状态

### 5. 完成/运营 {/* #5-completion--operation */}

最后一个阶段取决于项目类型：

**一次性项目**以正式收尾结束：

- 向客户或最终用户移交交付物
- 获得正式验收和签字确认
- 记录经验教训，供未来项目参考
- 归档项目文档
- 释放资源并结束合同

**持续运营的产品**则过渡到运营阶段：

- 将产品部署到生产环境
- 移交给运维或支持团队
- 建立监控和维护流程
- 规划未来的迭代和改进

## 总结 {/* #summary */}

| 阶段                                                       | 目标         | 产出                       |
| ---------------------------------------------------------- | ------------ | -------------------------- |
| [启动/分析](#1-initialization--analysis)                   | 评估可行性   | 项目章程、go/no-go 决策    |
| [规划](#2-planning)                                        | 制定路线图   | 项目计划、进度表、预算     |
| [实施/执行](#3-implementation--execution)                  | 开展工作     | 交付物、状态报告           |
| [测试/监控](#4-testing--monitoring)                        | 确保质量     | 测试结果、进度报告         |
| [完成/运营](#5-completion--operation)                      | 收尾或过渡   | 验收、经验教训             |
