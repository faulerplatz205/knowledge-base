# Software de código abierto frente a software propietario

## Definiciones {/*#definitions*/}

**Software de código abierto (Open Source)**: El código fuente es de acceso público. Cualquiera puede inspeccionar, modificar y distribuir el software, con sujeción a los términos de su licencia (p. ej. MIT, GPL, Apache).

**Software propietario**: El proveedor mantiene privado el código fuente. El uso se rige por un contrato de licencia y, normalmente, se prohíbe la modificación y la redistribución.

## Código abierto {/*#open-source*/}

### Ventajas {/*#advantages*/}

- **Uso gratuito**: En la mayoría de los casos, se puede usar sin costes de licencia
- **Transparencia**: el código puede auditarse en busca de vulnerabilidades de seguridad y errores
- **Impulsado por la comunidad**: La comunidad puede seguir desarrollándolo sin depender por completo del desarrollador original
- **Flexibilidad**: Una persona puede adaptarlo a sus necesidades particulares

### Desventajas {/*#disadvantages*/}

- **Soporte**: El soporte de la comunidad puede ser poco fiable y, en comunidades pequeñas, inexistente o de pago
- **Usabilidad**: interfaces a menudo menos pulidas que las alternativas comerciales
- **Riesgo de seguridad**: el código visible públicamente también puede ser analizado por atacantes
- **Complejidad de las licencias**: las distintas licencias de código abierto pueden imponer restricciones (p. ej. copyleft)
- **Carga de mantenimiento**: el autoalojamiento requiere conocimientos internos y tiempo

### Ejemplos {/*#examples*/}

- Firefox
- Linux
- React
- VSCode

## Software propietario {/*#proprietary-software*/}

### Ventajas {/*#advantages-1*/}

- **Soporte profesional**: soporte dedicado del proveedor con SLA
- **Acabado y UX**: normalmente, mayor inversión en experiencia de usuario y documentación
- **Actualizaciones y mantenimiento fiables**: El proveedor ofrece actualizaciones y parches probados con regularidad, sin necesidad de conocimientos internos para realizarlas.
- **Integración**: A menudo ofrece buena compatibilidad con otro software del mismo fabricante

### Desventajas {/*#disadvantages-1*/}

- **Coste**: las tarifas de licencia pueden ser considerables, especialmente a gran escala
- **Dependencia del proveedor (vendor lock-in)**: dependencia de la hoja de ruta y de los precios del proveedor
- **Falta de transparencia**: no se puede auditar el código fuente en cuanto a seguridad o calidad
- **Restricciones**: capacidad limitada para personalizar o ampliar más allá de lo que permite el proveedor

### Ejemplos {/*#examples-1*/}

- Microsoft Office
- Windows, iOS, MacOS
- Discord
- Google Chrome

## Comparación {/*#comparison*/}

|                          | Código abierto      | Propietario          |
| ------------------------ | ------------------- | -------------------- |
| Código fuente            | Público             | Privado              |
| Coste                    | Normalmente gratuito | Tarifas de licencia |
| Soporte                  | Comunidad / de pago | Ofrecido por el proveedor |
| Personalización          | Alta                | Baja                 |
| Dependencia del proveedor | Baja               | Alta                 |
| Transparencia de seguridad | Alta              | Baja                 |
