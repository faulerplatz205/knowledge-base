# Software de código aberto x software proprietário

## Definições {/*#definitions*/}

**Software de código aberto (Open Source)**: o código-fonte é publicamente disponível. Qualquer pessoa pode inspecionar, modificar e distribuir o software, sujeito aos termos de sua licença (p. ex., MIT, GPL, Apache).

**Software proprietário**: o código-fonte é mantido privado pelo fornecedor. O uso é regido por um contrato de licença, e a modificação e a redistribuição são, em regra, proibidas.

## Código aberto {/*#open-source*/}

### Vantagens {/*#advantages*/}

- **Uso gratuito**: na maioria dos casos, pode ser usado sem taxas de licença
- **Transparência**: o código pode ser auditado em busca de vulnerabilidades de segurança e bugs
- **Impulsionado pela comunidade**: pode ser desenvolvido adiante pela comunidade sem depender completamente do desenvolvedor original
- **Flexibilidade**: pode ser personalizado individualmente para atender a necessidades específicas

### Desvantagens {/*#disadvantages*/}

- **Suporte**: o suporte da comunidade pode ser pouco confiável e, no caso de comunidades pequenas, inexistente ou sujeito a pagamento adicional
- **Usabilidade**: interfaces frequentemente menos refinadas em comparação com alternativas comerciais
- **Risco de segurança**: o código publicamente visível também pode ser analisado por invasores
- **Complexidade de licenciamento**: diferentes licenças de código aberto podem impor restrições (p. ex., copyleft)
- **Carga de manutenção**: a hospedagem própria exige conhecimento especializado interno e tempo

### Exemplos {/*#examples*/}

- Firefox
- Linux
- React
- VSCode

## Software proprietário {/*#proprietary-software*/}

### Vantagens {/*#advantages-1*/}

- **Suporte profissional**: suporte dedicado do fornecedor com SLAs
- **Refinamento e UX**: normalmente, maior investimento em experiência do usuário e documentação
- **Atualizações e manutenção confiáveis**: atualizações e patches testados regularmente são fornecidos pelo provedor, sem necessidade de conhecimento especializado interno para executá-los.
- **Integração**: frequentemente apresenta boa compatibilidade com outros softwares do mesmo fabricante

### Desvantagens {/*#disadvantages-1*/}

- **Custo**: as taxas de licenciamento podem ser significativas, especialmente em larga escala
- **Vendor lock-in**: dependência do roadmap e dos preços do fornecedor
- **Sem transparência**: não é possível auditar o código-fonte quanto à segurança ou à qualidade
- **Restrições**: capacidade limitada de personalizar ou estender além do que o fornecedor permite

### Exemplos {/*#examples-1*/}

- Microsoft Office
- Windows, iOS, MacOS
- Discord
- Google Chrome

## Comparação {/*#comparison*/}

|                           | Código aberto           | Proprietário                  |
| ------------------------- | ----------------------- | ----------------------------- |
| Código-fonte              | Público                 | Privado                       |
| Custo                     | Geralmente gratuito     | Taxas de licença              |
| Suporte                   | Comunidade / pago       | Fornecido pelo fornecedor     |
| Personalização            | Alta                    | Baixa                         |
| Vendor lock-in            | Baixo                   | Alto                          |
| Transparência de segurança | Alta                   | Baixa                         |
