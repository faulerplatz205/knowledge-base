# Fases do projeto

## Visão geral {/* #overview */}

As 5 fases do projeto oferecem um framework estruturado que ajuda as equipes a planejar, executar e concluir um projeto de forma organizada. Cada fase se baseia nos resultados da anterior.

As fases variam ligeiramente conforme o projeto seja uma iniciativa pontual com data de término clara ou um produto desenvolvido continuamente enquanto já está em uso em produção.

## Fases {/* #phases */}

### 1. Inicialização / Análise {/* #1-initialization--analysis */}

Na fase de inicialização, a ideia do projeto é avaliada e sua viabilidade é examinada. O objetivo é determinar se vale a pena prosseguir com o projeto antes de comprometer recursos significativos.

- Definir os objetivos do projeto e os resultados esperados
- Realizar um estudo de viabilidade
- Identificar as principais partes interessadas
- Realizar uma avaliação inicial de riscos
- Elaborar uma análise aproximada de custo-benefício

A fase normalmente termina com um termo de abertura do projeto ou uma decisão de go/no-go.

### 2. Planejamento {/* #2-planning */}

Na fase de planejamento, a equipe cria um roteiro detalhado de como o projeto será conduzido. Esta é a fase mais importante para evitar problemas posteriores.

- Definir o escopo do projeto e as entregas
- Criar uma estrutura analítica do projeto (EAP/WBS)
- Estimar tempo, custos e recursos
- Montar um cronograma (p. ex. com um diagrama de Gantt  {/* (./gantt.md) */} ou diagrama de rede {/* (./network-plan.md) */})
- Definir marcos e critérios de qualidade
- Planejar estratégias de mitigação de riscos
- Atribuir papéis e responsabilidades

### 3. Implementação / Execução {/* #3-implementation--execution */}

Na fase de implementação, o trabalho propriamente dito é realizado conforme o plano. O gerente de projeto coordena a equipe e garante que o projeto permaneça no rumo.

- Executar as tarefas definidas no plano do projeto
- Coordenar membros da equipe e parceiros externos
- Comunicar o progresso às partes interessadas
- Gerenciar mudanças por meio de um processo de controle de mudanças
- Documentar decisões e desvios do plano

### 4. Testes / Monitoramento {/* #4-testing--monitoring */}

A fase de testes e monitoramento costuma ocorrer em paralelo à [fase de implementação](#3-implementation--execution). Seu propósito é garantir que as entregas atendam aos critérios de qualidade definidos.

- Verificar as entregas em relação aos critérios de aceitação
- Acompanhar o progresso com métricas-chave (orçamento, prazo, escopo)
- Identificar e tratar desvios cedo
- Realizar garantia de qualidade e testes
- Reportar o status às partes interessadas em intervalos regulares

### 5. Conclusão / Operação {/* #5-completion--operation */}

A fase final depende do tipo de projeto:

**Projetos pontuais** terminam com um encerramento formal:

- Entregar os produtos ao cliente ou usuário final
- Obter aceitação formal e aprovação
- Documentar as lições aprendidas para projetos futuros
- Arquivar a documentação do projeto
- Liberar recursos e encerrar contratos

**Produtos contínuos** passam para uma fase de operação:

- Implantar o produto em produção
- Transferir para uma equipe de operações ou suporte
- Estabelecer processos de monitoramento e manutenção
- Planejar iterações e melhorias futuras
