# رموز حالة HTTP

## نظرة عامة {/*#overview*/}

رموز حالة HTTP هي أرقام من ثلاثة أرقام يعيدها الخادم استجابةً لطلب العميل. وهي تشير إلى ما إذا كان الطلب ناجحًا أو أُعيد توجيهه أو أدى إلى خطأ. تُصنف رموز الحالة في خمس فئات بحسب رقمها الأول.

## 1xx - معلوماتية {/*#1xx---informational*/}

تم استلام الطلب، ويواصل الخادم معالجته.

| الرمز | الاسم                | الوصف                                                                               |
| ---- | ------------------- | ----------------------------------------------------------------------------------------- |
| 100  | Continue            | استلم الخادم ترويسات الطلب وينبغي للعميل المتابعة بإرسال المحتوى.   |
| 101  | Switching Protocols | يتحول الخادم إلى البروتوكول الذي طلبه العميل (مثل الترقية إلى WebSocket). |

### أمثلة {/*#examples*/}

- **100 Continue**: يرسل عميل ملفًا كبيرًا للرفع مع الترويسة `Expect: 100-continue`. يستجيب الخادم بـ `100` للإشارة إلى أنه ينبغي للعميل متابعة إرسال المحتوى.
- **101 Switching Protocols**: يرسل عميل طلب HTTP مع `Upgrade: websocket`. يستجيب الخادم بـ `101` ويتحول إلى بروتوكول WebSocket.

## 2xx - نجاح {/*#2xx---success*/}

تم استلام الطلب وفهمه وقبوله بنجاح.

| الرمز | الاسم       | الوصف                                                                           |
| ---- | ---------- | ------------------------------------------------------------------------------------- |
| 200  | OK         | نجح الطلب. يحتوي محتوى الاستجابة على البيانات المطلوبة.                 |
| 201  | Created    | تم إنشاء مورد جديد بنجاح (عادةً بعد `POST`).                   |
| 204  | No Content | نجح الطلب لكن لا يوجد محتوى لإعادته (عادةً بعد `DELETE`). |

### أمثلة {/*#examples-1*/}

- **200 OK**: `GET /api/users/42` => يعيد الخادم كائن المستخدم بصيغة JSON.
- **201 Created**: `POST /api/users` مع محتوى طلب => ينشئ الخادم المستخدم ويعيد المورد الجديد مع الترويسة `Location`.
- **204 No Content**: `DELETE /api/users/42` => يحذف الخادم المستخدم ويعيد استجابة فارغة.

## 3xx - إعادة توجيه {/*#3xx---redirection*/}

يجب على العميل اتخاذ إجراء إضافي لإكمال الطلب.

| الرمز | الاسم               | الوصف                                                             |
| ---- | ------------------ | ----------------------------------------------------------------------- |
| 301  | Moved Permanently  | نُقل المورد بشكل دائم إلى عنوان URL جديد.                   |
| 302  | Found              | يوجد المورد مؤقتًا في عنوان URL مختلف.                 |
| 304  | Not Modified       | لم يتغير المورد منذ الطلب الأخير (يُستخدم للتخزين المؤقت). |
| 307  | Temporary Redirect | مثل 302، لكن يجب ألا تتغير طريقة الطلب عند إعادة التوجيه.           |
| 308  | Permanent Redirect | مثل 301، لكن يجب ألا تتغير طريقة الطلب عند إعادة التوجيه.           |

### أمثلة {/*#examples-2*/}

- **301 Moved Permanently**: `GET /old-page` => يستجيب الخادم بـ `301` و`Location: /new-page`. تحدّث محركات البحث فهرسها وفقًا لذلك.
- **302 Found**: `GET /promo` => يعيد الخادم التوجيه مؤقتًا إلى `/current-sale`. يبقى عنوان URL الأصلي صالحًا للطلبات المستقبلية.
- **304 Not Modified**: يرسل العميل `GET /style.css` مع الترويسة `If-None-Match` التي تحتوي على ETag مخزّن مؤقتًا. يؤكد الخادم أن المورد لم يتغير ويعيد `304` بلا محتوى.
- **307 Temporary Redirect**: `POST /api/submit` => يعيد الخادم التوجيه مؤقتًا إلى `/api/v2/submit`. يجب على العميل إعادة إرسال طلب `POST` (دون تغييره إلى `GET`).
- **308 Permanent Redirect**: `POST /api/old-endpoint` => يعيد الخادم التوجيه بشكل دائم إلى `/api/new-endpoint`. يجب على العميل إعادة إرسال طلب `POST` إلى العنوان الجديد.

## 4xx - خطأ من العميل {/*#4xx---client-error*/}

يحتوي الطلب على خطأ من جانب العميل.

| الرمز | الاسم                   | الوصف                                                                                                           |
| ---- | ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 400  | Bad Request            | لا يستطيع الخادم معالجة الطلب بسبب صياغة مشوهة أو مدخلات غير صالحة.                                       |
| 401  | Unauthorized           | المصادقة مطلوبة ولم تُقدَّم أو غير صالحة.                                                   |
| 403  | Forbidden              | فهم الخادم الطلب لكنه يرفض التصريح به.                                                        |
| 404  | Not Found              | المورد المطلوب غير موجود على الخادم.                                                                  |
| 405  | Method Not Allowed     | طريقة HTTP المستخدمة غير مدعومة للمورد المطلوب.                                                     |
| 408  | Request Timeout        | انتهت مهلة الخادم أثناء انتظار العميل لإنهاء إرسال الطلب.                                            |
| 409  | Conflict               | يتعارض الطلب مع الحالة الحالية للمورد (مثل إدخال مكرر).                                  |
| 413  | Content Too Large      | يتجاوز محتوى الطلب حد الحجم المسموح به في الخادم.                                                                     |
| 415  | Unsupported Media Type | لا يدعم الخادم نوع الوسائط الخاص بمحتوى الطلب.                                                       |
| 418  | I'm a Teapot           | يرفض الخادم تحضير القهوة لأنه إبريق شاي ([RFC 2324](https://datatracker.ietf.org/doc/html/rfc2324)). |
| 422  | Unprocessable Content  | الطلب صحيح نحويًا لكنه غير صالح دلاليًا (مثل أخطاء التحقق من الصحة).                               |
| 429  | Too Many Requests      | أرسل العميل طلبات كثيرة جدًا في فترة زمنية معينة (تحديد المعدل).                                         |

### أمثلة {/*#examples-3*/}

- **400 Bad Request**: `POST /api/users` مع `{ name: }` => محتوى JSON مشوه ولا يمكن تحليله.
- **401 Unauthorized**: `GET /api/profile` بدون الترويسة `Authorization` => يتطلب الخادم المصادقة.
- **403 Forbidden**: `DELETE /api/users/1` مع رمز مميز صالح لمستخدم غير مسؤول => المستخدم موثَّق لكنه يفتقر إلى الإذن.
- **404 Not Found**: `GET /api/users/99999` => لا يوجد مستخدم بهذا المعرّف.
- **405 Method Not Allowed**: `DELETE /api/login` => نقطة النهاية `/api/login` تدعم `POST` فقط.
- **408 Request Timeout**: يفتح عميل اتصالًا ويبدأ بإرسال محتوى طلب كبير لكنه يتوقف في منتصف النقل. يغلق الخادم الاتصال بعد انتهاء مهلته.
- **409 Conflict**: `POST /api/users` مع `{ "email": "a@b.com" }` => يوجد مستخدم بهذا البريد الإلكتروني بالفعل.
- **413 Content Too Large**: `POST /api/upload` مع ملف حجمه 500 ميغابايت => حد الرفع في الخادم هو 50 ميغابايت.
- **415 Unsupported Media Type**: `POST /api/data` مع `Content-Type: text/xml` => نقطة النهاية لا تقبل إلا `application/json`.
- **418 I'm a Teapot**: `BREW /coffee` => يعتذر إبريق الشاي بأدب.
- **422 Unprocessable Content**: `POST /api/users` مع `{ "email": "not-an-email" }` => JSON صالح لكن حقل البريد الإلكتروني يفشل في التحقق من الصحة.
- **429 Too Many Requests**: يرسل عميل 1000 طلب في الدقيقة إلى `/api/search` => يفرض الخادم حدًا للمعدل ويستجيب بـ `429` مع الترويسة `Retry-After`.

## 5xx - خطأ من الخادم {/*#5xx---server-error*/}

فشل الخادم في تنفيذ طلب صالح.

| الرمز | الاسم                  | الوصف                                                                                          |
| ---- | --------------------- | ---------------------------------------------------------------------------------------------------- |
| 500  | Internal Server Error | حدث خطأ غير متوقع في الخادم.                                                          |
| 502  | Bad Gateway           | تلقى الخادم، بصفته بوابة أو وكيلًا، استجابة غير صالحة من خادم أعلى المسار.      |
| 503  | Service Unavailable   | الخادم غير قادر مؤقتًا على معالجة الطلب (مثل التحميل الزائد أو الصيانة).       |
| 504  | Gateway Timeout       | لم يتلقَّ الخادم، بصفته بوابة أو وكيلًا، استجابة في الوقت المناسب من خادم أعلى المسار. |

### أمثلة {/*#examples-4*/}

- **500 Internal Server Error**: `GET /api/reports` => يحدث استثناء غير معالج في شيفرة الخادم (مثل مؤشر فارغ أو القسمة على صفر).
- **502 Bad Gateway**: يمرر وكيل عكسي (مثل Nginx) الطلب إلى خلفية تعيد استجابة مشوهة أو غير مكتملة.
- **503 Service Unavailable**: يخضع الخادم لصيانة مجدولة أو يعاني من تحميل زائد ولا يستطيع معالجة الطلبات مؤقتًا. غالبًا ما يتضمن الترويسة `Retry-After`.
- **504 Gateway Timeout**: يمرر وكيل عكسي الطلب إلى خلفية تستغرق وقتًا طويلًا جدًا للاستجابة (مثل استعلام قاعدة بيانات بطيء يتجاوز مهلة الوكيل).
