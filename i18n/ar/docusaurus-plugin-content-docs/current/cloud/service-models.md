# نماذج الخدمة السحابية

## نظرة عامة {/*#overview*/}

تُصنَّف خدمات الحوسبة السحابية عادة في ثلاثة نماذج خدمة رئيسية، يقدم كل منها مستوى مختلفًا من التحكم والمرونة.

| نموذج الخدمة                                                               | ما يديره العميل                            | ما يديره المزوّد                                                               | أمثلة                                             |
| --------------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------- |
| **[الاستضافة المحلية](#on-premise)**                                               | كل شيء                                  | لا شيء                                                                        | مركز بيانات خاص، خوادم محلية                       |
| **[IaaS](#infrastructure-as-a-service-iaas)** (البنية التحتية كخدمة) | نظام التشغيل، البرمجيات الوسيطة، بيئة التشغيل، البيانات، التطبيقات | المحاكاة الافتراضية، الخوادم، التخزين، الشبكات                                   | AWS EC2, Azure VMs, Google Compute Engine            |
| **[PaaS](#platform-as-a-service-paas)** (المنصة كخدمة)             | البيانات، التطبيقات                          | بيئة التشغيل، البرمجيات الوسيطة، نظام التشغيل، المحاكاة الافتراضية، الخوادم، التخزين، الشبكات          | Heroku, Google App Engine, Azure App Service, Vercel |
| **[FaaS](#function-as-a-service-faas--serverless)** (الدالة كخدمة) | الدوال الفردية، البيانات                  | بيئة التشغيل، التوسع، البرمجيات الوسيطة، نظام التشغيل، المحاكاة الافتراضية، الخوادم، التخزين، الشبكات | AWS Lambda, Azure Functions, Cloudflare Workers      |
| **[SaaS](#software-as-a-service-saas)** (البرمجيات كخدمة)             | الإعدادات فقط                          | كل شيء                                                                     | Gmail, Salesforce, Microsoft 365, Dropbox            |

## الاستضافة المحلية (On-Premise) {/*#on-premise*/}

### التعريف {/*#definition*/}

تعني الاستضافة المحلية (On-Premise، ويقال لها أيضًا "on-prem") تشغيل جميع البنية التحتية لتقنية المعلومات وإدارتها محليًا داخل منشآت المؤسسة نفسها. ولا يشارك أي مزوّد خدمات سحابية. وتمتلك المؤسسة كل شيء وتشغّله وتصونه، من العتاد المادي إلى التطبيقات.

### ما تتضمنه {/*#what-is-included*/}

- الخوادم والعتاد المادي
- تحكم كامل في جميع الطبقات
- تبقى البيانات داخل منشآت المؤسسة
- لا اعتماد على مزوّدين خارجيين

### المسؤوليات {/*#responsibilities*/}

**تدير المؤسسة:**

- العتاد المادي (الخوادم والتخزين والشبكات)
- المحاكاة الافتراضية
- أنظمة التشغيل
- البرمجيات الوسيطة
- بيئات التشغيل
- التطبيقات
- البيانات
- الأمان والنسخ الاحتياطي والتعافي من الكوارث

### حالات الاستخدام {/*#use-cases*/}

- **متطلبات الامتثال الصارمة:** قطاعات ذات لوائح بيانات صارمة (مثل الحكومة والرعاية الصحية والتمويل)
- **الأنظمة القديمة:** تطبيقات لا يمكن نقلها إلى السحابة
- **الحاجة إلى زمن استجابة منخفض:** أنظمة تتطلب أدنى زمن ممكن لاستجابة الشبكة
- **السيادة الكاملة على البيانات:** إبقاء البيانات الحساسة بالكامل داخل المؤسسة

### المزايا {/*#advantages*/}

- تحكم كامل في العتاد والبرمجيات
- لا تغادر البيانات مقر المؤسسة أبدًا
- لا تكاليف اشتراك سحابي متكررة
- لا اعتماد على الاتصال بالإنترنت
- امتثال أسهل للوائح البيانات الصارمة

### العيوب {/*#disadvantages*/}

- تكاليف رأسمالية أولية مرتفعة (العتاد والمنشآت والتبريد)
- يتطلب كوادر متخصصة في تقنية المعلومات للصيانة
- يتطلب التوسع شراء عتاد جديد وتركيبه
- مسؤولية كاملة عن جميع التحديثات والتصحيحات والأمان
- قد يصبح العتاد قديمًا

## البنية التحتية كخدمة (IaaS) {/*#infrastructure-as-a-service-iaas*/}

### التعريف {/*#definition-1*/}

توفر IaaS موارد حوسبة افتراضية فقط عبر الإنترنت. وتقدم اللبنات الأساسية لبناء بنية تحتية سحابية مخصصة لتقنية المعلومات.

### ما تتضمنه {/*#what-is-included-1*/}

- الأجهزة الافتراضية
- التخزين
- الشبكات
- صور أنظمة التشغيل

### المسؤوليات {/*#responsibilities-1*/}

**يدير العميل:**

- أنظمة التشغيل
- التطبيقات
- البيانات
- بيئات التشغيل
- البرمجيات الوسيطة

**يدير المزوّد:**

- الخوادم المادية
- عتاد التخزين
- معدات الشبكات
- طبقة المحاكاة الافتراضية

### حالات الاستخدام {/*#use-cases-1*/}

- **الاختبار والتطوير:** تشغيل بيئات الاختبار وإيقافها بسرعة
- **استضافة المواقع:** استضافة المواقع مع تحكم كامل في البنية التحتية
- **التخزين والنسخ الاحتياطي:** حلول تخزين بيانات واسعة النطاق
- **الحوسبة عالية الأداء:** أحمال عمل كثيفة الحوسبة

### المزايا {/*#advantages-1*/}

- تحكم كامل في البنية التحتية
- نموذج تسعير بحسب الاستخدام
- قابلية توسع عالية
- لا صيانة لعتاد مادي

### العيوب {/*#disadvantages-1*/}

- يتطلب خبرة تقنية
- تقع تصحيحات الأمان والتحديثات على عاتق العميل وحده
- عبء إدارة أكبر من PaaS/SaaS

### أمثلة {/*#examples*/}

- Amazon Web Services (AWS) EC2
- Microsoft Azure Virtual Machines
- Google Compute Engine
- Hetzner

## المنصة كخدمة (PaaS) {/*#platform-as-a-service-paas*/}

### التعريف {/*#definition-2*/}

توفر PaaS منصة تتيح للعملاء تطوير التطبيقات وتشغيلها وإدارتها دون التعامل مع البنية التحتية.

### ما تتضمنه {/*#what-is-included-2*/}

- **بيئات تشغيل جاهزة للاستخدام** (Node.js وPython وJava وPHP وغيرها)
- **قواعد بيانات مُدارة** (PostgreSQL وMySQL وMongoDB وRedis)
- **نشر تلقائي** (دفع الشيفرة عبر Git => بناء تلقائي)
- **توسع مدمج** (يتوسع التطبيق تلقائيًا بحسب حركة المرور)
- **أدوات تطوير** (تسجيل ومراقبة وتنقيح)

### المسؤوليات {/*#responsibilities-2*/}

**يدير العميل:**

- التطبيقات
- البيانات

**يدير المزوّد:**

- بيئة التشغيل
- البرمجيات الوسيطة
- أنظمة التشغيل
- المحاكاة الافتراضية
- الخوادم والتخزين والشبكات

### حالات الاستخدام {/*#use-cases-2*/}

- **تطوير التطبيقات:** بناء التطبيقات دون الانشغال بالبنية التحتية
- **تطوير واجهات API وإدارتها:** إنشاء واجهات API واستضافتها
- **بنية الخدمات المصغرة:** نشر تطبيقات في حاويات

### المزايا {/*#advantages-2*/}

- تطوير ونشر أسرع
- قابلية توسع مدمجة
- تعقيد إداري أقل
- التركيز على الشيفرة لا على البنية التحتية
- أدوات تطوير متكاملة

### العيوب {/*#disadvantages-2*/}

- تحكم أقل من IaaS
- احتمال الارتباط بمزوّد بعينه (vendor lock-in)
- قد لا تدعم جميع لغات البرمجة والأطر
- خيارات تخصيص محدودة

### أمثلة {/*#examples-1*/}

- Heroku
- Google App Engine
- Microsoft Azure App Service
- Red Hat OpenShift
- AWS Elastic Beanstalk
- Vercel وNetlify

## الدالة كخدمة (FaaS) / بدون خوادم {/*#function-as-a-service-faas--serverless*/}

### التعريف {/*#definition-3*/}

FaaS هي الامتداد المنطقي لـ PaaS: لم تعد الوحدة المنشورة تطبيقًا بل دالة واحدة. ولا تعمل بصورة دائمة، إذ يشغّلها حدث، فتعالجه ثم تتوقف مجددًا.

"بدون خوادم" (Serverless) هو المصطلح الأوسع لنموذج التشغيل هذا، وهو مضلل: فالخوادم موجودة لكنها لم تعد مرئية للعميل ولا قابلة للإدارة من جهته. وإلى جانب FaaS يشمل الخدمات المُدارة التي تتبع المبدأ نفسه، مثل قواعد البيانات بدون خوادم وتخزين الكائنات وطوابير الرسائل.

### ما تتضمنه {/*#what-is-included-3*/}

- **تنفيذ مدفوع بالأحداث:** طلب HTTP، مؤقت، رسالة في طابور، رفع ملف، تغيير في قاعدة بيانات
- **توسع تلقائي من الصفر:** لا نسخة أثناء الخمول، ونسخ متوازية كثيرة تحت الحمل
- **لا تخطيط للسعة:** لا عدد نسخ ولا حجم جهاز ولا قواعد توسع تلقائي
- **فوترة لكل استدعاء:** زمن التنفيذ والذاكرة، عادة بدقة الميلي ثانية
- **تسجيل ومراقبة متكاملان** توفرهما المنصة

### المسؤوليات {/*#responsibilities-3*/}

**يدير العميل:**

- شيفرة الدالة وتبعياتها
- الإعدادات: المشغِّلات والأذونات ومتغيرات البيئة والذاكرة ومهلة التنفيذ
- البيانات والحالة الخارجية

**يدير المزوّد:**

- بيئة التشغيل وتحديثاتها
- التوسع، بما في ذلك عدد النسخ المتوازية
- البرمجيات الوسيطة ونظام التشغيل والمحاكاة الافتراضية
- الخوادم والتخزين والشبكات

### الخصائص {/*#properties*/}

| الخاصية          | النتيجة بالنسبة للتصميم                                                                                                              |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| عديمة الحالة (Stateless)         | لا تحتفظ الدالة بأي حالة بين الاستدعاءات. مكان الحالة هو قاعدة بيانات أو ذاكرة مؤقتة أو تخزين كائنات                                     |
| البدء البارد (Cold start)        | يحتاج الاستدعاء الأول بعد فترة خمول إلى وقت إضافي لبدء بيئة التشغيل، وهو ملحوظ في الطلبات الحساسة لزمن الاستجابة |
| حد التنفيذ   | يُقطع الاستدعاء بعد أقصى مدة تشغيل. ولذلك يجب تقسيم المهام الطويلة                                          |
| مدفوعة بالأحداث      | لا تعمل الدالة إلا عندما يشغّلها حدث، ولا يمكنها البدء من تلقاء نفسها                                                            |
| التوسع من الصفر | تنتج ذروة الحمل عددًا كبيرًا من حالات البدء البارد المتوازية                                                                                         |

### حالات الاستخدام {/*#use-cases-3*/}

- **واجهات API وخطافات الويب (webhooks):** نقاط نهاية ذات حمل غير منتظم أو غير متوقع
- **معالجة الأحداث:** التفاعل مع رفع ملف أو رسالة في طابور أو تغيير في قاعدة بيانات
- **المهام المجدولة:** التنظيف والتقارير والاستيراد بحسب مؤقت
- **شيفرة الربط:** تحويلات صغيرة بين خدمتين
- **معالجة الصور والملفات:** إنشاء صور مصغرة بعد الرفع

### المزايا {/*#advantages-3*/}

- لا إدارة للخوادم ولا تخطيط للسعة
- تتناسب التكاليف تمامًا مع الحمل، وفترات الخمول مجانية
- سرعة كبيرة من الفكرة إلى نقطة نهاية منشورة
- تتولى المنصة التوسع

### العيوب {/*#disadvantages-3*/}

- يجعل البدء البارد زمن الاستجابة أقل قابلية للتنبؤ
- حدود على زمن التشغيل والذاكرة وحجم الحزمة لكل دالة
- ارتباط قوي بالمزوّد لأن المشغِّلات ونماذج الأذونات خاصة بكل مزوّد
- التنقيح والاختبار المحلي أصعب منهما في تطبيق يعمل بصورة دائمة
- تُوزِّع الدوال الصغيرة الكثيرة المنطق وتجعل السلوك العام أصعب في التتبع
- تحت حمل مرتفع ومستمر تكون نسخة تعمل بصورة دائمة أرخص عادة

### أمثلة {/*#examples-2*/}

- AWS Lambda
- Azure Functions
- Google Cloud Functions / Cloud Run Functions
- Cloudflare Workers
- Vercel Functions وNetlify Functions

## البرمجيات كخدمة (SaaS) {/*#software-as-a-service-saas*/}

### التعريف {/*#definition-4*/}

تقدم SaaS تطبيقات كاملة الوظائف عبر الإنترنت. ويصل المستخدمون إلى البرمجيات عبر متصفح ويب دون تثبيت أو صيانة.

### ما تتضمنه {/*#what-is-included-4*/}

- تطبيقات جاهزة للاستخدام
- تحديثات تلقائية
- إمكانية الوصول من أي جهاز متصل بالإنترنت
- بنية متعددة المستأجرين (Multi-tenant)

### المسؤوليات {/*#responsibilities-4*/}

**يدير العميل:**

- إعدادات المستخدمين
- إدخال البيانات
- أذونات الوصول

**يدير المزوّد:**

- كل ما عدا ذلك (التطبيق والبيانات وبيئة التشغيل والبرمجيات الوسيطة ونظام التشغيل والبنية التحتية)

### حالات الاستخدام {/*#use-cases-4*/}

- **البريد الإلكتروني والتواصل:** بريد الأعمال والمراسلة
- **إدارة علاقات العملاء (CRM)**
- **أدوات التعاون:** مشاركة المستندات وإدارة المشاريع
- **إنتاجية المكتب:** معالجة النصوص والجداول والعروض التقديمية
- **الموارد البشرية:** الرواتب والتوظيف وإدارة الموظفين

### المزايا {/*#advantages-4*/}

- لا حاجة إلى تثبيت أو صيانة
- تحديثات تلقائية
- تكاليف أولية أقل
- سهولة في الاستخدام والتوسع

### العيوب {/*#disadvantages-4*/}

- لا تحكم في البنية التحتية واعتماد كامل على الشركة المشغِّلة
- تخصيص محدود
- مخاوف أمن البيانات (تُخزَّن البيانات خارجيًا في السحابة)
- قد تتراكم تكاليف الاشتراك
- الاعتماد على الاتصال بالإنترنت

### أمثلة {/*#examples-3*/}

- **Google Workspace** (Gmail وGoogle Docs وDrive)
- **Microsoft 365** (Outlook وWord وExcel وTeams)
- **ADITO** (CRM)
- **Slack** (تواصل الفرق)
- **Dropbox** (تخزين الملفات)
- **Zoom** (مؤتمرات الفيديو)

## تشبيه البيتزا {/*#the-pizza-analogy*/}

- **الاستضافة المحلية:** صنع البيتزا في المنزل
- **IaaS:** شراء العجين والإضافات وخبزها في المنزل
- **PaaS:** طلب بيتزا بإضافات يختارها الشخص بنفسه مع توصيلها
- **FaaS:** شراء شريحة واحدة عند الجوع والدفع لكل شريحة (لا شيء يُبقى ساخنًا)
- **SaaS:** تناول الطعام في مطعم بيتزا

## نماذج خدمة إضافية {/*#additional-service-models*/}

إلى جانب النماذج الثلاثة الأساسية و[FaaS](#function-as-a-service-faas--serverless)، توجد نماذج خدمة متخصصة أخرى:

### قاعدة البيانات كخدمة (DBaaS) {/*#database-as-a-service-dbaas*/}

- حلول قواعد بيانات مُدارة
- أمثلة: Amazon RDS وAzure SQL Database وMongoDB Atlas

### الحاويات كخدمة (CaaS) {/*#container-as-a-service-caas*/}

- منصات تنسيق الحاويات
- أمثلة: Amazon ECS وGoogle Kubernetes Engine وAzure Kubernetes Service

### سطح المكتب كخدمة (DaaS) {/*#desktop-as-a-service-daas*/}

- أسطح مكتب افتراضية تُقدَّم عبر السحابة
- أمثلة: Amazon WorkSpaces وAzure Virtual Desktop وCitrix DaaS

### الواجهة الخلفية كخدمة (BaaS) {/*#backend-as-a-service-baas*/}

- يدير المزوّد الواجهة الخلفية، ويتولى العميل الواجهة الأمامية
- أمثلة: Supabase وFirebase
