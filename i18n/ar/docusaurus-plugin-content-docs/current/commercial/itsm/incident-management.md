# إدارة الحوادث

## نظرة عامة {/*#overview*/}

**إدارة الحوادث (Incident Management)** هي **المستوى الأول من ITSM**، وتركّز على مساعدة المستخدمين على استئناف عملهم بأسرع وقت ممكن بعد حدوث اضطراب في تقنية المعلومات.

## عناصر التكوين (CI) {/*#configuration-items-ci*/}

**عنصر التكوين (Configuration Item, CI)** مصطلح واسع يشمل جميع الأجهزة والبرمجيات تقريبًا. تتميز عناصر التكوين بخصائص وترتبط بعناصر تكوين أخرى.

| الفئة               | أمثلة                                                  |
| ------------------- | ------------------------------------------------------ |
| أنظمة الأجهزة       | حاسوب مكتبي، حاسوب محمول، خادم، عميل رفيع              |
| مكونات الأجهزة      | بطاقات الرسوميات، بطاقات الشبكة، الأقراص الصلبة، المعالجات |
| مكونات البرمجيات    | أنظمة التشغيل، البرمجيات التطبيقية                     |
| مكونات الشبكة       | الموجّه، المحوّل، الموزّع، المكرّر، لوحة التوصيل، NAS  |
| الأجهزة الطرفية     | الطابعة، الماسح الضوئي، كاميرا الويب                   |
| الأجهزة المحمولة    | الجهاز اللوحي، الهاتف الذكي، أجهزة التقاط البيانات     |

## تعريف الحادثة {/*#incident-definition*/}

**الحادثة (Incident)** هي أي انقطاع غير مخطط له أو تراجع في جودة خدمة تقنية المعلومات. وتُعد حادثةً أيضًا أي واقعة قد تؤثر على خدمة تقنية المعلومات مستقبلًا. ويشمل ذلك وقائع بسيطة مثل استبدال خرطوشة حبر فارغة.

**الهدف الأعلى: استعادة الخدمة المتأثرة بأسرع وقت ممكن.**

## التصنيف {/*#categorisation*/}

تُصنَّف الحوادث عند تسجيلها لأول مرة في نظام تتبع التذاكر (Issue Tracking System):

- **HW** = مشكلة في الأجهزة
- **SW** = مشكلة في البرمجيات
- **NW** = مشكلة في الشبكة

الغرض: ضمان مسؤولية الفريق المناسب وإمكانية تقييم مدى الخطورة بشكل صحيح.

## تحديد الأولويات {/*#prioritisation*/}

تتحدد الأولوية بعاملين:

- **الإلحاح (Urgency، بالألمانية Dringlichkeit):** ما مدى تأثير الاضطراب على هدف المستخدم؟
- **الأثر (Impact، بالألمانية Auswirkung):** كم عدد الأشخاص المتأثرين بالاضطراب؟

يحدد الجمع بين [الإلحاح والأثر](./priorities.md#itil-priority-matrix) ترتيب معالجة التذاكر الواردة.

## مستويات الدعم {/*#support-levels*/}

| المستوى                  | الوصف                                                                                                                                                                  |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **دعم المستوى الأول**    | مكتب المساعدة / نقطة اتصال واحدة (SPOC)؛ يعالج المشكلات البسيطة باستخدام قاعدة المعرفة ويعمل كـ"جدار حماية" لدعم المستوى الثاني عبر تولّي التواصل المباشر مع العملاء |
| **دعم المستوى الثاني**   | خبراء تحليل السبب الجذري ([إدارة المشكلات](./problem-management.md))؛ يعيد تقييم الأولوية الأولية التي حددها المستوى الأول                                              |
| **دعم المستوى الثالث**   | دعم الشركة المصنّعة أو متخصصون خارجيون عندما يعجز المستوى الثاني عن حل المشكلة                                                                                         |

## سجل الحادثة {/*#incident-record*/}

**سجل الحادثة (Incident Record)** وثيقة تتضمن جميع المعلومات عن الحادثة، وتوثّق دورة حياتها منذ التقاطها الأولي وحتى حلها. وهو وثيقة معلوماتية لا يجوز تعديلها بعد إغلاق نسخة العملية.

المكونات القياسية السبعة عشر:

1. المعرّف / ID
2. الالتقاط الأولي (التاريخ والوقت)
3. نوع الإبلاغ
4. موظف مكتب الخدمة
5. بيانات المُبلِّغ / المستخدم
6. قناة التواصل
7. **وصف العَرَض** (أهم حقل؛ يساعد في التشخيص والبحث عن الحلول)
8. المستخدمون والمواقع و/أو مجالات العمل المتأثرة
9. الخدمات المتأثرة
10. الأولوية
11. مراجع عناصر التكوين (CI)
12. فئة الحادثة
13. روابط إلى سجلات حوادث أخرى
14. روابط إلى سجلات المشكلات
15. سجل حالات الحادثة
16. سجل الأنشطة / المهام
17. بيانات الحل والإغلاق

**الحقول الخمسة الأهم التي يجب تسجيلها دائمًا:** الأولوية، وفئة الحادثة، والمعرّف، والمستخدم/الخدمة المتأثرة، وقناة التواصل.

## الحادثة الكبرى {/*#major-incident*/}

**الحادثة الكبرى (Major Incident)** واقعة عالية الأولوية وعالية الأثر تتسبب في توقف خدمة حرجة أو اضطراب واسع يؤثر بشكل كبير على العمليات التجارية. وتُمنح عادةً أولوية "حرجة" أو "عالية".

الخصائص:

- تأثر عدد كبير من العملاء أو مجموعات عملاء مهمة
- تكاليف وخسائر كبيرة للعملاء و/أو لمنظمة الخدمة
- احتمال كبير لتضرر سمعة مزوّد الخدمة
- من المرجح أن يكون الجهد والوقت اللازمان لحل الحادثة كبيرين، وأن تُنتهك اتفاقيات [SLA](./sla.md) القائمة

## طلب الخدمة مقابل الحادثة {/*#service-request-vs-incident*/}

|                | طلب الخدمة                                                 | الحادثة                                     |
| -------------- | ---------------------------------------------------------- | ------------------------------------------- |
| **المحفّز**    | يتواصل المستخدم مع الدعم بنشاط بسؤال أو رغبة               | اضطراب غير مخطط له في الخدمة                |
| **أمثلة**      | كلمة مرور منسية، سؤال عن برنامج، إعداد مكان عمل جديد       | تعطل الطابعة، تعذّر الوصول إلى ERP، برمجية فدية |
| **جهة المعالجة** | يُحل عادةً بالكامل في دعم المستوى الأول                  | قد يتطلب التصعيد إلى المستوى الثاني/الثالث  |
| **العملية**    | تلبية الطلبات (Request Fulfillment)                        | إدارة الحوادث (Incident Management)         |
