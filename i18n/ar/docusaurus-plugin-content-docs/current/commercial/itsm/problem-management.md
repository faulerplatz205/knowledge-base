# إدارة المشكلات

## نظرة عامة {/*#overview*/}

إدارة المشكلات هي **المستوى الثاني من إدارة الحوادث**. وبينما تركّز إدارة الحوادث على استعادة الخدمة بأسرع وقت ممكن، تحدد إدارة المشكلات السبب الجذري الكامن وتزيله لمنع وقوع حوادث مستقبلية.

## الحادثة مقابل المشكلة مقابل الخطأ المعروف {/*#incident-vs-problem-vs-known-error*/}

| المصطلح          | التعريف                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------- |
| **الحادثة**      | انقطاع غير مخطط له في الخدمة؛ قد يكون السبب مجهولًا؛ وتُستعاد الخدمة بوصفها أولوية       |
| **المشكلة**      | حادثة واحدة أو أكثر ذات **سبب جذري مجهول**؛ يتولى الخبراء التحقيق فيها                   |
| **الخطأ المعروف** | مشكلة معروف سببها الجذري ويتوفر لها حل بديل أو إصلاح                                    |

إذا تعذر إيجاد حل في دعم المستوى الأول، يُجرى **تصعيد** للتذكرة: تتحول الحادثة إلى مشكلة يتولى إدارتها دعم المستوى الثاني.

## الأنشطة الثلاثة لإدارة المشكلات {/*#the-three-activities-of-problem-management*/}

### 1. التحكم في المشكلات {/*#1-problem-control*/}

تُحلَّل جميع المشكلات وتُوثَّق بشكل منهجي. والهدف تحويل الأسباب المجهولة إلى **أخطاء معروفة (Known Errors)**.

الخطوات:

1. تسجيل المشكلة ومقارنتها بقاعدة بيانات الأخطاء المعروفة
2. إذا وُجد حل بديل/حل مسبقًا => خطأ معروف، مع تحديث عدّاد الحدوث
3. تصنيف المشكلة (الفئة، والفئة الفرعية، والأولوية، والأثر على الأعمال)
4. تحليل السبب الجذري (انظر [طرق التحليل](./analysis-methods.md))
5. تسجيل النتيجة كخطأ معروف جديد في KEDB

### 2. التحكم في الأخطاء {/*#2-error-control*/}

عند وجود خطأ معروف، يدير التحكم في الأخطاء المسار من الحل البديل إلى الإصلاح الدائم.

- يُقدَّم **الحل البديل (Workaround)** فورًا لاستعادة الخدمة
- يبدأ الإصلاح الدائم عبر **[RFC](./change-management.md#request-for-change-rfc)**
- بعد تنفيذ التغيير، تتلقى إدارة المشكلات تأكيدًا عبر **[مراجعة ما بعد التنفيذ (PIR)](./change-management.md#closing-a-change-pir)**
- يُبلَّغ دعم المستوى الأول ليتمكن من تحديث معلومات العميل

### 3. إدارة المشكلات الاستباقية {/*#3-proactive-problem-management*/}

منع الحوادث قبل وقوعها:

- تحليل الأخطاء المعروفة المتكررة بكثرة (عدّاد حدوث مرتفع = مرشح لإدارة المشكلات الاستباقية)
- تقييم تنبيهات الشركة المصنّعة بشأن مشكلات وشيكة في البرمجيات/الأجهزة
- مراقبة التحذيرات والاستثناءات الآلية

## الحل البديل {/*#workaround*/}

**الحل البديل (Workaround)** هو تجاوز للمشكلة أو بديل أو حل مؤقت ("الالتفاف" حول المشكلة) لاستعادة الخدمة سريعًا بشكل مؤقت أثناء معالجة السبب الجذري.

**مهم:** يجب وسم الحلول البديلة بوضوح في النظام كإجراءات مؤقتة، حتى لا يتحول الإصلاح المؤقت إلى حالة دائمة.

**أمثلة:**

| الاضطراب                             | الحل البديل                                    |
| ------------------------------------ | ---------------------------------------------- |
| تعطل كاميرا الويب المدمجة            | توصيل كاميرا USB                               |
| تعطل جهاز التقاط البيانات المحمول    | استخدام جهاز مُعار                             |
| تعطل منفذ الشبكة السلكية             | استخدام وحدة WLAN أو محوّل LAN                 |
| تعطل منفذ شاشة DVI                   | استخدام DisplayPort أو HDMI إن توفر            |
| عدم تشغيل الطابعة الليزرية           | فصلها عن الكهرباء وإعادة تشغيلها               |
| ظهور صفحة فارغة في المتصفح           | مسح ذاكرة التخزين المؤقت للمتصفح أو استخدام متصفح آخر |

## قاعدة بيانات الأخطاء المعروفة (KEDB) {/*#known-error-database-kedb*/}

تخزّن KEDB جميع المشكلات المعروفة مع حلولها البديلة أو حلولها النهائية. ويستخدمها دعم المستوى الأول لتقديم مساعدة سريعة دون التصعيد إلى المستوى الثاني.

لكل إدخال **عدّاد حدوث** (Vorfallszähler) يتتبع عدد مرات تكرار المشكلة. ويشير ارتفاع العدّاد إلى مرشح لإدارة المشكلات الاستباقية.

## مؤشرات الأداء الرئيسية (KPIs) {/*#key-kpis*/}

| مؤشر الأداء                               | المعنى                                                                                                                                      |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **عدد المشكلات الجديدة**                  | إجمالي المشكلات المسجلة في فترة ما؛ وتهدف إدارة المشكلات الاستباقية إلى تقليله بحل الأخطاء قبل تحولها إلى حوادث                              |
| **عدد الحوادث لكل مشكلة معروفة**          | متوسط عدد الحوادث المرتبطة بالمشكلة نفسها؛ يبيّن مدى اتساع الأثر ويحدد المرشحين لإدارة المشكلات الاستباقية                                   |
| **جهد حل المشكلة**                        | متوسط جهد العمل اللازم لحل مشكلة، موزعًا بحسب الفئة؛ يبيّن الفئات الأكثر استهلاكًا للجهد                                                   |

## الفصل بين تحديد موقع المشكلة وحلها {/*#separation-of-problem-localisation-and-problem-resolution*/}

تحدد إدارة المشكلات موقع السبب الجذري؛ وتتولى [إدارة التغيير](./change-management.md) حله. ويحقق هذا الفصل ما يلي:

- يتيح التركيز على مهمة واحدة في كل مرة
- يمكّن من استعادة الخدمة (الحل البديل) قبل اكتمال التحقيق في السبب الجذري
- لا يستلزم بالضرورة فرقًا مختلفة، ولكنه يفصل بين خطوات العملية
