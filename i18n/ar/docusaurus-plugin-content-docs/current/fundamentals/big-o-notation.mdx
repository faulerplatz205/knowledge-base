# ترميز Big O

## نظرة عامة {/* #overview */}

يصف ترميز Big O كيف ينمو جهد الخوارزمية مع مدخلاتها. وبدلًا من ذكر زمن بالثواني، يبيّن شكل هذا النمو.

يُسمى حجم المدخلات **n**: وهو يمثل عدد العناصر في قائمة، أو الأحرف في سلسلة نصية، أو الصفوف في جدول. وتجيب كل فئة تعقيد عن السؤال: **ماذا يحدث لعدد الخطوات عندما يتضاعف n؟**

| الترميز | الاسم | عندما يتضاعف n، فإن الجهد ... | مثال |
| ------- | ----- | ----------------------------- | ---- |
| O(1)       | ثابت | يبقى كما هو | الوصول إلى مصفوفة بالفهرس |
| O(log n)   | لوغاريتمي | ينمو بخطوة واحدة | البحث الثنائي |
| O(n)       | خطي | يتضاعف | البحث الخطي |
| O(n log n) | خطي لوغاريتمي | يزيد قليلًا على الضعف | الفرز بالدمج (Merge sort) |
| O(n²)      | تربيعي | يصبح أربعة أضعاف | الفرز الفقاعي، الحلقات المتداخلة على القائمة نفسها |
| O(2ⁿ)      | أسي | يُربَّع | تجربة كل مجموعة جزئية من مجموعة |

في حالة O(2ⁿ)، تكفي إضافة عنصر واحد لمضاعفة الجهد.

---

## النمو بالأرقام {/* #growth-in-numbers */}

عدد الخطوات التي تحتاجها كل فئة تعقيد لمدخلات من n عنصر (اللوغاريتم بالأساس 2، مقرَّبًا):

| n         | O(1) | O(log n) | O(n)      | O(n log n) | O(n²)     | O(2ⁿ)         |
| --------- | ---- | -------- | --------- | ---------- | --------- | ------------- |
| 10        | 1    | 3        | 10        | 33         | 100       | 1,024         |
| 100       | 1    | 7        | 100       | 664        | 10,000    | ≈ 1.3 x 10³⁰  |
| 1,000     | 1    | 10       | 1,000     | 9,966      | 1,000,000 | ≈ 1.1 x 10³⁰¹ |
| 1,000,000 | 1    | 20       | 1,000,000 | ≈ 2 x 10⁷  | 10¹²      | ≈ 10³⁰¹⁰³⁰    |

بمعدل ميكروثانية واحدة لكل خطوة ومليون عنصر، تحتاج خوارزمية O(log n) إلى 20 µs، وخوارزمية O(n) إلى ثانية واحدة، وخوارزمية O(n log n) إلى نحو 20 ثانية، وخوارزمية O(n²) إلى 10⁶ ثانية، أي نحو 11.6 يومًا.

## التعريف الصوري {/* #formal-definition */}

f(n) هو عدد الخطوات التي تحتاجها الخوارزمية، وg(n) دالة مقارنة بسيطة مثل n أو n². تنتمي f(n) إلى O(g(n)) إذا كانت f، ابتداءً من حجم مدخلات معين، تنمو على الأكثر بسرعة g مضروبةً في عامل ثابت.

بصورة صورية: يوجد ثابت c > 0 وعتبة n₀ بحيث تتحقق f(n) ≤ c x g(n) لكل n ≥ n₀.

مثال: f(n) = 3n + 5 تنتمي إلى O(n). مع c = 4 وn₀ = 5، تتحقق 3n + 5 ≤ 4n لكل n ≥ 5.

- تُمتص العوامل الثابتة في c. و`3n` و`n / 2` و`100n` كلها تنتمي إلى O(n).
- السلوك دون n₀ غير ذي أهمية، لأن Big O يصف المدخلات الكبيرة فقط.
- O حد أعلى. وبالمعنى الدقيق، ينتمي البحث الثنائي أيضًا إلى O(n) وإلى O(n²). وعمليًا تُذكر أصغر فئة مناسبة.
- يُكتب الحد الأدنى Ω (أوميغا). ويُكتب الحد الذي هو أعلى وأدنى معًا Θ (ثيتا).

## تحديد فئة التعقيد {/* #determining-the-complexity-class */}

تُحدَّد فئة التعقيد بعدّ العملية الأكثر تكرارًا، وهي عادةً مقارنة أو إسناد في الحلقة الأعمق، كدالة في n ثم تبسيط النتيجة.

### عبارات منفردة: O(1) {/* #single-statements-o1 */}

الإسنادات والعمليات الحسابية والمقارنات والوصول إلى مصفوفة بالفهرس و`RETURN` تُنفَّذ عددًا ثابتًا من المرات لا يعتمد على n.

```text
first = list[0]
sum = a + b
```

### حلقة على المدخلات: O(n) {/* #loop-over-the-input-on */}

```text
FOR i = 0 TO n - 1
    sum = sum + list[i]
END FOR
```

تعمل `FOR` n مرة. والحلقة التي تعمل `n / 2` أو `2n` مرة هي O(n) أيضًا.

### الحلقات المتداخلة: الضرب {/* #nested-loops-multiply */}

تُضرب أعداد تكرارات الحلقات المتداخلة. وعندما تعمل الحلقتان على المدخلات، ينتج n x n خطوة وO(n²):

```text
FOR i = 0 TO n - 1
    FOR j = 0 TO n - 1
        ...
    END FOR
END FOR
```

وعندما يكون للحلقة الداخلية عدد ثابت من التكرارات، ينتج n x 7 = 7n خطوة، وبالتالي O(n):

```text
FOR i = 0 TO n - 1
    FOR day = 1 TO 7        // 7 iterations, independent of n
        ...
    END FOR
END FOR
```

### كتل متتالية: الاحتفاظ بأكبر حد {/* #consecutive-blocks-keep-the-largest-term */}

عندما تُنفَّذ كتل الشيفرة الواحدة تلو الأخرى، تُجمع أعداد خطواتها. ولا يحدد الفئة سوى الجزء الأسرع نموًا في المجموع:

```text
FOR i = 0 TO n - 1              // n steps
    ...
END FOR
FOR i = 0 TO n - 1              // n x n steps
    FOR j = 0 TO n - 1
        ...
    END FOR
END FOR
```

n + n² خطوة تعطي O(n²). وكلما كبر n، قلّت أهمية الجزء الأصغر.

### التنصيف: O(log n) {/* #halving-olog-n */}

عندما تنصّف كل خطوة المشكلة المتبقية، يساوي عدد الخطوات عدد المرات التي يمكن فيها تنصيف n حتى يبقى عنصر واحد. هذا العدد هو log₂ n. ويحذف Big O الأساس، لأن log₂ n وlog₁₀ n يختلفان بعامل ثابت فقط.

```text
1,000,000 => 500,000 => 250,000 => ... => 1      20 halvings
```

يعمل البحث الثنائي بهذه الطريقة على قائمة مرتبة:

```text
low = 0
high = n - 1
WHILE low <= high
    mid = (low + high) DIV 2
    IF list[mid] == target THEN
        RETURN mid
    ELSE IF list[mid] < target THEN
        low = mid + 1
    ELSE
        high = mid - 1
    END IF
END WHILE
RETURN -1
```

### فرّق تسد: O(n log n) {/* #divide-and-conquer-on-log-n */}

ينصّف الفرز بالدمج القائمة حتى تبقى عناصر مفردة. وينتج عن ذلك log n مستوى. وفي كل مستوى تُدمج جميع العناصر الـ n مرة واحدة. وبذلك فإن log n مستوى x n خطوة لكل مستوى تعطي O(n log n).

### مدخلان: متغيران {/* #two-inputs-two-variables */}

عندما تعمل خوارزمية على مدخلين مستقلين بحجمين n وm، يظهر كلاهما في النتيجة:

```text
FOR EACH customer IN customers          // n customers
    FOR EACH product IN products        // m products
        ...
    END FOR
END FOR
```

تعطي الحلقتان المتداخلتان n x m خطوة، وبالتالي O(n x m). وتعطي حلقتان متتاليتان O(n + m). وعلى خلاف n + n²، لا يمكن حذف أي من الحدين، لأنه لا يُعرف أي المدخلين أكبر.

## أفضل حالة والحالة المتوسطة وأسوأ حالة {/* #best-average-and-worst-case */}

تحتاج الخوارزمية نفسها إلى عدد مختلف من الخطوات بحسب المدخلات:

- **أفضل حالة (Best case):** المدخلات الأكثر ملاءمة. في البحث الخطي، هي قيمة في الموضع الأول تُوجد بعد مقارنة واحدة. تصف أفضل حالة مصادفة سعيدة ولا تقول الكثير عن السلوك المعتاد.
- **الحالة المتوسطة (Average case):** الجهد المتوقع على جميع المدخلات. في البحث الخطي، هي n / 2 مقارنة، أي O(n).
- **أسوأ حالة (Worst case):** المدخلات الأقل ملاءمة. في البحث الخطي، هي قيمة في الموضع الأخير أو قيمة غير موجودة، وتكلف n مقارنة. وأسوأ حالة ضمان لا تتجاوزه الخوارزمية أبدًا.

التعقيد المذكور دون وصف إضافي يشير إلى أسوأ حالة. ويمكن أن تختلف الحالة المتوسطة وأسوأ حالة اختلافًا جذريًا في الفئة: يحتاج Quicksort إلى O(n log n) في المتوسط، لكن إلى O(n²) عندما يكون عنصر المحور دائمًا أصغر قيمة أو أكبرها.

## تعقيد المساحة {/* #space-complexity */}

يصف الترميز نفسه الذاكرة التي تحتاجها الخوارزمية إضافةً إلى مدخلاتها.

- **O(1):** عدد ثابت من المتغيرات، مثل الفرز الفقاعي الذي يبدّل العناصر داخل القائمة (in place).
- **O(log n):** التكرار الذاتي (recursion) الذي ينصّف المشكلة يُبقي log n استدعاء في المكدس في الوقت نفسه.
- **O(n):** بنية مساعدة تنمو مع المدخلات، مثل القائمة المؤقتة في الفرز بالدمج أو مجموعة بكل القيم التي صودفت.

يمكن في كثير من الأحيان المبادلة بين الزمن والذاكرة. ويبيّن [المثال التطبيقي](#worked-example-finding-duplicates) مبادلة من هذا النوع.

## فئات الخوارزميات الشائعة {/* #classes-of-common-algorithms */}

### البحث {/* #searching */}

| الخوارزمية | أفضل حالة | الحالة المتوسطة | أسوأ حالة | مساحة إضافية | الشرط المسبق |
| ---------- | --------- | --------------- | --------- | ------------ | ------------ |
| البحث الخطي | O(1)      | O(n)         | O(n)       | O(1)        | لا شيء |
| البحث الثنائي | O(1)      | O(log n)     | O(log n)   | O(1)        | بيانات مرتبة مع وصول بالفهرس |

### الفرز {/* #sorting */}

| الخوارزمية | أفضل حالة | الحالة المتوسطة | أسوأ حالة | مساحة إضافية | مستقر |
| ---------- | --------- | --------------- | --------- | ------------ | ----- |
| الفرز الفقاعي (Bubble sort) | O(n)¹      | O(n²)        | O(n²)      | O(1)        | نعم |
| الفرز بالاختيار (Selection sort) | O(n²)      | O(n²)        | O(n²)      | O(1)        | لا |
| الفرز بالإدراج (Insertion sort) | O(n)²      | O(n²)        | O(n²)      | O(1)        | نعم |
| الفرز بالدمج (Merge sort) | O(n log n) | O(n log n)   | O(n log n) | O(n)        | نعم |
| Quicksort | O(n log n) | O(n log n)   | O(n²)      | O(log n)    | لا |

¹ فقط مع خروج مبكر يتوقف بعد دورة لا يحدث فيها أي تبديل. وبدونه يحتاج الفرز الفقاعي دائمًا إلى O(n²).

² في قائمة مرتبة أصلًا، يُقارن كل عنصر بسابقه مرة واحدة ويبقى في مكانه.

يكون الفرز **مستقرًا (stable)** عندما تحتفظ العناصر ذات المفاتيح المتساوية بترتيبها الأصلي. والمفتاح هو القيمة التي تُفرز القائمة بحسبها. وقائمة أشخاص مرتبة أصلًا بحسب الاسم ثم مفروزة بصورة مستقرة بحسب العمر تُبقي الأشخاص ذوي العمر نفسه بترتيب أبجدي.

يحتاج الفرز الذي لا يقارن سوى عنصرين في كل مرة إلى نحو n log n مقارنة على الأقل في أسوأ حالة. ولذلك يبلغ الفرز بالدمج أفضل فئة ممكنة للفرز القائم على المقارنة. ولا يمكن أن تكون أسرع إلا عمليات الفرز التي تستخدم القيم مباشرة، مثل الفرز بالعدّ (counting sort) للأعداد الصحيحة الصغيرة.

### بنى البيانات {/* #data-structures */}

| العملية | المصفوفة | القائمة المترابطة | جدول التجزئة |
| ------- | -------- | ----------------- | ------------ |
| الوصول إلى العنصر عند i | O(1)                  | O(n)¹       | غير منطبق²      |
| البحث عن قيمة أو مفتاح  | O(n)، وللمرتبة O(log n) | O(n)        | O(1) في المتوسط بحسب المفتاح³ |
| الإدراج في البداية    | O(n)⁴                 | O(1)⁵       | غير منطبق²      |

¹ يعرف كل عنصر خليفته فقط، لذلك تُجتاز القائمة من البداية.

² ليس لجدول التجزئة ترتيب لعناصره، لذلك لا يوجد موضع.

³ تحسب دالة التجزئة موقع التخزين، أي الحاوية (bucket)، مباشرة من المفتاح. وعندما تقع مفاتيح كثيرة في الحاوية نفسها، يُبحث فيها واحدًا تلو الآخر، ويتدهور البحث إلى O(n) في أسوأ حالة.

## مثال تطبيقي: إيجاد التكرارات {/* #worked-example-finding-duplicates */}

تفحص دالة ما إذا كانت قائمة تحتوي على قيمة مرتين.

### الصيغة 1: مقارنة كل زوج {/* #variant-1-compare-every-pair */}

```text
FUNCTION hasDuplicates(list)
    n = LENGTH(list)
    FOR i = 0 TO n - 2
        FOR j = i + 1 TO n - 1
            IF list[i] == list[j] THEN
                RETURN true
            END IF
        END FOR
    END FOR
    RETURN false
END FUNCTION
```

أسوأ حالة هي قائمة بلا تكرارات، فيُقارن كل زوج:

```text
i = 0        n - 1 comparisons
i = 1        n - 2 comparisons
...
i = n - 2    1 comparison

Total:  (n - 1) + (n - 2) + ... + 1  =  n x (n - 1) / 2  =  0.5n² - 0.5n
n = 5:  4 + 3 + 2 + 1                =  5 x 4 / 2        =  10
```

يؤدي حذف الحد الأصغر `0.5n` والعامل الثابت `0.5` إلى **O(n²)**. تقصر الحلقة الداخلية في كل دورة، لكنها في المتوسط ما تزال تمر على نصف القائمة. عند n = 1,000 يكون العدد 499,500 مقارنة، وعند n = 2,000 يكون 1,999,000، أي أربعة أضعاف.

### الصيغة 2: الفرز أولًا ثم مقارنة الجيران {/* #variant-2-sort-first-then-compare-neighbours */}

```text
FUNCTION hasDuplicates(list)
    n = LENGTH(list)
    sort(list)                          // O(n log n)
    FOR i = 0 TO n - 2                  // O(n)
        IF list[i] == list[i + 1] THEN
            RETURN true
        END IF
    END FOR
    RETURN false
END FUNCTION
```

بعد الفرز، تقع القيم المتساوية متجاورة، وتكفي دورة واحدة على الأزواج المتجاورة. O(n log n) + O(n) تعطي **O(n log n)**. وما لم تفرز الدالة نسخة، فإنها تغيّر ترتيب القائمة الممررة. وتكلف النسخة O(n) من الذاكرة.

### الصيغة 3: تذكّر القيم التي صودفت {/* #variant-3-remember-seen-values */}

```text
FUNCTION hasDuplicates(list)
    seen = empty set
    FOR EACH value IN list              // n iterations
        IF seen CONTAINS value THEN     // O(1) average
            RETURN true
        END IF
        ADD value TO seen               // O(1) average
    END FOR
    RETURN false
END FUNCTION
```

تجيب مجموعة (set) قائمة على التجزئة عن «contains» في زمن ثابت في المتوسط. وn تكرار بتكلفة O(1) لكل منها يعطي **O(n)**. وتكلف المجموعة O(n) من الذاكرة الإضافية.

### المقارنة {/* #comparison */}

| الصيغة | الزمن | مساحة إضافية | الخطوات عند n = 1,000,000 |
| ------ | ----- | ------------ | ------------------------- |
| 1: كل زوج | O(n²)      | O(1)                   | ≈ 5 x 10¹¹              |
| 2: الفرز أولًا | O(n log n) | O(1)، ومع نسخة O(n) | ≈ 2 x 10⁷               |
| 3: مجموعة (Set) | O(n)       | O(n)                   | ≈ 10⁶                   |

ما يبيّنه هذا المثال:

- لا يحسّن الفئة سوى نهج مختلف. وتحسين الحلقة الداخلية في الصيغة 1 يغيّر العامل الثابت فقط.
- تشتري الصيغة 3 سرعتها بالذاكرة.

## أخطاء شائعة {/* #common-mistakes */}

1. **عدّ كل حلقة متداخلة على أنها O(n²):** تعتمد الفئة على عدد مرات تشغيل كل حلقة. والحلقة الداخلية ذات العدد الثابت من التكرارات، مثل أيام الأسبوع السبعة، لا تضرب إلا بعامل ثابت، وتبقى النتيجة O(n).
2. **كتابة مدخلين مختلفين على أنهما n:** حلقة على n عميل متداخلة مع حلقة على m منتج هي O(n x m). وتفترض O(n²) أن للمدخلين الحجم نفسه وتخفي أيهما يتحكم في الجهد.
3. **الإبقاء على الثوابت والحدود الأصغر:** O(2n + 5) وO(n² + n) صحيحتان صوريًا لكنهما غير مبسطتين. والفئتان هما O(n) وO(n²) على التوالي، لأن الثوابت والحدود الأصغر لا تؤثر في النمو عند n الكبير.
4. **قراءة Big O على أنه زمن تشغيل بالثواني:** يخفي الترميز العوامل الثابتة، لذلك يمكن أن تكون خوارزمية O(n²) أسرع من خوارزمية O(n log n) عند n الصغير. ويتفوق الفرز بالإدراج على الفرز بالدمج في القوائم القصيرة، ولهذا تستخدم تطبيقات الفرز العملية مثل Timsort الفرز بالإدراج للأجزاء القصيرة.
5. **البحث الثنائي على بيانات غير مرتبة:** لا يصح O(log n) إلا على بيانات مرتبة مع وصول بالفهرس. ويكلف الفرز المسبق O(n log n) ولا يجدي إلا عندما يُبحث في البيانات نفسها مرات كثيرة.
6. **الخلط بين log n وn log n:** ينمو O(log n) أبطأ من الخطي ويحتاج إلى خطوات أقل بكثير من عدد العناصر. وينمو O(n log n) أسرع من الخطي ويُجري log n خطوة لكل عنصر.
