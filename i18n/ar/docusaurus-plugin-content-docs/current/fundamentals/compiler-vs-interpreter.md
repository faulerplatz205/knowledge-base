# المُصرِّف مقابل المفسِّر

## نظرة عامة {/*#overview*/}

لا يستطيع المعالج تنفيذ سوى شيفرة الآلة. ولذلك يجب ترجمة الشيفرة المصدرية المكتوبة بلغة عالية المستوى أولًا.
ويوجد نهجان أساسيان:

- **المُصرِّف (Compiler)**: يترجم البرنامج بأكمله **قبل** التنفيذ إلى ناتج مستقل مقروء آليًا
- **المفسِّر (Interpreter)**: يقرأ الشيفرة المصدرية **أثناء** التنفيذ وينفذ كل عبارة فورًا

كون اللغة مصرَّفة أو مفسَّرة خاصية **للتنفيذ البرمجي للغة (implementation)**، لا للغة
نفسها. فلغة C تُصرَّف عادةً، لكن توجد مفسِّرات للغة C؛ وكانت JavaScript تُفسَّر تاريخيًا
وتُصرَّف في وقت التشغيل بواسطة المحركات الحديثة.

## المُصرِّف {/*#compiler*/}

### عملية الترجمة {/*#translation-process*/}

تُنفَّذ الترجمة عادةً في عدة مراحل:

1. **التحليل المعجمي**: يُقسَّم تيار الأحرف إلى رموز (tokens) (كلمات مفتاحية ومعرّفات ومعاملات)
2. **التحليل النحوي**: تُفحص الرموز مقابل القواعد النحوية وتتحول إلى شجرة نحوية
3. **التحليل الدلالي**: يُتحقق من توافق الأنواع والتصريحات والنطاقات
4. **التحسين**: يُحسَّن التمثيل الوسيط (مثل حذف الشيفرة الميتة وفك الحلقات)
5. **توليد الشيفرة**: تُصدَر شيفرة الآلة، عادةً على هيئة ملفات كائنية (object files)

ثم يجمع **الرابط (linker)** الملفات الكائنية مع المكتبات المطلوبة في برنامج قابل للتنفيذ.

```text
Source Code => [Compiler] => Object Code => [Linker] => Executable => [CPU]
```

تُبلَّغ الأخطاء في وقت التصريف، لذلك لا يصل برنامج يحتوي على أخطاء نحوية أو أخطاء أنواع إلى التنفيذ أبدًا.

### المزايا {/*#advantages*/}

- **سرعة التنفيذ**: تعمل شيفرة الآلة المترجمة مباشرة على المعالج
- **الكشف المبكر عن الأخطاء**: تظهر الأخطاء النحوية وكثير من الأخطاء الدلالية قبل تسليم البرنامج
- **التحسين**: يكون البرنامج بأكمله مرئيًا، مما يتيح تحسينات واسعة
- **حماية الشيفرة المصدرية**: لا يلزم توزيع سوى الناتج المصرَّف
- **عدم وجود اعتماد على بيئة التشغيل**: لا يحتاج النظام المستهدف إلى تثبيت أداة المصرِّف

### العيوب {/*#disadvantages*/}

- **زمن التصريف**: يتطلب كل تغيير بناءً جديدًا قبل أن يمكن اختباره
- **الاعتماد على المنصة**: ترتبط شيفرة الآلة ببنية معالج ونظام تشغيل محددين، لذلك يلزم
  بناء منفصل لكل منصة مستهدفة
- **جهد تنقيح الأخطاء**: لم تعد شيفرة الآلة المنفَّذة تشبه الشيفرة المصدرية، مما يتطلب
  رموز تنقيح (debug symbols)

## المفسِّر {/*#interpreter*/}

يقرأ المفسِّر الشيفرة المصدرية عبارةً عبارة ويحللها وينفذها فورًا. ولا يُنتَج
ملف قابل للتنفيذ بصورة منفصلة. ويجب أن يكون المفسِّر موجودًا على النظام المستهدف.

```text
Source Code => [Interpreter] => Statement analysed and executed => [CPU]
```

لا تظهر الأخطاء إلا عندما يُبلَغ السطر المتأثر فعليًا. ولذلك قد يبقى خطأ نحوي في فرع نادر الاستخدام
دون ملاحظة لوقت طويل.

### المزايا {/*#advantages-1*/}

- **دورة تطوير سريعة**: يمكن تنفيذ الشيفرة المعدلة فورًا دون خطوة بناء
- **الاستقلال عن المنصة**: تعمل الشيفرة المصدرية نفسها أينما توفر مفسِّر
- **تنقيح أسهل للأخطاء**: تُبلَّغ الأخطاء بالإحالة إلى سطر الشيفرة المصدرية الأصلي
- **المرونة**: يمكن توليد الشيفرة وتنفيذها في وقت التشغيل

### العيوب {/*#disadvantages-1*/}

- **سرعة التنفيذ**: تحدث كلفة الترجمة في كل تشغيل، وبصورة متكررة للشيفرة داخل الحلقات
- **الكشف المتأخر عن الأخطاء**: لا تظهر الأخطاء إلا في وقت التشغيل
- **الاعتماد على بيئة التشغيل**: يجب تثبيت المفسِّر على النظام المستهدف
- **انكشاف الشيفرة المصدرية**: يُسلَّم البرنامج عادةً على هيئة شيفرة مصدرية مقروءة

## الشيفرة الوسيطة (Bytecode) والآلات الافتراضية {/*#bytecode-and-virtual-machines*/}

تجمع معظم المنصات الحديثة بين النهجين. تُصرَّف الشيفرة المصدرية إلى **Bytecode**، وهي شيفرة
وسيطة مضغوطة غير مرتبطة بمعالج محدد. ثم تنفذ **آلة افتراضية** (VM) هذه
الشيفرة الوسيطة على النظام المستهدف.

```text
Source Code => [Compiler] => Bytecode => [Virtual Machine] => Machine Code => [CPU]
```

| المنصة | المصرِّف | الشيفرة الوسيطة | بيئة التشغيل |
| ------ | -------- | --------------- | ------------ |
| Java      | `javac`  | Bytecode (`.class`)                | JVM (Java Virtual Machine)    |
| C# / .NET | `csc`    | CIL (Common Intermediate Language) | CLR (Common Language Runtime) |
| Python    | مضمَّن | Bytecode (`.pyc`)                  | Python VM                     |

يفصل هذا بين الأمرين المعتمدين على المنصة: يعمل المصرِّف مرة واحدة وينتج شيفرة وسيطة قابلة للنقل،
بينما لا يلزم تطبيق سوى الآلة الافتراضية لكل منصة. والنتيجة هي مبدأ
*اكتب مرة، شغّل في أي مكان*، على حساب طبقة إضافية بين البرنامج والعتاد.

## التصريف في وقت التشغيل (Just-in-Time) {/*#just-in-time-compilation*/}

**المصرِّف الفوري (JIT)** جزء من الآلة الافتراضية. تُفسَّر الشيفرة الوسيطة في البداية، وتسجل
بيئة التشغيل عدد مرات تنفيذ كل مقطع. وتُصرَّف المقاطع كثيرة الاستخدام، المسماة *النقاط الساخنة (hot spots)*،
إلى شيفرة آلة أصلية في وقت التشغيل وتُخزَّن مؤقتًا، بحيث تعمل الاستدعاءات اللاحقة بسرعة الشيفرة الأصلية.

```text
Bytecode => [Interpretation + Profiling] => hot code => [JIT Compiler] => cached Machine Code
```

### المزايا {/*#advantages-2*/}

- **سرعة قريبة من الأصلية** مع الاحتفاظ بقابلية نقل الشيفرة الوسيطة
- **معلومات وقت التشغيل** مثل أنواع البيانات الفعلية وتكرار الفروع تتيح تحسينات لا يستطيع
  مصرِّف ساكن تنفيذها

### العيوب {/*#disadvantages-2*/}

- **مرحلة الإحماء**: تكون عمليات التنفيذ الأولى بطيئة، وهو أمر ملحوظ في البرامج قصيرة التشغيل
- **استهلاك الذاكرة**: تشغل بيانات التنميط والشيفرة المصرَّفة ذاكرة إضافية
- **توقيت أقل قابلية للتنبؤ**: يجعل التصريف أثناء التنفيذ أزمنة التشغيل متذبذبة، وهو أمر إشكالي
  للأنظمة الآنية

ويقابله **التصريف المسبق (AOT، Ahead-of-Time)**، حيث تُترجم الشيفرة الوسيطة بالكامل قبل
التنفيذ. وهذا يزيل مرحلة الإحماء ويقصّر زمن بدء التشغيل، لكنه يفقد معلومات وقت التشغيل،
ولذلك يُستخدم للعمليات قصيرة العمر مثل أدوات سطر الأوامر أو الدوال بلا خادم (serverless).

### JIT مقابل AOT {/*#jit-vs-aot*/}

| المعيار | Just-in-Time (JIT) | Ahead-of-Time (AOT) |
| ------- | ------------------ | ------------------- |
| نقطة الترجمة | في وقت التشغيل، للشيفرة كثيرة الاستخدام | بالكامل قبل التنفيذ |
| زمن بدء التشغيل | بطيء، مرحلة إحماء | سريع، دون إحماء |
| الأداء الأقصى | مرتفع، بفضل التحسين في وقت التشغيل | محدود، تحسين ساكن فقط |
| أساس التحسين | ملف تشغيل فعلي (نقاط ساخنة، أنواع) | تحليل ساكن للشيفرة فقط |
| استهلاك الذاكرة | أعلى، بيانات تنميط وذاكرة مؤقتة للشيفرة | أقل |
| إمكانية التنبؤ بالتوقيت | متذبذب | يمكن التنبؤ به |
| ميزات اللغة الديناميكية | غير مقيدة | مقيدة، تتطلب إعدادًا |
| حالات الاستخدام النموذجية | تطبيقات الخوادم وسطح المكتب طويلة التشغيل | العمليات قصيرة العمر وأدوات CLI والدوال بلا خادم |

## المحوِّل المصدري (Transpiler) {/*#transpiler*/}

يترجم **المحوِّل المصدري** (مصرِّف من مصدر إلى مصدر) الشيفرة المصدرية إلى الشيفرة المصدرية للغة
أخرى بمستوى التجريد نفسه، بدلًا من شيفرة الآلة. ومن الأمثلة النموذجية TypeScript
التي تُحوَّل إلى JavaScript، وSass التي تُحوَّل إلى CSS.

```text
TypeScript => [Transpiler] => JavaScript => [Engine with JIT] => Machine Code
```

## المقارنة {/*#comparison*/}

| المعيار | المصرِّف | المفسِّر |
| ------- | -------- | -------- |
| نقطة الترجمة | بالكامل قبل التنفيذ | أثناء التنفيذ، عبارةً عبارة |
| الناتج | ملف قابل للتنفيذ | لا يوجد ناتج منفصل |
| سرعة التنفيذ | عالية | منخفضة |
| كشف الأخطاء | في وقت التصريف | في وقت التشغيل، في الشيفرة المنفَّذة فقط |
| دورة التطوير | أبطأ، يتطلب بناءً | أسرع، تنفيذ فوري |
| الاستقلال عن المنصة | منخفض، بناء واحد لكل منصة | مرتفع، يتطلب مفسِّرًا |
| المتطلبات على النظام المستهدف | لا شيء | يجب تثبيت المفسِّر |
| حماية الشيفرة المصدرية | متوفرة | غير متوفرة عادةً |

## الممثلون النموذجيون {/*#typical-representatives*/}

- **مصرَّفة إلى شيفرة آلة**: C وC++ وRust وGo وDelphi
- **مفسَّرة**: نصوص Shell وPerl وPHP وRuby وPython
- **Bytecode مع VM وJIT**: Java وKotlin وC#، وJavaScript في محركات مثل V8
