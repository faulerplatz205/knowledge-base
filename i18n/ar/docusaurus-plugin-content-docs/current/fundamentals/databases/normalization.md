# التطبيع

## نظرة عامة {/*#overview*/}

التطبيع (Normalization) هو عملية هيكلة قاعدة بيانات علائقية لتقليل تكرار البيانات وتحسين سلامتها. ويبني كل شكل نظامي على الشكل الذي يسبقه.

## التكرار {/*#redundancy*/}

التكرار (Redundancy) هو التكرار غير الضروري للبيانات نفسها في قاعدة البيانات.

## الشكل النظامي الأول (1NF) {/*#first-normal-form-1nf*/}

**القاعدة**: يجب أن يحتوي كل عمود على قيم ذرية (غير قابلة للتجزئة)، ويجب أن يكون كل صف فريدًا.

**المخالفة**: عمود `Phone` يخزّن عدة أرقام في خلية واحدة.

| CustomerID | Name  | Phone            |
| ---------- | ----- | ---------------- |
| 1          | Alice | 111-111, 222-222 |

**بعد التصحيح**:

| CustomerID | Name  | Phone   |
| ---------- | ----- | ------- |
| 1          | Alice | 111-111 |
| 1          | Alice | 222-222 |

**المخالفة**: عدة أعمدة للخاصية نفسها.

| CustomerID | Name  | Phone1  | Phone2  |
| ---------- | ----- | ------- | ------- |
| 1          | Alice | 111-111 | 222-222 |

**بعد التصحيح**:

| CustomerID | Name  | Phone   |
| ---------- | ----- | ------- |
| 1          | Alice | 111-111 |
| 1          | Alice | 222-222 |

## الشكل النظامي الثاني (2NF) {/*#second-normal-form-2nf*/}

**القاعدة**: يجب أن يكون في 1NF، ويجب أن تعتمد كل خاصية غير مفتاحية على **كامل** المفتاح الأساسي، وليس على جزء منه فقط

**المخالفة**: يستخدم الجدول `(OrderID, ProductID)` كمفتاح مركب، لكن `ProductName` يعتمد على `ProductID` فقط.

| OrderID | ProductID | ProductName | Quantity |
| ------- | --------- | ----------- | -------- |
| 1       | 42        | Keyboard    | 2        |
| 2       | 42        | Keyboard    | 1        |

**بعد التصحيح**: نقل `ProductName` إلى جدول `Products` منفصل.

**Orders**:

| OrderID | ProductID | Quantity |
| ------- | --------- | -------- |
| 1       | 42        | 2        |
| 2       | 42        | 1        |

**Products**:

| ProductID | ProductName |
| --------- | ----------- |
| 42        | Keyboard    |

## الشكل النظامي الثالث (3NF) {/*#third-normal-form-3nf*/}

**القاعدة**: يجب أن يكون في 2NF، ولا يجوز أن تعتمد أي خاصية غير مفتاحية على خاصية غير مفتاحية أخرى (لا اعتماديات متعدية).

**المخالفة**: `DepartmentHead` يعتمد على `Department`، وليس مباشرة على `EmployeeID`.

| EmployeeID | Department | DepartmentHead |
| ---------- | ---------- | -------------- |
| 1          | Sales      | Carol          |
| 2          | Sales      | Carol          |
| 3          | IT         | Dave           |

**بعد التصحيح**: نقل `DepartmentHead` إلى جدول `Departments` منفصل.

**Employees**:

| EmployeeID | Department |
| ---------- | ---------- |
| 1          | Sales      |
| 2          | Sales      |
| 3          | IT         |

**Departments**:

| Department | DepartmentHead |
| ---------- | -------------- |
| Sales      | Carol          |
| IT         | Dave           |

## الخلاصة {/*#summary*/}

| الشكل النظامي | المتطلب                                                     |
| ------------- | ----------------------------------------------------------- |
| 1NF           | قيم ذرية، دون أعمدة متكررة، وصفوف فريدة                     |
| 2NF           | 1NF + دون اعتماديات جزئية على مفتاح مركب                    |
| 3NF           | 2NF + دون اعتماديات متعدية بين الخصائص غير المفتاحية        |
