# مخطط قاعدة البيانات

يصف مخطط قاعدة البيانات بنية قاعدة بيانات علائقية: جداولها وأعمدتها مع أنواع البيانات والمفاتيح والمراجع بين الجداول. وعلى خلاف [نموذج ER](./er-model.md)، فهو مرتبط بالنموذج العلائقي. فلا توجد العلاقات بعد الآن كعناصر مستقلة، بل يُعبَّر عنها بدلًا من ذلك عبر المفاتيح الخارجية وجداول الربط. ويُنشأ المخطط في المرحلة الدلالية من [تطوير قاعدة البيانات](./database-development-phases.md) ويُنفَّذ في المرحلة الفيزيائية بعبارات `CREATE TABLE`.

## المصطلحات {/*#terminology*/}

| المصطلح العلائقي | المصطلح الشائع     | المعنى                                                   |
| ---------------- | ------------------ | -------------------------------------------------------- |
| العلاقة (Relation) | جدول               | مجموعة من الصفوف ذات الخصائص نفسها                       |
| الصف (Tuple)     | صف، سجل            | إدخال واحد في جدول                                       |
| الخاصية (Attribute) | عمود               | خاصية يملكها كل صف في الجدول                             |
| المجال (Domain)  | نوع البيانات       | مجموعة القيم التي يمكن أن تتخذها الخاصية                 |
| مخطط العلاقة (Relation schema) | تعريف الجدول       | اسم الجدول وخصائصه                                       |
| مخطط قاعدة البيانات (Database schema) | بنية قاعدة البيانات | جميع مخططات العلاقات في قاعدة البيانات وقيودها          |

## المفاتيح {/*#keys*/}

- **المفتاح المرشح (Candidate key):** مجموعة دنيا من الخصائص تحدد كل صف بشكل فريد. ويمكن أن يكون للجدول عدة مفاتيح، مثل `CustomerID` و`Email`.
- **المفتاح الأساسي (Primary key، PK):** المفتاح المرشح المختار لتحديد الصفوف. يجب أن يكون فريدًا ويجب ألا يكون `NULL`.
- **المفتاح المركب (Composite key):** مفتاح يتكون من عدة خصائص، مثل `(OrderID, LineNumber)`.
- **المفتاح الخارجي (Foreign key، FK):** خاصية واحدة أو أكثر تشير إلى المفتاح الأساسي لجدول آخر أو للجدول نفسه. ويمكن أن يكون أيضًا جزءًا من المفتاح الأساسي، كما في جدول الربط أو جدول الكيان الضعيف.
- **المفتاح الطبيعي (Natural key):** مفتاح مأخوذ من البيانات نفسها، مثل ISBN.
- **المفتاح البديل (Surrogate key):** مفتاح اصطناعي لا معنى له خارج قاعدة البيانات، وهو عادةً رقم متزايد تلقائيًا أو UUID.

## الترميز {/*#notation*/}

### الترميز النصي {/*#textual-notation*/}

يُكتب كل جدول باسمه متبوعًا بخصائصه بين قوسين:

| العلامة                                          | المعنى                                                     |
| ------------------------------------------------ | ---------------------------------------------------------- |
| خط تحتها                                         | المفتاح الأساسي؛ وفي المفتاح المركب يُوضع خط تحت كل جزء    |
| `#` أو `↑` في البداية، وأحيانًا خط تحتي متقطع | المفتاح الخارجي                                            |
| اللاحقة `PK` أو `FK`                              | بديل نصي عادي حيث يتعذر وضع خط تحتي                        |

الخاصية التي هي مفتاح أساسي ومفتاح خارجي معًا يوضع تحتها خط وتوسم بـ `#`.

### مخطط الجداول {/*#table-diagram*/}

- **المربع:** جدول واحد، مع اسم الجدول في الترويسة والأعمدة أسفل الخط
- **`PK` و`FK`:** علامة أمام العمود؛ وتشير `PK FK` إلى عمود هو الاثنان معًا
- **الخط:** مرجع مفتاح خارجي بين جدولين
- **نهايات الخط:** الكاردينالية، إما `1` أو `N`

## التحويل من نموذج ER {/*#transformation-from-an-er-model*/}

| عنصر ER                           | مخطط قاعدة البيانات                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------- |
| نوع الكيان                        | جدول                                                                                              |
| الخاصية                           | عمود                                                                                              |
| خاصية المفتاح                     | المفتاح الأساسي                                                                                   |
| الخاصية المركبة                   | عمود لكل خاصية فرعية، مثل `Street` و`City` و`ZIP`                                                 |
| الخاصية متعددة القيم              | جدول منفصل مع مفتاح خارجي إلى المالك، مثل `PhoneNumbers (#CustomerID, Number)`         |
| الخاصية المشتقة                   | لا تُخزَّن عادةً، بل تُحسب في الاستعلام                                                           |
| علاقة 1:1                         | مفتاح خارجي مع قيد `UNIQUE` في أحد الجدولين                                                       |
| علاقة 1:N                         | مفتاح خارجي في الجدول الواقع في جانب N                                                            |
| علاقة N:M                         | جدول ربط يتكون مفتاحه الأساسي من المفاتيح الخارجية إلى الجدولين                                   |
| خاصية العلاقة                     | عمود في الجدول الحامل للمفتاح الخارجي، وفي علاقة N:M في جدول الربط                                |
| الكيان الضعيف                     | جدول يجمع مفتاحه الأساسي بين المفتاح الأساسي للمالك (وهو أيضًا مفتاح خارجي) والمفتاح الجزئي       |
| المشاركة الكلية في جانب N         | مفتاح خارجي معلن `NOT NULL`                                                                       |

علاقة N:M بين الطلاب والمقررات مع خاصية العلاقة `EnrolledOn`:

```text
Students    (StudentID, Name)
             ─────────
Courses     (CourseID, Title)
             ────────
Enrollments (#StudentID, #CourseID, EnrolledOn)
             ──────────  ─────────
```

## التكامل المرجعي {/*#referential-integrity*/}

يجب أن تطابق كل قيمة مفتاح خارجي قيمة مفتاح أساسي موجودة في الجدول المشار إليه، أو أن تكون `NULL` حيث يسمح العمود بذلك. ويرفض نظام DBMS أي إدراج أو تحديث ينتهك هذه القاعدة. أما ما يحدث عند حذف صف مُشار إليه (`ON DELETE`) أو تغيير مفتاحه الأساسي (`ON UPDATE`) فيُحدَّد لكل مفتاح خارجي:

| الخيار                   | أثر حذف الصف المُشار إليه                                               |
| ------------------------ | ----------------------------------------------------------------------- |
| `RESTRICT` / `NO ACTION` | يُرفض الحذف ما دامت هناك صفوف تشير إليه (الافتراضي)                     |
| `CASCADE`                | تُحذف الصفوف المشيرة أيضًا، مثل بنود طلب محذوف                          |
| `SET NULL`               | يُضبط المفتاح الخارجي على `NULL`؛ ويجب أن يسمح العمود بـ `NULL`          |

## مثال: إدارة الطلبات {/*#example-order-management*/}

يتحول المثال من [نموذج ER](./er-model.md) إلى ثلاثة جداول. وتتحول العلاقة 1:N `places` إلى المفتاح الخارجي `CustomerID` في `Orders`. وتجعل العلاقة المحددة للهوية `contains` العمود `OrderID` جزءًا من المفتاح الأساسي لـ `OrderItems`.

```text
Customers  (CustomerID, Name, Email)
            ──────────
Orders     (OrderID, #CustomerID, OrderDate)
            ───────
OrderItems (#OrderID, LineNumber, Quantity)
            ────────  ──────────
```

```text
┌─────────────────────┐          ┌──────────────────────┐
│ Customers           │          │ Orders               │
├─────────────────────┤          ├──────────────────────┤
│ PK     CustomerID   │1        N│ PK     OrderID       │
│        Name         ├──────────┤ FK     CustomerID    │
│        Email        │          │        OrderDate     │
└─────────────────────┘          └──────────┬───────────┘
                                            │ 1
                                            │
                                            │ N
                                 ┌──────────┴───────────┐
                                 │ OrderItems           │
                                 ├──────────────────────┤
                                 │ PK FK  OrderID       │
                                 │ PK     LineNumber    │
                                 │        Quantity      │
                                 └──────────────────────┘
```

```sql
CREATE TABLE Customers (
    CustomerID INT          PRIMARY KEY,
    Name       VARCHAR(100) NOT NULL,
    Email      VARCHAR(255) NOT NULL UNIQUE
);

CREATE TABLE Orders (
    OrderID    INT  PRIMARY KEY,
    CustomerID INT  NOT NULL,
    OrderDate  DATE NOT NULL,
    FOREIGN KEY (CustomerID) REFERENCES Customers (CustomerID)
);

CREATE TABLE OrderItems (
    OrderID    INT NOT NULL,
    LineNumber INT NOT NULL,
    Quantity   INT NOT NULL,
    PRIMARY KEY (OrderID, LineNumber),
    FOREIGN KEY (OrderID) REFERENCES Orders (OrderID) ON DELETE CASCADE
);
```

## الأخطاء الشائعة {/*#common-mistakes*/}

1. **خط دون عمود مفتاح خارجي:** لا يُنشئ الخط بين جدولين مرجعًا ما دام عمود المفتاح الخارجي غائبًا عن الجدول الواقع في جانب N.
2. **مفتاح خارجي في جانب 1:** العمود `OrderID` في `Customers` لا يستطيع حمل أكثر من طلب واحد لكل عميل.
3. **علاقة N:M دون جدول ربط:** يحمل عمود المفتاح الخارجي قيمة واحدة لكل صف، لذا فإن مفتاحًا خارجيًا في أي من الجدولين يحصر ذلك الجانب في شريك واحد.
4. **جدول ربط بمفتاح بديل فقط:** إذا لم يكن زوج المفاتيح الخارجية هو المفتاح الأساسي ولا `UNIQUE`، فيمكن للطالب نفسه التسجيل في المقرر نفسه مرتين.
5. **ترميز ER في المخطط:** المعينات والأشكال البيضاوية للخصائص وأسماء العلاقات تنتمي إلى مخطط ER. أما المخطط العلائقي فيعرض الجداول وعلامتي `PK` و`FK` والمراجع.
6. **كلمات محجوزة كأسماء جداول:** `ORDER` و`GROUP` كلمتان محجوزتان في SQL ويجب وضعهما بين علامات اقتباس في كل عبارة أو استبدالهما عند استخدامهما كأسماء جداول.
