# DNS (نظام أسماء النطاقات)

يحلّ DNS أسماء DNS إلى عناوين IP والعكس. يتكوّن اسم DNS من جزأين: **اسم المضيف** الذي يحدد مضيفاً واحداً، و**اسم النطاق** الذي يحدد مجموعة من المضيفين في فضاء أسماء مشترك. يفصل بين الجزأين نقطة.

## التسلسل الهرمي وFQDN {/*#hierarchy-and-fqdn*/}

DNS نظام هرمي مبني من الجذر نزولاً:

- **الجذر (Root)** – قمة التسلسل الهرمي (يُكتب `.`)
- **نطاق المستوى الأعلى (TLD)** – مثل `com` و`net` و`de` و`org`
- **نطاق المستوى الثاني** – مثل `heise` في `heise.de`
- **نطاق فرعي / مضيف** – مستويات أخرى تحت نطاق المستوى الثاني، مثل `www`

عند تحديد جميع الأجزاء حتى الجذر، تنتج **FQDN** (اسم النطاق المؤهل بالكامل) الذي يجب أن يكون فريداً في الشبكة، مثل `www.heise.de`.

## المناطق (Zones) {/*#zones*/}

يتولى كل خادم DNS مسؤولية جزء محدد من فضاء الأسماء يسمى **منطقة** (مثل `heise.de`). ويحمل الخادم الذي يدير ملف المنطقة **السلطة** على تلك المنطقة.

- **المنطقة الأساسية (Primary)** – وصول بالقراءة والكتابة، وهي النسخة المعتمدة من المنطقة.
- **المنطقة الثانوية (Secondary)** – نسخة للقراءة فقط من منطقة أساسية (للتكرار أو لتوزيع الحمل). يمكنها الإجابة عن الاستعلامات لكنها لا تستطيع تحديث ملف المنطقة.

تُتبادل بيانات المنطقة بين الخوادم عبر **نقل المنطقة** (خادما DNS بلا وحدة تحكم بالنطاق) أو **تكرار المنطقة** (مناطق متكاملة مع Active Directory على وحدات التحكم بالنطاق).

بحسب الاتجاه:

- **منطقة البحث الأمامي (Forward lookup)** – تحلّ أسماء النطاقات إلى عناوين IP.
- **منطقة البحث العكسي (Reverse lookup)** – تحلّ عناوين IP إلى أسماء نطاقات.

## أنواع السجلات {/*#record-types*/}

| السجل     | الغرض                                     |
| --------- | ----------------------------------------- |
| **A**     | اسم النطاق إلى عنوان IPv4                 |
| **AAAA**  | اسم النطاق إلى عنوان IPv6                 |
| **CNAME** | اسم مستعار يشير إلى سجل مضيف آخر          |
| **SRV**   | يحلّ خدمة إلى عنوان IP                    |
| **PTR**   | بحث عكسي: من عنوان IP إلى اسم النطاق      |

## الاستعلامات التعاودية مقابل التكرارية {/*#recursive-vs-iterative-queries*/}

- **الاستعلام التعاودي (Recursive)** – يرسله العميل إلى خادم الأسماء الخاص به ويتوقع إجابة نهائية (عنوان IP). إذا كان الخادم يحتفظ بالمنطقة، يعيد **إجابة معتمدة**.
- **الاستعلام التكراري (Iterative)** – إذا لم يستطع الخادم الإجابة بنفسه، يستعلم من خوادم DNS أخرى على امتداد التسلسل الهرمي. وقد يكتفي كل منها بالإشارة إلى الخادم المسؤول التالي بدلاً من الإجابة النهائية، حتى الوصول إلى الخادم المعتمد.
- **التخزين المؤقت (Caching)** – يخزّن كل خادم مشارك النتائج في **ذاكرة DNS المؤقتة**. وتُعاد الإجابة المخزّنة مؤقتاً بوصفها **إجابة غير معتمدة**.

## مثال على الحلّ (`www.example.com`) {/*#example-resolution-wwwexamplecom*/}

1. يرسل العميل استعلاماً **تعاودياً** إلى خادم DNS المهيأ لديه.
2. هذا الخادم ليس معتمداً ولا يملك إدخالاً مخزّناً مؤقتاً، فيرسل استعلاماً **تكرارياً** إلى خادم أسماء **الجذر**.
3. يردّ خادم الجذر بعنوان خادم أسماء TLD الخاص بـ `com.`.
4. يستعلم خادم DNS من خادم أسماء `com.`.
5. يردّ خادم `com.` بعنوان خادم أسماء `example.com.`.
6. يستعلم خادم DNS من خادم أسماء `example.com.`.
7. يردّ ذلك الخادم، وهو معتمد للمنطقة، بعنوان IP الخاص بـ FQDN.
8. يعيد خادم DNS عنوان IP إلى العميل (ويخزّنه مؤقتاً).

## ملف HOSTS {/*#hosts-file*/}

في الشبكات الصغيرة جداً، يمكن لملف `HOSTS` ثابت (`C:\Windows\System32\Drivers\etc\HOSTS`) أن يربط أسماء المضيفين بعناوين IP بدلاً من DNS. ولأن Active Directory يتطلب DNS، نادراً ما يُستخدم هذا البديل اليوم.

## أوامر مفيدة (جهة العميل) {/*#useful-commands-client*/}

| الأمر                  | الغرض                          |
| ---------------------- | ------------------------------ |
| `ipconfig /displaydns` | عرض ذاكرة DNS المؤقتة المحلية  |
| `ipconfig /flushdns`   | مسح ذاكرة DNS المؤقتة المحلية  |

## قواعد التسمية لنطاقات Windows {/*#naming-rules-for-windows-domains*/}

- للشبكات الداخلية، يُستخدم نطاق فرعي من نطاق إنترنت رسمي (مثل `media.ct.de` بدلاً من `media.ct.local`).
- تُبقى الأسماء قصيرة (النطاقات 64 حرفاً كحد أقصى).
