# TCP (بروتوكول التحكم في الإرسال)

## نظرة عامة {/*#overview*/}

TCP هو بروتوكول نقل موجّه نحو الاتصال يعمل على الطبقة 4 من [نموذج OSI](./osi-model.md)، ومحدّد في RFC 9293. وهو يحوّل التسليم غير الموثوق للحزم في IP إلى تدفق بايتات موثوق ومرتّب بين تطبيقين: فكل ما يُكتب على أحد الطرفين يصل إلى الطرف الآخر كاملًا وبالترتيب الصحيح ودون تكرار، وإلا أبلغ الاتصال عن خطأ. ويُعنوَن طرف TCP بمزيج من عنوان IP ورقم المنفذ.

---

## الخصائص {/*#characteristics*/}

| الخاصية               | السلوك في TCP                                                             |
| --------------------- | ------------------------------------------------------------------------- |
| الاتصال               | موجّه نحو الاتصال، يُنشأ الاتصال قبل أول بيانات فعلية                     |
| التسليم               | موثوق، يُعاد إرسال المقاطع المفقودة                                       |
| الترتيب               | مضمون، يُعاد ترتيب المقاطع حسب رقم التسلسل قبل التسليم                    |
| التكرارات             | تُكتشف وتُهمل                                                             |
| نموذج البيانات        | تدفق بايتات متواصل، لا تُحفظ حدود الرسائل                                 |
| الاتجاه               | ثنائي الاتجاه الكامل (Full duplex)، يستطيع الطرفان الإرسال في آن واحد     |
| التحكم في التدفق      | نعم، عبر نافذة الاستقبال                                                  |
| التحكم في الازدحام    | نعم، يتكيف معدل الإرسال مع الحمل في الشبكة                                |
| حجم الترويسة          | 20 بايتًا كحد أدنى، وحتى 60 بايتًا مع الخيارات                            |
| البث / البث المتعدد   | غير ممكن، للاتصال دائمًا طرفان اثنان بالضبط                               |

يتمثل الحمل الإضافي الناتج عن هذه الضمانات في ترويسة أكبر، ورحلة ذهاب وإياب إضافية لإنشاء الاتصال، وتأخير كلما استلزم الأمر إعادة إرسال مقطع مفقود.

## ترويسة المقطع {/*#segment-header*/}

| الحقل                  | الغرض                                                                  |
| ---------------------- | ---------------------------------------------------------------------- |
| منفذ المصدر            | منفذ التطبيق المرسِل                                                   |
| منفذ الوجهة            | منفذ التطبيق المستقبِل                                                 |
| رقم التسلسل            | موضع أول بايت من بيانات هذا المقطع في تدفق البايتات                    |
| رقم الإقرار            | البايت التالي الذي يتوقع مرسل هذا المقطع استلامه                       |
| الأعلام                | بتات تحكم، انظر أدناه                                                  |
| النافذة                | عدد البايتات التي يستطيع مرسل هذا المقطع قبولها حاليًا                 |
| المجموع الاختباري      | اكتشاف الأخطاء في الترويسة والبيانات                                   |
| الخيارات               | الحد الأقصى لحجم المقطع، وتحجيم النافذة، والإقرار الانتقائي            |

### أعلام التحكم {/*#control-flags*/}

| العلم                   | المعنى                                                              |
| ----------------------- | ------------------------------------------------------------------- |
| `SYN` (مزامنة)          | يطلب اتصالًا ويزامن أرقام التسلسل                                   |
| `ACK` (إقرار)           | رقم الإقرار صالح                                                    |
| `FIN` (إنهاء)           | لن تُرسل بيانات أخرى في هذا الاتجاه                                 |
| `RST` (إعادة ضبط)       | يُجهض الاتصال فورًا دون إنهاء منظم                                  |
| `PSH` (دفع)             | يطلب من المستقبِل تمرير البيانات إلى التطبيق دون تأخير              |
| `URG` (عاجل)            | يعلّم بيانات عاجلة (متقادم عمليًا)                                  |

## إنشاء الاتصال (المصافحة الثلاثية) {/*#connection-establishment-three-way-handshake*/}

يعلن كل طرف رقم التسلسل الابتدائي الخاص به (`x` و`y` في المخطط) ويؤكد رقم الطرف الآخر بواسطة `ack = x + 1` أو `ack = y + 1`.

```text
Client                                           Server

  | ---- SYN, seq = x -------------------------> |   listening
  |                                              |
  | <--- SYN, ACK, seq = y, ack = x + 1 -------- |   connection accepted
  |                                              |
  | ---- ACK, ack = y + 1 ---------------------> |   connection established
  |                                              |
  | ==== payload ==============================> |
```

- يعلم العميل بعد المقطع الثاني، ويعلم الخادم بعد المقطع الثالث، أن الاتصال يعمل في الاتجاهين.
- تكلّف المصافحة رحلة ذهاب وإياب واحدة قبل إمكان إرسال أول بايت من البيانات.
- يُجاب على `SYN` المرسل إلى منفذ مغلق بـ `RST`، وبهذه الطريقة يميّز فحص المنافذ بين المنفذ المغلق والمنفذ المرشَّح.

## إنهاء الاتصال {/*#connection-teardown*/}

يغلق الإنهاء المنظم كل اتجاه على حدة، ولذلك يستغرق أربعة مقاطع. و`FIN` لا يعني إلا أن *هذا الطرف انتهى من الإرسال*. وقد يظل الاتجاه الآخر ينقل بيانات (إغلاق جزئي، Half-close).

```text
Client                                           Server

  | ---- FIN ----------------------------------> |
  | <--- ACK ----------------------------------- |
  | <--- FIN ----------------------------------- |
  | ---- ACK ----------------------------------> |
  |                                              |
  | (TIME_WAIT, then the connection is released) |
```

يبقى الطرف الذي يغلق أولًا في الحالة `TIME_WAIT` لفترة قصيرة، حتى لا تُحسب المقاطع المتأخرة من الاتصال القديم مقاطع تابعة لاتصال جديد على زوج المنافذ نفسه. أما `RST` فيتخطى هذا الإجراء ويُهمل كل ما لا يزال في الطريق.

## الموثوقية {/*#reliability*/}

- **أرقام التسلسل:** لكل بايت من البيانات موضع في التدفق، مما يتيح إعادة الترتيب واكتشاف التكرارات.
- **الإقرارات:** يؤكد المستقبِل البايت التالي المتوقع، وبذلك يقرّ تراكميًا بكل ما استُلم حتى الآن.
- **مهلة إعادة الإرسال:** يُعاد إرسال المقطع الذي لم يُقرّ به خلال المهلة. وتُشتق المهلة من زمن الرحلة ذهابًا وإيابًا المقيس.
- **إعادة الإرسال السريعة (Fast retransmit):** تشير عدة إقرارات مكررة للبايت نفسه إلى فقدان مقطع واحد، وتُطلق إعادة الإرسال قبل انتهاء المهلة.
- **المجموع الاختباري:** يُهمل المقطع التالف ولذلك لا يُقرّ به أبدًا. ويؤدي غياب الإقرار إلى إعادة الإرسال.
- **الإقرار الانتقائي (SACK):** خيار يتيح للمستقبِل الإبلاغ بدقة عن نطاقات البايتات التي وصلت، فلا تُعاد إلا النطاقات المفقودة.

## التحكم في التدفق {/*#flow-control*/}

يحمي التحكم في التدفق *المستقبِل* من الإغراق. يعلن كل مقطع في حقل النافذة عدد البايتات التي يستطيع مرسله تخزينها مؤقتًا حاليًا. ولا يجوز للطرف الآخر أن يكون لديه في الطريق بيانات غير مقرّ بها تتجاوز ما تسمح به هذه النافذة.

يعلن المستقبِل الذي امتلأت ذاكرته المؤقتة نافذة قدرها صفر. فيتوقف المرسل حينئذ إلى أن يعلن مقطع لاحق نافذة أكبر.

## التحكم في الازدحام {/*#congestion-control*/}

يحمي التحكم في الازدحام *الشبكة* من الإغراق، ويعمل بصورة مستقلة عن نافذة الاستقبال. وحد الإرسال الفعلي هو الأصغر بين نافذة الاستقبال ونافذة الازدحام.

| المرحلة              | السلوك                                                                    |
| -------------------- | ------------------------------------------------------------------------- |
| البدء البطيء (Slow start) | تبدأ نافذة الازدحام صغيرة وتنمو أُسّيًا                              |
| تجنب الازدحام        | فوق عتبة معينة تنمو النافذة خطيًا فقط                                     |
| اكتشاف فقدان         | تُخفَّض النافذة لأن فقدان الحزم يدل على ازدحام                            |
| الاسترداد السريع     | بعد إعادة إرسال سريعة يستمر النقل بنافذة مخفَّضة                          |
