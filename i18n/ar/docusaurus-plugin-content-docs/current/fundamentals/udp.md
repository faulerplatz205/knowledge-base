# UDP (User Datagram Protocol)

## نظرة عامة {/*#overview*/}

UDP بروتوكول نقل بلا اتصال يعمل على الطبقة الرابعة من [نموذج OSI](./osi-model.md)، وهو محدد في RFC 768. لا يضيف إلى تسليم الحزم في IP إلا القليل: أرقام المنافذ وحقل الطول ومجموعًا اختباريًا. يُعنوَن كل datagram ويُوجَّه بصورة مستقلة، دون إنشاء اتصال مسبق ودون حالة مشتركة ودون إقرار بالاستلام أو إعادة إرسال. يُرسَل الـ datagram فإما أن يصل أو لا يصل، ولا يُبلَّغ المرسل بأيٍّ من الحالتين. تُحدَّد نقطة نهاية UDP بمزيج من عنوان IP ورقم المنفذ.

---

## الخصائص {/*#characteristics*/}

| الخاصية               | السلوك في UDP                                                          |
| --------------------- | ---------------------------------------------------------------------- |
| الاتصال               | بلا اتصال، يمكن إرسال datagram فورًا                                   |
| التسليم               | غير موثوق، لا تُكتشف الـ datagrams المفقودة ولا يُعاد إرسالها          |
| الترتيب               | غير مضمون، قد تصل الـ datagrams بترتيب مختلف                           |
| التكرار               | ممكن، ويُترك اكتشافه للتطبيق                                           |
| نموذج البيانات        | موجَّه بالرسائل، كل عملية إرسال تنتج datagram واحدًا بالضبط            |
| الاتجاه               | يمكن لكلا الطرفين الإرسال في أي وقت، وكل datagram قائم بذاته           |
| التحكم في التدفق      | لا يوجد                                                                |
| التحكم في الازدحام    | لا يوجد، يمكن للمرسل إغراق الشبكة                                      |
| حجم الترويسة          | 8 بايتات، ثابتة                                                        |
| البث / البث المتعدد   | مدعومان، يمكن لـ datagram واحد مخاطبة عدة مستقبِلين                    |

مقابل الكلفة الإضافية الصغيرة، لا يقدم UDP أي ضمانات.

---

## ترويسة الـ Datagram {/*#datagram-header*/}

تتكون الترويسة من أربعة حقول، طول كل منها بايتان:

| الحقل            | الغرض                                                                                                      |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| منفذ المصدر      | منفذ التطبيق المرسل، ويمكن أن يكون 0 إذا لم يكن الرد متوقعًا                                              |
| منفذ الوجهة      | منفذ التطبيق المستقبِل                                                                                     |
| الطول            | طول الترويسة والحمولة بالبايت                                                                              |
| المجموع الاختباري | اكتشاف الأخطاء في الترويسة والحمولة وأجزاء من ترويسة IP، اختياري في IPv4 وإلزامي في IPv6                  |

يُهمَل الـ datagram التالف بصمت.

---

## التواصل دون اتصال {/*#communication-without-a-connection*/}

بخلاف TCP الذي لا تُرسَل فيه الحمولة إلا بعد المصافحة الثلاثية (three-way handshake)، يحمل أول datagram حمولة منذ البداية. ولا تبقى أي حالة اتصال لدى أي من الطرفين بعد آخر datagram.

```text
Client                                           Server

  | ---- datagram (query) ---------------------> |   application reads it
  |                                              |
  | <--- datagram (answer) --------------------- |
  |                                              |
  | ---- datagram (query) --------X              |   lost, nobody is informed
  |                                              |
  |  (timeout in the application)                |
  |                                              |
  | ---- datagram (query, repeated) -----------> |
```

- لا يعلم العميل أن استعلامه وصل إلا من الرد. وغياب الرد قد يعني ضياع الاستعلام أو ضياع الرد أو عدم توفر الخادم.
- لا يُتحقَّق من عنوان مرسل الـ datagram بمصافحة. لذلك تكون الطلبات المنتحلة ممكنة، وهو ما تستغله هجمات التضخيم عبر DNS أو NTP.
- يُرَدّ على datagram مرسَل إلى منفذ مغلق برسالة ICMP من نوع *port unreachable*. أما المنفذ المفتوح والمنفذ المصفّى فيبقيان عادةً صامتين كلاهما، ولذلك لا يستطيع فحص منافذ UDP في أحيان كثيرة التمييز بينهما.

---

## لا تحكم في التدفق ولا في الازدحام {/*#no-flow-or-congestion-control*/}

يمرر UDP الـ datagrams بالسرعة التي يرسلها بها التطبيق. وإذا امتلأت ذاكرة الاستقبال المؤقتة، تُهمَل الـ datagrams اللاحقة دون إشعار. وإذا كانت الشبكة محمَّلة فوق طاقتها، تضيع الـ datagrams في طوابير الموجِّهات.

على التطبيق الذي يرسل كميات كبيرة عبر UDP أن يحدّ من معدله بنفسه (RFC 8085). وإلا فإنه يزاحم حركة TCP، لأن TCP يخفض معدله عند فقدان الحزم بينما يستولي UDP على السعة المتحررة.

## حالات الاستخدام النموذجية {/*#typical-use-cases*/}

### UDP مقابل TCP {/*#udp-vs-tcp*/}

|         | UDP                                                                                        | [TCP](./tcp.md)                                                                    |
| ------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| المعيار | الحزمة المتأخرة عديمة القيمة، أو أن كلفة الاتصال تفوق حجم الحمولة                          | الاكتمال أهم من زمن الاستجابة                                                      |
| أمثلة   | الصوت والفيديو المباشران، الألعاب عبر الإنترنت، الاستعلامات القصيرة، القياس عن بُعد، الاكتشاف عبر البث المتعدد | نقل الملفات، صفحات الويب، البريد الإلكتروني، الإدارة عن بُعد، اتصالات قواعد البيانات |

### منافذ UDP المعروفة {/*#well-known-udp-ports*/}

| المنفذ   | الخدمة        | سبب استخدام UDP                                                             |
| -------- | ------------- | --------------------------------------------------------------------------- |
| 53       | DNS           | استعلام قصير واحد ورد قصير واحد، وإعادة المحاولة أرخص من إنشاء اتصال        |
| 67/68    | DHCP          | العميل لا يملك عنوان IP بعد ويعتمد على البث                            |
| 69       | TFTP          | بسيط عن قصد، ويُستخدم في بيئات الإقلاع                                      |
| 123      | NTP           | الطابع الزمني المعاد إرساله يكون قد أصبح قديمًا                             |
| 161/162  | SNMP          | رسائل حالة صغيرة كثيرة، وفقدان رسالة واحدة منها مقبول                       |
| 443      | QUIC / HTTP/3 | تُنفَّذ الموثوقية داخل QUIC فوق UDP                                         |
| 500/4500 | IPsec (IKE)   | تبادل المفاتيح وعبور NAT                                                    |
| 5060     | SIP           | الإشارات الخاصة بالاتصالات الصوتية                                          |

يعمل البروتوكولان جنبًا إلى جنب في DNS: تُرسَل الاستعلامات والردود القصيرة عبر UDP، بينما تستخدم عمليات نقل المناطق (zone transfers) والردود التي تتجاوز حد حجم UDP بروتوكول TCP. وهذا الحد هو 512 بايت، أو حجم الذاكرة المؤقتة الذي يعلنه العميل عبر EDNS(0).
