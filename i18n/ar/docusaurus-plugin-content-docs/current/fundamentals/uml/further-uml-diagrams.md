# مخططات UML الأخرى

## نظرة عامة {/*#overview*/}

يعرّف UML 2.5 أربعة عشر نوعًا من المخططات. وتُعرض هنا الأنواع السبعة التي لا تغطيها مداخل مستقلة.

| المخطط                       | الفئة  | السؤال الجوهري                                                             |
| ---------------------------- | ------ | -------------------------------------------------------------------------- |
| مخطط الكائنات                | بنية   | ما النسخ الملموسة الموجودة في لحظة واحدة وكيف ترتبط؟                       |
| مخطط الحزم                   | بنية   | كيف يُقسَّم النموذج إلى وحدات وأي وحدة تعتمد على أي وحدة؟                  |
| مخطط الاتصال                 | سلوك   | أي الكائنات تتبادل الرسائل، وعلى امتداد أي روابط؟                          |
| مخطط التوقيت                 | سلوك   | في أي حالة يكون العنصر عند أي نقطة على محور الزمن؟                         |
| مخطط نظرة التفاعل            | سلوك   | بأي ترتيب تُنفَّذ تفاعلات كاملة؟                                           |
| مخطط البنية المركبة          | بنية   | كيف يُبنى المصنِّف (classifier) داخليًا وعبر أي منافذ يتحدث؟               |
| مخطط Profile                 | بنية   | كيف يُوسَّع UML نفسه لمجال أو منصة؟                                        |

---

## مخطط الكائنات {/*#object-diagram*/}

لقطة لنظام ما في لحظة معينة: النسخ الموجودة والروابط بينها. ترميزه هو ترميز [مخطط الأصناف](./class-diagram.md) ولكن على مستوى النسخ.

عناصر الترميز الأساسية:

- **مواصفة النسخة:** مستطيل باسم مسطَّر بالصيغة `name : Class`؛ ويمكن حذف الاسم أو الصنف (`o7 : Order`، `: Order`، `o7`)
- **قيم السمات:** في القسم السفلي بالصيغة `attribute = value`
- **الرابط (Link):** خط متصل بسيط بين نسختين، وهو النظير على مستوى النسخ للارتباط؛ دون تعددية، لأن الرابط يصل دائمًا نسختين بالضبط

لا يمكن للنص العادي إظهار التسطير، وفي الترميز الفعلي يُسطَّر الاسمان `m1 : Customer` و`o7 : Order`:

```text
 ┌────────────────────┐              ┌────────────────────┐
 │ m1 : Customer      │   places     │ o7 : Order         │
 ├────────────────────┤──────────────├────────────────────┤
 │ name = "Meier"     │              │ total = 249.90     │
 │ city = "Kiel"      │              │ status = "paid"    │
 └────────────────────┘              └────────────────────┘
```

الاستخدام النموذجي: شرح مخطط أصناف معقد بمثال عملي، ومناقشة تشكيلة بيانات ملموسة، وتوثيق بيانات الاختبار أو الحالة التي يقع فيها عيب ما.

## مخطط الحزم {/*#package-diagram*/}

يبيّن مخطط الحزم كيف يُقطَّع النموذج إلى وحدات وأي وحدة تعتمد على أي وحدة. ولا تحمل الحزم سلوكًا خاصًا بها.

عناصر الترميز الأساسية:

- **الحزمة:** مستطيل بلسان؛ ويُكتب التداخل رسوميًا أو بالصيغة `shop::service`
- **الاعتمادية:** سهم متقطع يشير من الحزمة المستخدِمة إلى الحزمة المستخدَمة
- **`«import»`:** يجعل العناصر العامة في الحزمة الهدف قابلة للاستخدام دون تأهيل
- **`«access»`:** العلاقة نفسها ولكن دون تمرير الأسماء المستوردة إلى أبعد من ذلك
- **`«merge»`:** ينسخ مفاهيميًا محتوى الحزمة الهدف إلى الحزمة المصدر ويدمجه معها
- **التطبيق في طبقات (Layering):** حزم مرتبة فوق بعضها مع اتجاه كل الاعتماديات في اتجاه واحد

```text
┌──────┐
│ shop │
├──────┴──────────────────┐
│                         │
│   ┌─────────┐           │
│   │ ui      │           │
│   ├─────────┴───────┐   │
│   │                 │   │
│   └────────┬────────┘   │
│            ┆ «import»   │
│            ▼            │
│   ┌─────────┐           │
│   │ service │           │
│   ├─────────┴───────┐   │
│   │                 │   │
│   └────────┬────────┘   │
│            ┆ «import»   │
│            ▼            │
│   ┌─────────────┐       │
│   │ persistence │       │
│   ├─────────────┴───┐   │
│   │                 │   │
│   └─────────────────┘   │
│                         │
└─────────────────────────┘
```

الاستخدام النموذجي: المعماريات الطبقية، وتقطيع نظام إلى وحدات، وإظهار الاعتماديات الدورية قبل أن تصل إلى الشيفرة.

الحدّ الفاصل: يصف [مخطط المكونات](./component-diagram.md) لبنات قابلة للاستبدال تقدم واجهات وتطلبها أثناء التشغيل، أما مخطط الحزم فيُنظّم عناصر النموذج والمصدر وقت التصميم فقط.

## مخطط الاتصال {/*#communication-diagram*/}

يبيّن مخطط الاتصال أي الكائنات تتبادل الرسائل وعلى امتداد أي روابط تفعل ذلك. تُوضع الكائنات بحرية، ويُستخلص ترتيب الرسائل من ترقيمها.

عناصر الترميز الأساسية:

- **الكائن:** مستطيل بـ `name : Class` مسطَّر، كما في مخطط الكائنات
- **الرابط:** خط متصل بين كائنين
- **الرسالة:** سهم صغير مرسوم بجوار الرابط، موسوم بـ `1: placeOrder()`
- **أرقام التسلسل الهرمية:** `1` و`1.1` و`1.2`، حيث يُرسَل `1.1` و`1.2` الواحد بعد الآخر ضمن معالجة الرسالة `1`
- **علامة التكرار والحراس:** `*` و`[condition]` كجزء من وسم الرسالة

```text
  ┌──────────┐   1: placeOrder() ►  ┌─────────────┐
  │ : Client │──────────────────────│ : OrderCtrl │
  └──────────┘   ◄ 1.3: confirm()   └─────────────┘
                                           │
                                           │ ▼ 1.1: checkStock()
                                           │ ▼ 1.2: reserve()
                                           │
                                    ┌─────────────┐
                                    │ : Warehouse │
                                    └─────────────┘
```

الاستخدام النموذجي: إظهار الكائنات التي تتواصل فيما بينها، وتقدير اقتران تصميم ما، والتفاعلات الصغيرة التي تكون البنية فيها أهم من الترتيب الدقيق.

الحدّ الفاصل: يعرض [مخطط التسلسل](./sequence-diagram.md) التفاعل نفسه على محور زمني صريح من الأعلى إلى الأسفل ويقدم أجزاء مركبة (combined fragments) مثل `alt` و`opt` و`loop`. ويمكن نقل الكائنات والرسائل وترتيبها من مخطط إلى آخر، أما الأجزاء المركبة فلا نظير لها في مخطط الاتصال. وتُقرأ البدائل والحلقات أسهل في مخطط التسلسل، وتُرى شبكة الروابط أسهل في مخطط الاتصال.

## مخطط التوقيت {/*#timing-diagram*/}

يبيّن مخطط التوقيت كيف تتطور حالة عنصر أو أكثر أو قيمته على محور زمني صريح.

عناصر الترميز الأساسية:

- **محور الزمن:** أفقي، مع مقياس، ومسار واحد لكل خط حياة
- **خط حياة الحالة:** خط متدرج بين الحالات المدرجة على المحور الرأسي
- **خط حياة القيمة:** شكل شريط مدمج يشير فيه التقاطع إلى تغير القيمة
- **المدة وقيد الزمن:** `{d..3*d}` و`{t = 0}`
- **الأحداث والرسائل:** أسهم بين المسارات
- **علامات التدريج:** وحدات المقياس الزمني

```text
 : Motor
           │
   active  │         ┌──────────────┐
           │         │              │
   idle    ├─────────┘              └──────────
           │         ├── {20..40} ──┤
           └────┬────┬────┬────┬────┬────┬────┬───► t
           0    10   20   30   40   50   60   70  ms
```

الاستخدام النموذجي: أنظمة الزمن الحقيقي والأنظمة المدمجة، وبروتوكولات الناقل والشبكات، والتحكم المرتبط بالعتاد، ومتطلبات زمن الاستجابة والمهل الزمنية وأدنى أزمنة الثبات.

الحدّ الفاصل: يحدد [مخطط آلة الحالة](./state-machine-diagram.md) الحالات والانتقالات الممكنة دون محور زمني. ويبيّن مخطط التوقيت متى يكون العنصر في أي من هذه الحالات.

## مخطط نظرة التفاعل {/*#interaction-overview-diagram*/}

يرتب مخطط نظرة التفاعل عدة مخططات تسلسل أو اتصال أو توقيت في تدفق تحكم واحد، وكل عقدة فيه تفاعل كامل.

عناصر الترميز الأساسية:

- **الإطار:** مع الترويسة `sd <name>`
- **استخدام التفاعل:** مستطيل بالكلمة المفتاحية `ref` واسم مخطط تفاعل موجود
- **التفاعل المضمَّن:** مخطط تسلسل صغير مضمَّن مباشرةً كعقدة
- **عناصر التحكم:** كل ما في مخطط النشاط، أي العقدة الابتدائية والقرار والدمج وfork وjoin وعقدة النهاية

```text
 ┌ sd Checkout ─────────────────────────────┐
 │                  ●                       │
 │                  │                       │
 │                  ▼                       │
 │          ┌───────────────┐               │
 │          │ ref  Login    │               │
 │          └───────────────┘               │
 │                  │                       │
 │             ╱─────────╲                  │
 │            ╱  paid ?   ╲                 │
 │            ╲           ╱                 │
 │             ╲─────────╱                  │
 │       [yes]  │       │  [no]             │
 │     ┌────────┘       └────────┐          │
 │     ▼                         ▼          │
 │ ┌───────────────┐   ┌───────────────┐    │
 │ │ ref  Ship     │   │ ref  Cancel   │    │
 │ └───────────────┘   └───────────────┘    │
 │     │                         │          │
 │     └────────┐       ┌────────┘          │
 │              ▼       ▼                   │
 │                  ◉                       │
 └──────────────────────────────────────────┘
```

الاستخدام النموذجي: النظرة الشاملة إلى بروتوكول أو إلى معاملة أعمال طويلة الأمد تتألف من تفاعلات فردية كثيرة.

الحدّ الفاصل: يستخدم [مخطط النشاط](./activity-diagram.md) عناصر التحكم نفسها، لكن عقده أفعال مفردة. ومخطط نظرة التفاعل بديل كذلك عن مخطط تسلسل واحد ضخم محشو بأجزاء `alt` و`loop` متداخلة.

## مخطط البنية المركبة {/*#composite-structure-diagram*/}

ينظر مخطط البنية المركبة داخل مصنِّف واحد: من أي أجزاء يتألف، وكيف ترتبط هذه الأجزاء، وعبر أي نقاط تفاعل يتصل بمحيطه.

عناصر الترميز الأساسية:

- **الجزء (Part):** مستطيل داخل إطار المصنِّف، يُكتب بالصيغة `role : Type` مع تعددية اختيارية، مثل `wheels : Wheel [4]`
- **المنفذ (Port):** مربع صغير على حدّ المصنِّف، نقطة تفاعل مسماة ومنمَّطة
- **الواجهات:** الواجهة المقدَّمة بشكل lollipop `─○`، والواجهة المطلوبة بشكل socket `─(`
- **الموصِّلات:** موصِّل assembly بين جزأين، وموصِّل delegation بين جزء ومنفذ
- **التعاون (Collaboration):** شكل بيضاوي متقطع بأدوار مسماة، يصف نمط تعاون مستقلًا عن الأصناف الملموسة

```text
 ┌ Car ──────────────────────────────────────┐
 │                                           │
 │ ┌────────────┐        ┌──────────────┐    │
 │ │ e : Engine │────────│ g : Gearbox  │────┼──□───○ Drive
 │ └────────────┘        └──────────────┘    │
 │                                           │
 └───────────────────────────────────────────┘
```

الاستخدام النموذجي: المعمارية الداخلية لمكوِّن، وربط الأجزاء في تصميم الأنظمة والأنظمة المدمجة، ووصف نمط تصميم بوصفه تعاونًا بين أدوار.

الحدّ الفاصل: يقول [مخطط الأصناف](./class-diagram.md) أي الأصناف مرتبطة بصورة عامة، أما مخطط البنية المركبة فيقول كيف ترتبط النسخ داخل كل واحد في دور محدد. ويستخدم [مخطط المكونات](./component-diagram.md) ترميز lollipop وsocket نفسه، لكن على مستوى اللبنات القابلة للنشر في النظام ككل وليس داخل مصنِّف واحد.

## مخطط Profile {/*#profile-diagram*/}

يوسّع مخطط Profile لغة UML نفسها لمجال معين أو منصة مستهدفة.

عناصر الترميز الأساسية:

- **Profile:** حزمة بالكلمة المفتاحية `«profile»`
- **Stereotype:** مستطيل بالكلمة المفتاحية `«stereotype»`، يوسّع metaclass موجودًا؛ وأي اسم بين guillemets ليس كلمة مفتاحية معرَّفة مسبقًا في UML هو stereotype معرَّف في profile ما
- **الامتداد (Extension):** خط متصل برأس سهم ممتلئ من الـ stereotype إلى الـ metaclass، مثل `«metaclass» Class`
- **القيمة الموسومة (Tagged value):** سمة للـ stereotype، مثل `table : String`، تُملأ عند العنصر الحامل للـ stereotype
- **القيد (Constraint):** قاعدة بين أقواس معقوفة، تُكتب بـ OCL أو بنص حر
- **التطبيق:** اعتمادية `«apply»` من حزمة إلى الـ profile؛ ويمكن لعناصرها حينئذ أن تحمل `«entity»` و`«controller»` وهكذا

```text
 ┌ «profile» Persistence ─────────────────────┐
 │                                            │
 │  ┌─────────────────┐     ┌───────────────┐ │
 │  │ «stereotype»    │────►│ «metaclass»   │ │
 │  │ Entity          │     │ Class         │ │
 │  ├─────────────────┤     └───────────────┘ │
 │  │ table : String  │                       │
 │  └─────────────────┘                       │
 └────────────────────────────────────────────┘
```

العلاقة بالنموذج الفوقي (metamodel): يوصف UML بمعمارية من أربع طبقات. تحوي `M0` الكائنات الحقيقية، و`M1` النموذج، و`M2` النموذج الفوقي لـ UML الذي يحدد ما الصنف وما الارتباط، و`M3` لغة MOF (Meta Object Facility) التي يُكتب بها النموذج الفوقي نفسه. والـ profile آلية التوسيع الخفيفة في UML: فهو يوسّع الطبقة `M2` دون تعديلها، ولذلك يظل تبادل النماذج المزودة بـ profile ممكنًا بين الأدوات. أما التوسيع الثقيل فيغيّر النموذج الفوقي مباشرةً وينشئ بذلك لغة جديدة.

الاستخدام النموذجي: لغات النمذجة الخاصة بمجال معين مثل SysML أو MARTE، وربط نموذج بمنصة مثل JPA أو EJB، واصطلاحات النمذجة على مستوى الشركة.
