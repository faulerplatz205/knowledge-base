# HTTPステータスコード

## 概要 {/*#overview*/}

HTTPステータスコードは、クライアントのリクエストに対する応答としてサーバーが返す3桁の数字である。リクエストが成功したか、リダイレクトされたか、エラーになったかを示す。ステータスコードは最初の桁によって5つのクラスに分類される。

## 1xx - 情報 {/*#1xx---informational*/}

リクエストは受信され、サーバーは処理を続行している。

| コード | 名前                | 説明                                                                                      |
| ------ | ------------------- | ----------------------------------------------------------------------------------------- |
| 100    | Continue            | サーバーがリクエストヘッダーを受信し、クライアントはボディの送信に進んでよい。            |
| 101    | Switching Protocols | サーバーがクライアントから要求されたプロトコルに切り替える(例: WebSocketへのアップグレード)。 |

### 例 {/*#examples*/}

- **100 Continue**: クライアントが`Expect: 100-continue`ヘッダー付きで大きなファイルのアップロードを送信する。サーバーは`100`で応答し、クライアントがボディの送信に進んでよいことを知らせる。
- **101 Switching Protocols**: クライアントが`Upgrade: websocket`付きでHTTPリクエストを送信する。サーバーは`101`で応答し、WebSocketプロトコルに切り替える。

## 2xx - 成功 {/*#2xx---success*/}

リクエストは正常に受信され、理解され、受理された。

| コード | 名前       | 説明                                                                                  |
| ------ | ---------- | ------------------------------------------------------------------------------------- |
| 200    | OK         | リクエストが成功した。レスポンスボディには要求されたデータが含まれる。                |
| 201    | Created    | 新しいリソースが正常に作成された(通常は`POST`の後)。                                  |
| 204    | No Content | リクエストは成功したが、返すコンテンツがない(通常は`DELETE`の後)。                      |

### 例 {/*#examples-1*/}

- **200 OK**: `GET /api/users/42` => サーバーはユーザーオブジェクトをJSONとして返す。
- **201 Created**: リクエストボディ付きの`POST /api/users` => サーバーはユーザーを作成し、`Location`ヘッダー付きで新しいリソースを返す。
- **204 No Content**: `DELETE /api/users/42` => サーバーはユーザーを削除し、空のレスポンスを返す。

## 3xx - リダイレクト {/*#3xx---redirection*/}

リクエストを完了するために、クライアントが追加のアクションを取る必要がある。

| コード | 名前               | 説明                                                                    |
| ------ | ------------------ | ----------------------------------------------------------------------- |
| 301    | Moved Permanently  | リソースが新しいURLに恒久的に移動された。                               |
| 302    | Found              | リソースが一時的に別のURLに置かれている。                               |
| 304    | Not Modified       | 前回のリクエスト以降、リソースは変更されていない(キャッシュに使用)。    |
| 307    | Temporary Redirect | 302と同様だが、リダイレクト時にリクエストメソッドを変更してはならない。 |
| 308    | Permanent Redirect | 301と同様だが、リダイレクト時にリクエストメソッドを変更してはならない。 |

### 例 {/*#examples-2*/}

- **301 Moved Permanently**: `GET /old-page` => サーバーは`301`と`Location: /new-page`で応答する。検索エンジンはそれに応じてインデックスを更新する。
- **302 Found**: `GET /promo` => サーバーは一時的に`/current-sale`へリダイレクトする。元のURLは今後のリクエストでも有効なままである。
- **304 Not Modified**: クライアントは、キャッシュされたETagを含む`If-None-Match`ヘッダー付きで`GET /style.css`を送信する。サーバーはリソースが変更されていないことを確認し、ボディなしで`304`を返す。
- **307 Temporary Redirect**: `POST /api/submit` => サーバーは一時的に`/api/v2/submit`へリダイレクトする。クライアントは`POST`リクエストを再送しなければならない(`GET`に変更してはならない)。
- **308 Permanent Redirect**: `POST /api/old-endpoint` => サーバーは恒久的に`/api/new-endpoint`へリダイレクトする。クライアントは新しいURLへ`POST`リクエストを再送しなければならない。

## 4xx - クライアントエラー {/*#4xx---client-error*/}

リクエストにクライアント側のエラーがある。

| コード | 名前                   | 説明                                                                                                                  |
| ------ | ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 400    | Bad Request            | 構文の誤りまたは不正な入力のため、サーバーがリクエストを処理できない。                                                |
| 401    | Unauthorized           | 認証が必要だが、提供されていないか無効である。                                                                        |
| 403    | Forbidden              | サーバーはリクエストを理解したが、認可を拒否する。                                                                    |
| 404    | Not Found              | 要求されたリソースがサーバー上に存在しない。                                                                          |
| 405    | Method Not Allowed     | 使用されたHTTPメソッドが、要求されたリソースに対してサポートされていない。                                            |
| 408    | Request Timeout        | クライアントがリクエストの送信を完了するのをサーバーが待機している間にタイムアウトした。                              |
| 409    | Conflict               | リクエストがリソースの現在の状態と競合している(例: 重複するエントリ)。                                                |
| 413    | Content Too Large      | リクエストボディがサーバーのサイズ上限を超えている。                                                                  |
| 415    | Unsupported Media Type | サーバーがリクエストボディのメディアタイプをサポートしていない。                                                      |
| 418    | I'm a Teapot           | サーバーはティーポットであるため、コーヒーの抽出を拒否する([RFC 2324](https://datatracker.ietf.org/doc/html/rfc2324))。 |
| 422    | Unprocessable Content  | リクエストは構文的には正しいが、意味的に無効である(例: バリデーションエラー)。                                        |
| 429    | Too Many Requests      | クライアントが一定期間内に多すぎるリクエストを送信した(レート制限)。                                                  |

### 例 {/*#examples-3*/}

- **400 Bad Request**: `{ name: }`付きの`POST /api/users` => JSONボディの形式が不正で、解析できない。
- **401 Unauthorized**: `Authorization`ヘッダーなしの`GET /api/profile` => サーバーは認証を要求する。
- **403 Forbidden**: 管理者でないユーザーの有効なトークン付きの`DELETE /api/users/1` => ユーザーは認証されているが、権限がない。
- **404 Not Found**: `GET /api/users/99999` => そのIDのユーザーは存在しない。
- **405 Method Not Allowed**: `DELETE /api/login` => `/api/login`エンドポイントは`POST`のみをサポートする。
- **408 Request Timeout**: クライアントが接続を開き、大きなリクエストボディの送信を開始したが、転送の途中で止まる。サーバーはタイムアウト後に接続を閉じる。
- **409 Conflict**: `{ "email": "a@b.com" }`付きの`POST /api/users` => そのメールアドレスのユーザーがすでに存在する。
- **413 Content Too Large**: 500 MBのファイルを伴う`POST /api/upload` => サーバーのアップロード上限は50 MBである。
- **415 Unsupported Media Type**: `Content-Type: text/xml`付きの`POST /api/data` => エンドポイントは`application/json`のみを受け付ける。
- **418 I'm a Teapot**: `BREW /coffee` => ティーポットは丁寧に断る。
- **422 Unprocessable Content**: `{ "email": "not-an-email" }`付きの`POST /api/users` => JSONは有効だが、メールフィールドがバリデーションに失敗する。
- **429 Too Many Requests**: クライアントが`/api/search`に毎分1000件のリクエストを送信する => サーバーはレート制限を適用し、`429`と`Retry-After`ヘッダーで応答する。

## 5xx - サーバーエラー {/*#5xx---server-error*/}

サーバーが有効なリクエストを処理できなかった。

| コード | 名前                  | 説明                                                                                                 |
| ------ | --------------------- | ---------------------------------------------------------------------------------------------------- |
| 500    | Internal Server Error | サーバー上で予期しないエラーが発生した。                                                             |
| 502    | Bad Gateway           | ゲートウェイまたはプロキシとして動作しているサーバーが、上流サーバーから無効なレスポンスを受け取った。 |
| 503    | Service Unavailable   | サーバーが一時的にリクエストを処理できない(例: 過負荷またはメンテナンス中)。                         |
| 504    | Gateway Timeout       | ゲートウェイまたはプロキシとして動作しているサーバーが、上流サーバーから時間内にレスポンスを受け取れなかった。 |

### 例 {/*#examples-4*/}

- **500 Internal Server Error**: `GET /api/reports` => サーバーコードで未処理の例外が発生する(例: ヌルポインタ、ゼロ除算)。
- **502 Bad Gateway**: リバースプロキシ(例: Nginx)がリクエストをバックエンドに転送するが、バックエンドが破損した、または不完全なレスポンスを返す。
- **503 Service Unavailable**: サーバーが計画メンテナンス中であるか、過負荷のために一時的にリクエストを処理できない。多くの場合、`Retry-After`ヘッダーが含まれる。
- **504 Gateway Timeout**: リバースプロキシがリクエストをバックエンドに転送するが、バックエンドの応答に時間がかかりすぎる(例: 低速なデータベースクエリがプロキシのタイムアウトを超える)。
