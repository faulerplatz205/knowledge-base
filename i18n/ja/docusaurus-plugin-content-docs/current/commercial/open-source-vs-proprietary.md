# オープンソースとプロプライエタリソフトウェア

## 定義 {/*#definitions*/}

**オープンソースソフトウェア**: ソースコードが公開されている。ライセンス(例: MIT、GPL、Apache)の条件の範囲内で、誰でもソフトウェアを検査、変更、配布できる。

**プロプライエタリソフトウェア**: ソースコードはベンダーが非公開としている。利用はライセンス契約によって規定され、変更と再配布は通常禁止されている。

## オープンソース {/*#open-source*/}

### 利点 {/*#advantages*/}

- **無償で利用可能**: 多くの場合、ライセンス料なしで利用できる
- **透明性**: コードを監査して、セキュリティ上の脆弱性やバグを確認できる
- **コミュニティ主導**: 元の開発者に完全に依存することなく、コミュニティによって発展させることができる
- **柔軟性**: 個人が自分のニーズに合わせてカスタマイズできる

### 欠点 {/*#disadvantages*/}

- **サポート**: コミュニティのサポートは当てにならない場合があり、小規模なコミュニティでは存在しないか、追加の支払いが必要となる
- **使いやすさ**: 商用の代替製品に比べて、インターフェースの完成度が低いことが多い
- **セキュリティリスク**: 公開されているコードは攻撃者にも解析されうる
- **ライセンスの複雑さ**: オープンソースライセンスによっては制限が課される(例: コピーレフト)
- **保守の負担**: 自己ホスティングには、社内の専門知識と時間が必要となる

### 例 {/*#examples*/}

- Firefox
- Linux
- React
- VSCode

## プロプライエタリソフトウェア {/*#proprietary-software*/}

### 利点 {/*#advantages-1*/}

- **専門的なサポート**: SLAを伴う、ベンダー専任のサポート
- **完成度とUX**: 通常、ユーザー体験とドキュメントへの投資が大きい
- **信頼性の高い更新と保守**: 十分にテストされた更新とパッチが提供元から提供され、更新の実施に社内の専門知識を必要としない。
- **統合**: 同一メーカーの他のソフトウェアとの互換性が高いことが多い

### 欠点 {/*#disadvantages-1*/}

- **コスト**: ライセンス料は、特に大規模な導入では高額になりうる
- **ベンダーロックイン**: ベンダーのロードマップと価格設定への依存
- **透明性の欠如**: セキュリティや品質のためにソースコードを監査できない
- **制約**: ベンダーが許可する範囲を超えたカスタマイズや拡張が限られる

### 例 {/*#examples-1*/}

- Microsoft Office
- Windows、iOS、MacOS
- Discord
- Google Chrome

## 比較 {/*#comparison*/}

|                       | オープンソース | プロプライエタリ |
| --------------------- | ---------------- | --------------- |
| ソースコード | 公開 | 非公開 |
| コスト | 通常は無償 | ライセンス料 |
| サポート | コミュニティ / 有償 | ベンダー提供 |
| カスタマイズ性 | 高い | 低い |
| ベンダーロックイン | 低い | 高い |
| セキュリティの透明性 | 高い | 低い |
