# サービスリクエストの分類

## 概要 {/*#overview*/}

受信するすべてのメッセージは、IT組織の中心的な窓口である**シングルポイントオブコンタクト(SPOC)**、別名**ヘルプデスク**に届く。ヘルプデスクは、ローカル、分散型、または仮想型(複数のヘルプデスクが外部からは1つに見える形)で組織できる。この最初の支援レベルは**ファーストレベルサポート**とも呼ばれる。

受信するメッセージは、基本的に3つの種類に分けられる。

## 3つの種類 {/*#the-three-types*/}

### [イベント](./event-management.md) {/*#event*/}

システムの状態に関する**自動的に生成されるメッセージ**。こうした受信メッセージは**イベント**とも呼ばれ、ユーザーからの直接の報告を必要としない。監視システムによって生成される。

### サービスリクエスト {/*#service-request*/}

**ユーザーからの正式な依頼**またはサポート依頼であり、**サービスリクエスト**とも呼ばれる。一般的な質問、パスワードの失念、プログラムの使い方の案内、新しい機器の依頼などが含まれる。

### [インシデント](./incident-management.md) {/*#incident*/}

サービスの**計画外の中断の報告**であり、ITSMでは**インシデント**とも呼ばれる。

## 課題管理システム {/*#issue-tracking-system*/}

ヘルプデスクの**課題管理システム(Issue Tracking System)**は、受信するすべての依頼を管理し、空いているヘルプデスク担当者に自動的に割り当てる。障害と依頼の履歴を詳細に把握できる。

別名:**ヘルプデスクシステム**または**サポートチケットシステム**。

プロセスの流れ:

```text
Customer inquiry / disruption report
=> Create service ticket
=> Classify and prioritise (HW / SW / NW, urgency, impact)
=> Route to responsible team
=> Find and deliver solution
=> Document and close (incl. commercial aspects via CRM link)
```

分類と優先度付けの目的:適切なチームがチケットを担当し、その重大度を正しく評価できるようにすること。

## ナレッジベース {/*#knowledge-base*/}

セルフサービスでの参照のための、**知識ベースの情報処理支援システム**。ヘルプデスク担当者は、既知の問題([既知のエラー](./problem-management.md#known-error-database-kedb))の解決策を素早く見つけるためにこれを利用する。

| 利点                                                                            | 欠点                                                |
| ------------------------------------------------------------------------------- | --------------------------------------------------- |
| 繰り返し発生する問題に素早く回答できる                                          | 知識が陳腐化する => 保守に手間がかかる              |
| 担当者が退職しても知識が社内に残る => 知識の欠落を防ぐ                          | すべての問題に既成の解決策があるわけではない        |
| 費用対効果の高いトラブルシューティング                                          | 顧客との直接のやり取りが減る                        |

## リクエストフルフィルメントのプロセス {/*#request-fulfillment-process*/}

**リクエストフルフィルメント(Request Fulfillment)**のサブプロセスは、サービスリクエスト(顧客からの問い合わせ)を扱う。その目標は、geringfügige(軽微な)変更とユーザーからの質問を効率的に処理することである。

- 担当:ファーストレベルサポート
- 使用するツール:課題管理システム、ナレッジベース、ハンドブック
- 起点:顧客がユーザーからの問い合わせでサポートに連絡すること
- 判断ポイント:ユーザーからの問い合わせの分類(Hilfestellung / Änderungswunsch / Passwortanfrage)
