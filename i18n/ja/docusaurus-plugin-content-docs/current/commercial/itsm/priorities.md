# ITサポートにおける優先度付け

## 概要 {/*#overview*/}

ITサポートにおける優先度付けには、主に2つのツールが用いられる。**ITIL優先度マトリクス**と**アイゼンハワー・マトリクス**である。

## ITIL優先度マトリクス {/*#itil-priority-matrix*/}

### 緊急度のレベル {/*#urgency-levels*/}

| レベル         | 説明                                                                                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **高(H)**     | インシデントによる損害が急速に拡大する。遂行できないタスクの時間的な切迫度が非常に高い。迅速な対応により、軽微なインシデントが[重大インシデント](./incident-management.md#major-incident)に発展することを防げる。複数のVIPユーザーが影響を受けている。 |
| **中(M)**     | 損害が時間とともに拡大する。遂行できないタスクの時間的な切迫度は中程度である。VIPユーザー1名が影響を受けている。                                                                                                                                        |
| **低(N)**     | 損害は時間が経っても拡大しない。遂行できないタスクに時間的な切迫度はない。                                                                                                                                                                              |

### 影響度のレベル {/*#impact-levels*/}

| レベル         | 説明                                                                                                                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **高(H)**     | 多数の従業員が影響を受け、または業務を遂行できない。多数の顧客が影響を受けるか、著しく支障を来す。金銭的損害が10,000 EURを超える可能性が高い。広範囲に及ぶ評判の毀損が見込まれる。生命や身体への危険がある。                                |
| **中(M)**     | 中程度の人数の従業員が影響を受け、または計画どおりに業務を遂行できない。中程度の数の顧客が影響を受けるか、快適性に制限が生じる。金銭的損害が1,000～10,000 EURとなる可能性が高い。中程度の評判の毀損が見込まれる。                          |
| **低(N)**     | 影響を受ける従業員はごく少数で、追加の労力は要するものの業務は遂行できる。影響を受ける顧客はごく少数で、快適性の軽微な制限にとどまる。金銭的損害が1,000 EUR未満となる可能性が高い。評判の毀損は最小限にとどまる見込みである。               |

### 優先度マトリクス {/*#priority-matrix*/}

**緊急度 x 影響度のマトリクス**により、1(最も重大)から5(最も低い)までの優先度レベルが得られる。

|               | **影響度 H** | **影響度 M** | **影響度 N** |
| ------------- | ------------ | ------------ | ------------ |
| **緊急度 H**  | **1**        | 2            | 3            |
| **緊急度 M**  | 2            | **3**        | 4            |
| **緊急度 N**  | 3            | 4            | **5**        |

### 優先度コードと[SLA](./sla.md)の応答/解決時間 {/*#priority-codes-and-sla-responseresolution-times*/}

| 優先度   | 説明                    | 応答時間 | 解決時間 |
| -------- | ----------------------- | -------- | -------- |
| **1**    | Kritisch(クリティカル)  | 即時     | 1時間    |
| **2**    | Hoch(高)                | 10分     | 4時間    |
| **3**    | Mittel(中)              | 1時間    | 8時間    |
| **4**    | Niedrig(低)             | 4時間    | 24時間   |
| **5**    | Sehr niedrig(非常に低い) | 1日      | 1週間    |

## アイゼンハワー・マトリクス {/*#eisenhower-matrix*/}

**アイゼンハワー・マトリクス**は、重要なタスクと緊急のタスクを区別するための時間管理手法である。名称は米国大統領ドワイト・D・アイゼンハワー(1953～1961年)に由来する。四象限法、アイゼンハワー法、アイゼンハワー・ボックスとも呼ばれる。

**目標:** 物事を正しく行うことではなく、正しいことを行うこと(単なる効率ではなく有効性)。

タスクごとに2つの問いを立てる。

1. そのタスクはどれだけ重要か。
2. そのタスクはどれだけ緊急か。

### 4つの象限 {/*#the-four-quadrants*/}

|                   | **緊急**                          | **緊急でない**                            |
| ----------------- | --------------------------------- | ----------------------------------------- |
| **重要**          | **A: 実行**(直ちに自分で)         | **B: 計画**(計画し、期限を設定する)       |
| **重要でない**    | **C: 委任**(または自動化)         | **D: 破棄**(アーカイブまたは削除)         |

### 原則 {/*#principles*/}

- 重要なタスクとは、定められた目標に直接関係するタスクである
- 緊急のタスクは遅延を許さず、可能であれば直ちに処理するのが望ましい
- 重要かつ緊急のタスク:自分で、可能な限り速やかに処理する
- 緊急だが重要ではないタスク:可能であれば委任または自動化し、不可能であればAのタスクの後に処理する
- 重要だが緊急ではないタスク:計画してスケジュールに組み込む。Aのタスクより優先度は低い
- 重要でも緊急でもないタスク:処理せず、適宜アーカイブまたは削除する

## 比較:ITILマトリクスとアイゼンハワー・マトリクス {/*#comparison-itil-matrix-vs-eisenhower-matrix*/}

| 基準                | ITIL優先度マトリクス                                                                                                        | アイゼンハワー・マトリクス                 |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| **目的**            | ITの[インシデント](./incident-management.md)/[問題](./problem-management.md)/[変更](./change-management.md)の優先度付け     | 個人またはチームのタスクの優先度付け       |
| **次元**            | 緊急度 x 影響度(ビジネス志向)                                                                                              | 緊急度 x 重要度(目標志向)                  |
| **尺度**            | 定義された[SLA](./sla.md)時間を持つ5段階の優先度レベル                                                                      | アクションを伴う4つの象限                  |
| **最適な用途**      | ITサービスデスク、構造化されたチーム                                                                                        | 自己管理、一般的なタスクの整理             |
| **実用性**          | 客観的、標準化されており、拡張可能                                                                                          | より単純で柔軟だが、構造化の度合いは低い   |
