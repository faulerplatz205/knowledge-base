# サービスレベル契約 (SLA)

## 概要 {/*#overview*/}

**SLA (Service Level Agreement)** は、ITサービスプロバイダーと顧客の間の契約であり、提供されるITサービスの範囲、品質、条件を定める。

## SLAの典型的な構成 {/*#typical-sla-structure*/}

### 1. 説明 / 対象範囲 {/*#1-description--scope*/}

対象となるIT上の問題、その対応方法、使用するサポートチャネル(電話、メール)を定める。対象となるハードウェアとシステムも明記する。

### 2. [優先度](./priorities.md) {/*#2-priorities*/}

応答時間の異なる3段階以上の優先度。例:

| 優先度 | 応答時間 |
| ---------- | ---------------------------------- |
| 優先度1 | 1営業時間、特急料金あり |
| 優先度2 | 5営業時間、標準優先度 |
| 優先度3 | 1営業日 |

**応答時間:** 障害が[ヘルプデスク](./service-requests.md)に報告されてから、担当のサポートレベルで問題解決の作業が開始されるまでの時間。

### 3. サービス時間 {/*#3-service-times*/}

| 曜日 | 時間 |
| --------------------------- | -------------------- |
| 月~金 | 07:00~20:00 |
| 土曜日 | 09:00~18:00 |
| 日曜日および祝日 | サービスなし |
| 時間延長 | 要請に応じて対応可能 |

### 4. 言語 {/*#4-languages*/}

サポートで対応する言語(例: ドイツ語、英語)。

### 5. 品質指標: 着信応答 {/*#5-quality-metrics-call-acceptance*/}

| 指標 | 目標 |
| -------------------------- | -------------------------------------- |
| 応答した通話 | 全着信の95 %、放棄呼は5 %未満 |
| 20秒以内に応答 | 75 % |
| 40秒以内に応答 | 90 % |
| ボイスメール経由で処理 | 最大10 % |

### 6. 品質指標: 問題解決 {/*#6-quality-metrics-problem-resolution*/}

| 指標 | 目標 |
| ------------------------------------------ | -------------------------- |
| 通話の平均処理時間 | 最大30分 |
| 未回答の場合の中間報告 | 4時間後 |
| 障害の平均処理時間 | 最大2時間 |
| 最大処理時間 | 3日 |
| 最低解決率 | 2営業日以内に70 % |

### 7. 品質指標: 顧客満足度 {/*#7-quality-metric-customer-satisfaction*/}

オンラインアンケートとトレーラーコール(通話者の10 %へのコールバックと評価)によって測定する。

### 8. レポート {/*#8-reporting*/}

月次のレビューと四半期ごとの統計評価。

### 9. 有効期間 {/*#9-validity-and-duration*/}

SLAの期間と再交渉の時期を定める(例: 「20xx年8月1日まで有効」)。

### 10. 署名者 {/*#10-signatories*/}

プロバイダーと顧客がそれぞれ契約に署名する。

## サービスレベル管理 (SLM) {/*#service-level-management-slm*/}

**SLM**は、顧客とSLAが締結され、合意されたサービスレベルを満たすようにサービスが設計されることを保証する。

**タスク:**

- サービス要件の収集
- 合意されたサービスレベルが満たされているかの確認
- サービスレベルレポートによる情報提供

## 役割 {/*#roles*/}

### サービスレベルマネージャー {/*#service-level-manager*/}

サービスレベル管理のプロセスオーナー。

責任:

- SLAの交渉
- SLAの遵守の確保
- すべてのITSMプロセス、OLA、第三者との契約が、合意されたサービスレベル目標を支えていることの確保
- サービスレベルの監視とレポートの提供

### サービスオーナー (Serviceverantwortlicher) {/*#service-owner-serviceverantwortlicher*/}

合意されたSLAの範囲内でインフラストラクチャサービスを提供する責任を負う。

責任:

- OLAを合意する際に、サービスレベルマネージャーの交渉相手となる
- 通常は、技術専門家のチームまたは社内サポート部門を率いるマネージャー

## OLA (運用レベル契約) {/*#ola-operational-level-agreement*/}

**OLA**は、運用レベルでのサービス提供に関するITチームまたは部門間の内部的な合意である。OLAは、外部SLAの履行を支える。
