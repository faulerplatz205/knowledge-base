# クラウドサービスモデル

## 概要 {/*#overview*/}

クラウドコンピューティングサービスは、一般に3つの主要なサービスモデルに分類される。各モデルは、制御と柔軟性の度合いが異なる。

| サービスモデル                                                              | 利用者が管理するもの                        | 提供者が管理するもの                                                           | 例                                                   |
| --------------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------- |
| **[オンプレミス](#on-premise)**                                             | すべて                                      | なし                                                                           | 自社データセンター、ローカルサーバー                 |
| **[IaaS](#infrastructure-as-a-service-iaas)** (Infrastructure as a Service) | OS、ミドルウェア、ランタイム、データ、アプリケーション | 仮想化、サーバー、ストレージ、ネットワーク                                  | AWS EC2, Azure VMs, Google Compute Engine            |
| **[PaaS](#platform-as-a-service-paas)** (Platform as a Service)             | データ、アプリケーション                    | ランタイム、ミドルウェア、OS、仮想化、サーバー、ストレージ、ネットワーク      | Heroku, Google App Engine, Azure App Service, Vercel |
| **[FaaS](#function-as-a-service-faas--serverless)** (Function as a Service) | 個々の関数、データ                          | ランタイム、スケーリング、ミドルウェア、OS、仮想化、サーバー、ストレージ、ネットワーク | AWS Lambda, Azure Functions, Cloudflare Workers      |
| **[SaaS](#software-as-a-service-saas)** (Software as a Service)             | 設定のみ                                    | すべて                                                                         | Gmail, Salesforce, Microsoft 365, Dropbox            |

---

## オンプレミス {/*#on-premise*/}

### 定義 {/*#definition*/}

オンプレミス (「オンプレ」とも呼ばれる) とは、すべてのIT基盤を組織自身の施設内で運用・管理する形態を指す。クラウドプロバイダーは関与しない。物理ハードウェアからアプリケーションまで、すべてを組織が所有、運用、保守する。

### 含まれるもの {/*#what-is-included*/}

- 物理サーバーとハードウェア
- すべてのレイヤーに対する完全な制御
- データが組織自身の施設内に留まる
- 外部プロバイダーへの依存がない

### 責任範囲 {/*#responsibilities*/}

**組織が管理するもの:**

- 物理ハードウェア (サーバー、ストレージ、ネットワーク)
- 仮想化
- オペレーティングシステム
- ミドルウェア
- ランタイム環境
- アプリケーション
- データ
- セキュリティ、バックアップ、ディザスタリカバリ

### ユースケース {/*#use-cases*/}

- **厳格なコンプライアンス要件:** データに関する規制が厳しい業界 (例: 行政、医療、金融)
- **レガシーシステム:** クラウドへ移行できないアプリケーション
- **低遅延の要件:** ネットワーク遅延を最小限に抑える必要があるシステム
- **完全なデータ主権:** 機密データを完全に社内で保持すること

### 利点 {/*#advantages*/}

- ハードウェアとソフトウェアを完全に制御できる
- データが組織の敷地外に出ない
- 継続的なクラウド利用料が発生しない
- インターネット接続に依存しない
- 厳格なデータ規制への対応が容易

### 欠点 {/*#disadvantages*/}

- 初期の資本コスト (ハードウェア、施設、冷却) が高い
- 保守のための専任IT担当者が必要
- スケールにはハードウェアの購入と設置が必要
- すべての更新、パッチ、セキュリティについて全責任を負う
- ハードウェアが陳腐化し得る

## Infrastructure as a Service (IaaS) {/*#infrastructure-as-a-service-iaas*/}

### 定義 {/*#definition-1*/}

IaaSは、仮想化されたコンピューティングリソースのみをインターネット経由で提供する。独自のクラウドIT基盤を構築するための基本的な構成要素を提供する。

### 含まれるもの {/*#what-is-included-1*/}

- 仮想マシン
- ストレージ
- ネットワーク
- オペレーティングシステムイメージ

### 責任範囲 {/*#responsibilities-1*/}

**利用者が管理するもの:**

- オペレーティングシステム
- アプリケーション
- データ
- ランタイム環境
- ミドルウェア

**提供者が管理するもの:**

- 物理サーバー
- ストレージハードウェア
- ネットワーク機器
- 仮想化レイヤー

### ユースケース {/*#use-cases-1*/}

- **テストと開発:** テスト環境を迅速に起動・停止できる
- **Webサイトのホスティング:** 基盤を完全に制御してWebサイトをホストする
- **ストレージとバックアップ:** 大規模なデータストレージソリューション
- **ハイパフォーマンスコンピューティング:** 計算負荷の高いワークロード

### 利点 {/*#advantages-1*/}

- 基盤を完全に制御できる
- 従量課金制
- 高いスケーラビリティ
- 物理ハードウェアの保守が不要

### 欠点 {/*#disadvantages-1*/}

- 技術的な専門知識が必要
- セキュリティパッチと更新は利用者のみの責任となる
- PaaS/SaaSより管理の負担が大きい

### 例 {/*#examples*/}

- Amazon Web Services (AWS) EC2
- Microsoft Azure Virtual Machines
- Google Compute Engine
- Hetzner

## Platform as a Service (PaaS) {/*#platform-as-a-service-paas*/}

### 定義 {/*#definition-2*/}

PaaSは、利用者が基盤を意識せずにアプリケーションを開発、実行、管理できるプラットフォームを提供する。

### 含まれるもの {/*#what-is-included-2*/}

- **すぐに使えるランタイム環境** (Node.js, Python, Java, PHP, ...)
- **マネージドデータベース** (PostgreSQL, MySQL, MongoDB, Redis)
- **自動デプロイ** (Gitでコードをプッシュ => 自動ビルド)
- **組み込みのスケーリング** (トラフィックに応じてアプリケーションが自動的にスケールする)
- **開発ツール** (ログ、モニタリング、デバッグ)

### 責任範囲 {/*#responsibilities-2*/}

**利用者が管理するもの:**

- アプリケーション
- データ

**提供者が管理するもの:**

- ランタイム環境
- ミドルウェア
- オペレーティングシステム
- 仮想化
- サーバー、ストレージ、ネットワーク

### ユースケース {/*#use-cases-2*/}

- **アプリケーション開発:** 基盤を意識せずにアプリを構築する
- **API開発と管理:** APIの作成とホスティング
- **マイクロサービスアーキテクチャ:** コンテナ化されたアプリケーションのデプロイ

### 利点 {/*#advantages-2*/}

- 開発とデプロイが速い
- スケーラビリティが組み込まれている
- 管理の複雑さが軽減される
- 基盤ではなくコードに集中できる
- 統合された開発ツール

### 欠点 {/*#disadvantages-2*/}

- IaaSより制御が限られる
- ベンダーロックインの可能性がある
- すべてのプログラミング言語/フレームワークに対応するとは限らない
- カスタマイズの選択肢が限られる

### 例 {/*#examples-1*/}

- Heroku
- Google App Engine
- Microsoft Azure App Service
- Red Hat OpenShift
- AWS Elastic Beanstalk
- Vercel, Netlify

## Function as a Service (FaaS) / サーバーレス {/*#function-as-a-service-faas--serverless*/}

### 定義 {/*#definition-3*/}

FaaSはPaaSの論理的な延長にある。デプロイされる単位はアプリケーションではなく、単一の関数になる。関数は常時稼働せず、イベントによって起動し、そのイベントを処理して再び停止する。

「サーバーレス」はこの運用モデルを指すより広い用語であり、誤解を招きやすい。サーバーは依然として使われているが、利用者からは見えず、管理もできなくなる。FaaSのほかに、サーバーレスデータベース、オブジェクトストレージ、メッセージキューなど、同じ原則に従うマネージドサービスも含まれる。

### 含まれるもの {/*#what-is-included-3*/}

- **イベント駆動の実行:** HTTPリクエスト、タイマー、キュー内のメッセージ、ファイルアップロード、データベースの変更
- **ゼロからの自動スケーリング:** アイドル中はインスタンスなし、負荷時は多数の並列インスタンス
- **キャパシティプランニング不要:** インスタンス数、マシンサイズ、オートスケーリングルールの設定が不要
- **呼び出し単位の課金:** 実行時間とメモリに対して、通常はミリ秒単位で課金される
- プラットフォームが提供する**統合ログとモニタリング**

### 責任範囲 {/*#responsibilities-3*/}

**利用者が管理するもの:**

- 関数のコードとその依存関係
- 設定: トリガー、権限、環境変数、メモリ、タイムアウト
- データと外部状態

**提供者が管理するもの:**

- ランタイム環境とその更新
- 並列インスタンス数を含むスケーリング
- ミドルウェア、オペレーティングシステム、仮想化
- サーバー、ストレージ、ネットワーク

### 特性 {/*#properties*/}

| 特性              | 設計への影響                                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| ステートレス      | 関数は呼び出し間で状態を保持しない。状態はデータベース、キャッシュ、オブジェクトストレージに置く                                        |
| コールドスタート  | アイドル後の最初の呼び出しではランタイムの起動に追加の時間がかかり、遅延が重要なリクエストでは体感できる                                |
| 実行時間の上限    | 呼び出しは最大実行時間を超えると中断される。そのため、長時間のジョブは分割する必要がある                                                |
| イベント駆動      | 関数はイベントがトリガーしたときにのみ実行され、自力では起動できない                                                                    |
| ゼロからのスケーリング | 負荷の急増により、多数のコールドスタートが並列で発生する                                                                           |

### ユースケース {/*#use-cases-3*/}

- **APIとWebhook:** 負荷が不規則または予測できないエンドポイント
- **イベント処理:** アップロード、キューのメッセージ、データベースの変更への反応
- **スケジュールジョブ:** クリーンアップ、レポート、インポートをタイマーで実行
- **グルーコード:** 2つのサービス間の小規模な変換
- **画像・ファイル処理:** アップロード後のサムネイル生成

### 利点 {/*#advantages-3*/}

- サーバー管理とキャパシティプランニングが不要
- コストが負荷に正確に比例し、アイドル時間は無料
- アイデアからデプロイ済みエンドポイントまでが非常に速い
- スケーリングはプラットフォームが処理する

### 欠点 {/*#disadvantages-3*/}

- コールドスタートにより遅延が予測しにくくなる
- 関数ごとの実行時間、メモリ、パッケージサイズに制限がある
- トリガーや権限モデルがプロバイダー固有であるため、ベンダーロックインが強い
- 常時稼働するアプリケーションに比べて、デバッグとローカルテストが難しい
- 多数の小さな関数にロジックが分散し、全体の挙動を追いにくくなる
- 高負荷が継続する場合は、常時稼働するインスタンスのほうが通常は安価

### 例 {/*#examples-2*/}

- AWS Lambda
- Azure Functions
- Google Cloud Functions / Cloud Run Functions
- Cloudflare Workers
- Vercel Functions, Netlify Functions

## Software as a Service (SaaS) {/*#software-as-a-service-saas*/}

### 定義 {/*#definition-4*/}

SaaSは、完全に機能するアプリケーションをインターネット経由で提供する。ユーザーはインストールや保守なしに、Webブラウザからソフトウェアを利用する。

### 含まれるもの {/*#what-is-included-4*/}

- すぐに使えるアプリケーション
- 自動更新
- インターネットに接続できる任意のデバイスからアクセス可能
- マルチテナントアーキテクチャ

### 責任範囲 {/*#responsibilities-4*/}

**利用者が管理するもの:**

- ユーザー設定
- データ入力
- アクセス権限

**提供者が管理するもの:**

- それ以外のすべて (アプリケーション、データ、ランタイム、ミドルウェア、OS、基盤)

### ユースケース {/*#use-cases-4*/}

- **メールとコミュニケーション:** ビジネスメール、メッセージング
- **顧客関係管理 (CRM)**
- **コラボレーションツール:** ドキュメント共有、プロジェクト管理
- **オフィス生産性:** ワープロ、表計算、プレゼンテーション
- **人事:** 給与計算、採用、従業員管理

### 利点 {/*#advantages-4*/}

- インストールや保守が不要
- 自動更新
- 初期コストが低い
- 使いやすく、スケールしやすい

### 欠点 {/*#disadvantages-4*/}

- 基盤を制御できず、運営会社に完全に依存する
- カスタマイズが限られる
- データセキュリティ上の懸念 (データがクラウド上の外部に保存される)
- サブスクリプション費用が積み重なり得る
- インターネット接続に依存する

### 例 {/*#examples-3*/}

- **Google Workspace** (Gmail, Google Docs, Drive)
- **Microsoft 365** (Outlook, Word, Excel, Teams)
- **ADITO** (CRM)
- **Slack** (チームコミュニケーション)
- **Dropbox** (ファイルストレージ)
- **Zoom** (ビデオ会議)

## ピザのたとえ {/*#the-pizza-analogy*/}

- **オンプレミス:** 自宅でピザを作る
- **IaaS:** ピザ生地とトッピングを買って自宅で焼く
- **PaaS:** 好みのトッピングを指定したピザを配達で注文する
- **FaaS:** 空腹のときに1切れだけ買い、1切れ単位で支払う (保温はされない)
- **SaaS:** ピザレストランで食べる

## その他のサービスモデル {/*#additional-service-models*/}

3つの主要モデルと[FaaS](#function-as-a-service-faas--serverless)のほかにも、特化したサービスモデルがある。

### Database as a Service (DBaaS) {/*#database-as-a-service-dbaas*/}

- マネージドデータベースソリューション
- 例: Amazon RDS, Azure SQL Database, MongoDB Atlas

### Container as a Service (CaaS) {/*#container-as-a-service-caas*/}

- コンテナオーケストレーションプラットフォーム
- 例: Amazon ECS, Google Kubernetes Engine, Azure Kubernetes Service

### Desktop as a Service (DaaS) {/*#desktop-as-a-service-daas*/}

- クラウド経由で提供される仮想デスクトップ
- 例: Amazon WorkSpaces, Azure Virtual Desktop, Citrix DaaS

### Backend as a Service (BaaS) {/*#backend-as-a-service-baas*/}

- バックエンドは提供者が管理し、フロントエンドは利用者が管理する
- 例: Supabase, Firebase
