# NAT (Network Address Translation)

## 概要 {/*#overview*/}

インターネットの急速な成長は、より効率的に使用する仕組みがなければ、利用可能なIPアドレスのプールをすぐに使い果たしていただろう。NAT (Network Address Translation) は、プライベートネットワーク内の多数のデバイスが少数のパブリックIPアドレスを共有できるようにすることで、これに対処する。

NATは境界デバイス(通常はファイアウォールまたはルーター)上で動作する。パケットが通過する際、NATは送信元IPアドレス(ルーティング不可能なプライベートアドレス)を、ルーティング可能なパブリックIPアドレスに置き換える。応答のパブリックアドレスは、パケットが正しい内部ホストに配信されるよう、プライベートアドレスに変換し直される。

## 利点 {/*#benefits*/}

- **番号の付け替えが容易**: ISPを変更する際、内部ホストに新しいIPアドレスは不要である。新しいISPが割り当てるパブリックアドレスだけが変わる。
- **アドレスの節約**: [PAT](#nat-overloading-pat)により、多数の内部ホストが単一のパブリックIPアドレスを共有でき、必要なパブリックアドレスの数が大幅に減る。
- **セキュリティの向上**: パブリックアドレスのみが見えるため、内部アドレスとネットワークトポロジーは外部ネットワークから隠される。

## NATの仕組み {/*#how-nat-works*/}

1. 内部ホスト(例: `10.0.0.3`)が、外部ホスト(例: `128.23.2.2`)宛てのパケットを送信する
2. 境界ルーター(RTA)は、パケットがインターネットに向かうことを認識し、利用可能なグローバルIPアドレス(例: `179.9.8.80`)を選択する
3. RTAはパケットの送信元アドレスをグローバルアドレスに置き換え、対応付けをNATテーブルに記録する
4. パケットは宛先に転送される
5. `179.9.8.80` 宛ての応答が到着すると、RTAはNATテーブルを参照して対応する内部アドレスを見つけ、宛先フィールドを置き換えて、パケットを内部に転送する

NATテーブルは、3種類のアドレスを記録する。

- **内部ローカルIP**: 内部ホストのプライベートIPアドレス
- **内部グローバルIP**: NATルーターが、内部ホストを外部に対して表すために割り当てるパブリックIPアドレス
- **外部グローバルIP**: 外部ネットワーク内の宛先ホストのIPアドレス

**NATテーブルの例:**

| 内部ローカルIP | 内部グローバルIP | 外部グローバルIP |
| ----------------- | ------------------ | ------------------ |
| 10.0.0.3          | 179.9.8.80         | 128.23.2.2         |

## NATオーバーロード(PAT) {/*#nat-overloading-pat*/}

NATオーバーロードは、PAT (Port Address Translation) とも呼ばれ、ポート番号を追加で追跡することで、複数のプライベートIPアドレスを単一のパブリックIPアドレスに対応付ける。各内部接続にはパブリック側で一意のポート番号が割り当てられ、ルーターは受信した応答を正しい内部ホストに振り分けることができる。

**オーバーロード時のNATテーブル:**

| 内部IP | 内部ポート | グローバルIP  | 外部ポート |
| ----------- | ------------- | ---------- | ------------- |
| 10.0.0.2    | 1555          | 179.9.8.80 | 1555          |
| 10.0.0.3    | 1331          | 179.9.8.80 | 1331          |
| 10.0.0.4    | 1444          | 179.9.8.80 | 1444          |

## ポートフォワーディング {/*#port-forwarding*/}

デフォルトでは、NATは外部から開始されるすべての着信接続をブロックする。ポートフォワーディングは、パブリックIP上の宛先ポート番号を特定の内部IPアドレスに対応付けることで、特定の外部トラフィックが内部ホストに到達できるようにする。

流れの例:

1. クライアントが `https://knowledge.moritz-grimm.dev`(パブリックIP `209.165.200.225`、ポート `443`)にリクエストを送信する
2. `209.165.200.225` がルーター自身のパブリックIPであるため、ルーターがパケットを受信する
3. ポートフォワーディングルールが外部ポート `443` を内部ホスト `192.168.1.254:443` に対応付けるため、ルーターは宛先を書き換えてパケットを内部に転送する

:::info
外部ポート番号と内部ポート番号が同じである必要はない。
:::
