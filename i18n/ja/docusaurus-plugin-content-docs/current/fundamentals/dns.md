# DNS (Domain Name System)

DNSは、DNS名をIPアドレスに、またその逆に解決する。DNS名は2つの部分からなる。単一のホストを識別する**ホスト名**と、共通の名前空間内のホストのグループを識別する**ドメイン名**であり、両者はドットで区切られる。

## 階層とFQDN {/*#hierarchy-and-fqdn*/}

DNSは階層型のシステムであり、ルートから下に向かって構成される。

- **ルート** – 階層の最上位(`.` と表記される)
- **トップレベルドメイン(TLD)** – 例: `com`, `net`, `de`, `org`
- **セカンドレベルドメイン** – 例: `heise.de` の `heise`
- **サブドメイン / ホスト** – セカンドレベルドメインの下にあるさらに下位の階層。例: `www`

ルートまでのすべての部分が指定されると、**FQDN**(Fully Qualified Domain Name、完全修飾ドメイン名)になる。FQDNはネットワーク内で一意でなければならない。例: `www.heise.de`。

## ゾーン {/*#zones*/}

各DNSサーバーは、**ゾーン**と呼ばれる名前空間の区切られた一部(例: `heise.de`)を担当する。ゾーンのファイルを管理するサーバーは、そのゾーンの**権限**を持つ。

- **プライマリゾーン** – 読み取りと書き込みが可能。ゾーンの権威あるコピー。
- **セカンダリゾーン** – プライマリゾーンの読み取り専用コピー(冗長性または負荷分散のため)。クエリに応答できるが、ゾーンファイルを更新することはできない。

ゾーンデータは、**ゾーン転送**(ドメインコントローラーのない2台のDNSサーバー)または**ゾーンレプリケーション**(ドメインコントローラー上のActive Directory統合ゾーン)によってサーバー間で交換される。

方向による分類:

- **正引きゾーン** – ドメイン名をIPアドレスに解決する。
- **逆引きゾーン** – IPアドレスをドメイン名に解決する。

## レコードタイプ {/*#record-types*/}

| レコード    | 用途                                   |
| --------- | ----------------------------------------- |
| **A**     | ドメイン名からIPv4アドレス               |
| **AAAA**  | ドメイン名からIPv6アドレス               |
| **CNAME** | 別のホストレコードを指す別名     |
| **SRV**   | サービスをIPアドレスに解決する       |
| **PTR**   | 逆引き: IPアドレスからドメイン名 |

## 再帰クエリと反復クエリ {/*#recursive-vs-iterative-queries*/}

- **再帰クエリ** – クライアントがネームサーバーに送信し、最終的な回答(IPアドレス)を期待する。サーバーがそのゾーンを保持している場合は、**権威ある回答**を返す。
- **反復クエリ** – サーバー自身が回答できない場合、階層に沿って他のDNSサーバーに問い合わせる。各サーバーは、権威サーバーに到達するまで、最終的な回答ではなく次の担当サーバーを示すだけの場合がある。
- **キャッシュ** – 関与したすべてのサーバーは、結果を**DNSキャッシュ**に保存する。キャッシュされた回答は**権威のない回答**として返される。

## 名前解決の例(`www.example.com`) {/*#example-resolution-wwwexamplecom*/}

1. クライアントは、設定されているDNSサーバーに**再帰**クエリを送信する。
2. そのサーバーは権威を持たず、キャッシュされたエントリもないため、**ルート**ネームサーバーに**反復**クエリを送信する。
3. ルートサーバーは、`com.` TLDネームサーバーのアドレスで応答する。
4. DNSサーバーは `com.` ネームサーバーに問い合わせる。
5. `com.` サーバーは、`example.com.` ネームサーバーのアドレスで応答する。
6. DNSサーバーは `example.com.` ネームサーバーに問い合わせる。
7. そのゾーンの権威を持つサーバーが、FQDNのIPアドレスで応答する。
8. DNSサーバーは、IPアドレスをクライアントに返す(そしてキャッシュする)。

## HOSTSファイル {/*#hosts-file*/}

ごく小規模なネットワークでは、静的な `HOSTS` ファイル(`C:\Windows\System32\Drivers\etc\HOSTS`)で、DNSの代わりにホスト名をIPアドレスに対応付けることができる。Active DirectoryはDNSを必要とするため、この代替手段は今日ではほとんど使われない。

## 便利なコマンド(クライアント) {/*#useful-commands-client*/}

| コマンド                | 用途                   |
| ---------------------- | ------------------------- |
| `ipconfig /displaydns` | ローカルDNSキャッシュを表示する  |
| `ipconfig /flushdns`   | ローカルDNSキャッシュを消去する |

## Windowsドメインの命名規則 {/*#naming-rules-for-windows-domains*/}

- 内部ネットワークでは、公式のインターネットドメインのサブドメインを使用する(例: `media.ct.local` ではなく `media.ct.de`)。
- 名前は短く保つ(ドメインは最大64文字)。
