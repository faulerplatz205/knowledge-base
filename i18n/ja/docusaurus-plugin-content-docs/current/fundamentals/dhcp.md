# DHCP (Dynamic Host Configuration Protocol)

DHCPは、ローカルネットワーク内でクライアントにIPアドレス、サブネットマスク、その他の設定パラメータを自動的に割り当てる。これにより、すべてのホストを手動で設定する必要がなくなる。DHCPはUDPポート `67`(サーバー)と `68`(クライアント)を使用する。

## DORAプロセス {/*#the-dora-process*/}

クライアントは4つのステップで設定を取得する。これは**DORA**と呼ばれる。

1. **Discover** – クライアントはサーバーを見つけるために、`DHCP Discover` をローカルネットワークにブロードキャストする。
2. **Offer** – DHCPサーバーは、利用可能なアドレスと設定パラメータを含む `DHCP Offer` で応答する。
3. **Request** – クライアントは `DHCP Request` で、提示されたアドレスを要求する。
4. **Acknowledge** – アドレスがまだ利用可能であれば、サーバーは `DHCP Ack` で確認する。

## 主要な概念 {/*#key-concepts*/}

- **リース** – アドレスは限られた期間(リース)だけ割り当てられる。これにより、アドレスがクライアントに永久に拘束されることが防がれ、再利用が可能になる。
- **スコープ** – サーバーが割り当てることのできるIPアドレスの範囲(サブネットマスクを含む)。
- **オプション** – アドレスとともに配布される追加のパラメータ。例: デフォルトゲートウェイ、DNSサーバー、サブネットマスク。
- **予約** – 特定のMACアドレスに恒久的に結び付けられた固定IPアドレス。クライアントは常に同じアドレスを受け取る。

## リレーエージェント {/*#relay-agent*/}

ルーターはブロードキャストを転送しないため、DHCPサーバーは通常、自身のサブネットにのみサービスを提供する。**DHCPリレーエージェント**は、別のサブネットからのDHCP要求をDHCPサーバーに(ユニキャストとして)転送し、1台のサーバーで複数のサブネットにサービスを提供できるようにする。

## フェイルオーバー {/*#failover*/}

高可用性のために、2台のDHCPサーバーが同じスコープを共有し、リース情報を複製できる。モードは2種類ある。

- **負荷分散** – 両方のサーバーが同時にアドレスを割り当てる(デフォルトの比率は50/50で、調整可能)。
- **ホットスタンバイ** – プライマリサーバーがすべてのアドレスを割り当て、セカンダリサーバーはプライマリが故障した場合にのみ引き継ぐ。

フェイルオーバーは最大2台のサーバーまでをサポートし、IPv4スコープでのみ機能する。

## DHCPv6とSLAACの比較 {/*#dhcpv6-vs-slaac*/}

IPv6では、アドレス設定に必ずしもDHCPを必要としない。

- **SLAAC** (Stateless Address Autoconfiguration) – ホストは、ルーターが通知するグローバルプレフィックス(ルーター通知)から自身のアドレスを生成する。中央のサーバーは関与しない。
- **DHCPv6** (ステートフル) – DHCPv6サーバーが、IPv4と同様に設定全体を一元的に割り当て、管理する。ルーターは引き続き `managed` フラグを付けたルーター通知を送信し、ホストにDHCPv6を使用するよう知らせる。

## 便利なコマンド(クライアント) {/*#useful-commands-client*/}

| コマンド             | 用途                                                         |
| ------------------- | --------------------------------------------------------------- |
| `ipconfig /all`     | IP設定の全体を表示する(アダプター、MAC、IP、DNS、ゲートウェイ) |
| `ipconfig /release` | 現在のアドレス(リース)を解放する                             |
| `ipconfig /renew`   | DHCPサーバーに新しいリースを要求する                              |
