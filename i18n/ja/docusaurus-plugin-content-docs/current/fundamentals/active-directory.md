# Active Directory

**Active Directory (AD)** は、Windows環境において、IDとアクセスの一元管理を提供するディレクトリサービスである。各マシンを個別に設定する代わりに、ユーザー、コンピューター、リソースを一元的に管理する。**ドメインコントローラー (DC)** は、Active Directory Domain Services (AD DS) をホストするWindows Serverである。

ドメインコントローラーには、一意の名前(例: `dc1`)、静的IPアドレス、動作するDNSサーバーが必要となる。「Active Directory Domain Services」ロールをインストールし、その後サーバーを昇格させる。

## 論理構造 {/*#logical-structure*/}

Active Directoryは、論理構造を物理構造(サイト、サブネット、DC)から分離している。論理的な構成要素は次のとおりである。

- **オブジェクト:** 管理可能な最小単位。すべてのネットワークリソース(ユーザー、コンピューター、プリンターなど)がオブジェクトとして表現される。
- **組織単位 (OU):** オブジェクト(ユーザー、コンピューター、グループ)をまとめて、企業の構造をモデル化するコンテナー。OUはグループポリシーのリンクにも使用される。
- **ドメイン:** Active Directoryを保持する中心的な単位。セキュリティポリシーはドメイン内で適用され、ドメインには少なくとも1台のDCが必要である。
- **ツリー:** 階層的に配置され、連続した名前空間を共有する複数のドメイン(例: `abc.com`の下の`de.abc.com`)。
- **フォレスト:** 1つ以上のツリー。通常は異なる名前空間を持つ。ドメインは独立して動作するが、フォレスト全体で通信できる。

## グローバルカタログ {/*#global-catalog*/}

**グローバルカタログ**は、他の名前空間のオブジェクトを含め、フォレスト全体でオブジェクトを検索するために使われるデータベースである。各ADサイトには、グローバルカタログのコピーを持つDCを少なくとも1台配置する必要がある。

## 信頼関係 {/*#trusts*/}

**信頼関係**は、2つのドメイン間の関係を表す。信頼する側のドメインは、信頼される側のドメインからの認証を受け入れる。

- **一方向:** 一方向の信頼 / **双方向:** 両方向の信頼
- **推移的:** 信頼がさらに他の信頼にも及ぶ / **非推移的:** 明示的に設定された信頼のみ

既定は**双方向かつ推移的**である。

## LDAPと命名 {/*#ldap-and-naming*/}

**LDAP** (Lightweight Directory Access Protocol) は、ディレクトリサービスへのアクセスに使用される。

- **識別名 (DN):** オブジェクトの一意の「LDAPパス」。`CN`(Common Name)、`OU`(Organizational Unit)、`DC`(Domain Component)を用いる。例: `CN=HPjet5, OU=Assistenz, DC=Firma, DC=DE`。
- **正規名:** 同じ情報をDNSドメイン名の形式で表したもの。例: `HPjet5.Assistenz.firma.de`。

## 移動プロファイル {/*#roaming-profiles*/}

**移動プロファイル**はサーバー上に一元的に保存され、ユーザーはどのドメインコンピューターでも同じ環境を利用できる。プロファイルはログオン時にマシンへコピーされ、ログオフ時に同期して戻される。

- **利点:** すべてのコンピューターで同じ環境が使える。
- **欠点:** 多くのストレージを必要とする。ログオンとログオフが遅くなることがある。

**SYSVOL**共有と**NETLOGON**共有は、サーバーをDCに昇格させたときに作成される。これらには、クライアントが取得するグループポリシーとログオンスクリプトが保存される。

## 機能レベル {/*#functional-levels*/}

DCを昇格させる際には、**フォレストの機能レベル**と**ドメインの機能レベル**を選択する。これらは、利用可能なADの機能を定義し、異なるWindows Serverバージョンを搭載したDC同士が相互運用できること(後方互換性)を保証する。レベルが高いほど多くの機能が提供されるが、元に戻すことはできない。ドメインはフォレストより高いレベルで動作できるが、低いレベルでは動作できない。

## グループポリシー (GPO) {/*#group-policies-gpo*/}

**グループポリシー**は、設定(例: パスワードポリシー、電源設定、アクセス制限)を強制するための構成指示である。Active Directoryに保存され、レプリケーションによってドメイン全体で利用できる。**グループポリシーオブジェクト (GPO)** は個々の設定を保持し、影響を与えたいオブジェクトに**リンク**される。GPOにはユーザー用とコンピューター用の別々の設定が含まれ、グループではなく、OUに含まれるユーザーアカウントとコンピューターアカウントに作用する。

### 処理順序 {/*#processing-order*/}

グループポリシーは、サイト、ドメイン、OUにリンクできる。また、すべてのコンピューターにはローカルポリシーもある。処理順序は**L-S-D-OU**である。

1. **ローカル**
2. **サイト**
3. **ドメイン**
4. **OU**

後の段階は、前の段階と競合する設定を上書きする。したがって、ローカルポリシーの優先度が最も低く、OUポリシーが最も高い。同じレベルに複数のGPOがリンクされている場合は、リンク順序で決まる(リンク値が最も小さいものが最後に処理されるため優先される)。

### 更新 {/*#refresh*/}

グループポリシーの設定は、バックグラウンドで、クライアントではおよそ**90分**ごと、ドメインコントローラーでは**5分**ごとに更新される。更新は`gpupdate /force`で強制できる。フォルダーリダイレクトは例外であり、ユーザーのログオン時にのみ適用される。
