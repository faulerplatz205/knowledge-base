# ARP (Address Resolution Protocol)

## 概要 {/*#overview*/}

ARP (Address Resolution Protocol) は、[OSI参照モデル](./osi-model.md)のレイヤー2(データリンク層)とレイヤー3(ネットワーク層)の境界で動作する。既知の**IPアドレス**を、ローカルネットワークセグメント内でフレームを配送するために必要な、対応する**MACアドレス**に解決する。

## 2種類のアドレス {/*#two-types-of-addresses*/}

EthernetのLAN内のすべての機器には、2つの異なるアドレスで到達する。

- **MACアドレス:** 同じネットワークセグメント内のネットワークインターフェースカード間の通信に使用される。レイヤー2のEthernetフレームのアドレス指定である。
- **IPアドレス:** 間にいくつのネットワークがあるかにかかわらず、パケットを元の送信元から最終的な宛先へ送るために使用される。レイヤー3のIPパケットのアドレス指定である。

EthernetフレームはIPパケットを包むようにカプセル化される。IPパケットはエンドツーエンドで移動するが、それを包むEthernetフレームは常に単一のネットワークセグメント上にしか存在しない。

## ARPが必要な理由 {/*#why-arp-is-needed*/}

IPパケットには送信元と宛先のIPアドレスが含まれるが、Ethernetフレームはローカルセグメント上の配送にMACアドレスを使用する。機器はデータを送信する際、宛先のIPアドレスは分かっているが、フレームの宛先とすべきMACアドレスを先に調べなければならない。

## ローカル配送とリモート配送 {/*#local-vs-remote-delivery*/}

送信側の機器はまず、サブネットマスクを適用して(自身のIPおよび宛先のIPとマスクとの論理ANDを取って)、宛先が**同じネットワーク**にあるかどうかを判定する。その結果によって、フレームに必要なMACアドレスが決まる。

- **同じネットワーク:** 宛先MACアドレスは、宛先ホスト自身のMACアドレスである。機器は、ARPを通じて宛先IPを解決する。
- **異なるネットワーク:** 宛先MACアドレスは、**デフォルトゲートウェイ**(ルーターのネットワークインターフェース)のMACアドレスである。機器は、ARPを通じてゲートウェイのIPを解決する。

どちらの場合も、パケット内の送信元と宛先の**IPアドレスは変わらない**。書き換えられるのは、フレーム内のMACアドレスだけである。経路上の各ルーターは、受信したフレームを取り除き、次のホップ用の送信元および宛先MACアドレスを持つ新しいフレームを組み立てる。

## ARPテーブルの検索 {/*#arp-table-lookup*/}

送信の前に、機器は解決が必要なIPをARPテーブル(RAM上に保持)から検索する。

- 宛先IPが**同じネットワーク**にある場合は、**宛先IPアドレス**を検索する。
- 宛先IPが**異なるネットワーク**にある場合は、**デフォルトゲートウェイのIPアドレス**を検索する。

一致するエントリがあれば、キャッシュされたMACアドレスを使ってフレームを組み立てる。エントリがなければ、機器は**ARP要求**を送信する。

## ARP要求/応答の流れ {/*#arp-request--reply-process*/}

1. **ARPキャッシュの確認:** 必要なIPのMACアドレスがすでにキャッシュにあれば、要求は不要である
2. **ARP要求(ブロードキャスト):** キャッシュにない場合、送信側はセグメント上のすべての機器にARP要求をブロードキャストする。*「IP X.X.X.Xを持つのは誰か。IP Y.Y.Y.Yに知らせよ」*。このブロードキャストフレームの宛先MACアドレスは`FF:FF:FF:FF:FF:FF`である
3. **ARP応答(ユニキャスト):** 一致するIPを持つ機器が、自身のMACアドレスを送信側に直接返す。他のすべての機器は要求を無視する
4. **キャッシュの更新:** 送信側は、IPとMACの対応を今後のためにARPキャッシュに保存する
5. **フレームの送信:** 送信側は、解決されたMACアドレスを使ってEthernetフレームを組み立てる

## ARPキャッシュ {/*#arp-cache*/}

ARPキャッシュは、繰り返しのブロードキャストを避けるために、最近のIPとMACの対応を保存する。

- エントリにはTTL (Time to Live) があり、自動的に失効する
- 一般的なコマンド(Windows/Linux):

| コマンド | 目的 |
| -------- | ------------------------ |
| `arp -a` | ARPテーブルを表示する |
| `arp -d` | ARPテーブルのエントリを削除する |

## セキュリティ: ARPスプーフィング {/*#security-arp-spoofing*/}

ARPには認証の仕組みがないため、攻撃者は偽のARP応答を送って他の機器のキャッシュを汚染し、通信を攻撃者のマシン経由に迂回させることができる(中間者攻撃)。

対策には次のものがある。

- マネージドスイッチでの**ダイナミックARPインスペクション (DAI)**
- 重要な機器に対する**静的ARPエントリ**
- ネットワーク監視と異常検知
