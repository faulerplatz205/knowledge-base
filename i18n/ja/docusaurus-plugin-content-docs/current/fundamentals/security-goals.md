# ITセキュリティの目標

## 概要 {/*#overview*/}

ITセキュリティは、安全なシステムが保証しなければならないことを定義する4つの中核的な目標の上に成り立つ。

## 機密性 {/*#confidentiality*/}

情報は、許可された者だけがアクセスできる。

- データは、不正なアクセスや開示から保護されなければならない
- 暗号化、アクセス制御、知る必要性の原則によって実現される
- **例**: 想定された受信者だけが、暗号化されたメールを読める

## 完全性 {/*#integrity*/}

情報は正確であり、改ざんされていない。

- データは、意図的か偶発的かを問わず、許可なく変更、破損、削除されてはならない
- ハッシュ関数、デジタル署名、チェックサムによって実現される
- **例**: ハッシュ値が公開された値と一致するダウンロードファイルは、改変されていない

## 可用性 {/*#availability*/}

システムとデータは、許可されたユーザーが必要とするときにアクセスできる。

- サービスは稼働し、応答し続けなければならない。ダウンタイムやアクセスの拒否はセキュリティ上の失敗である
- 冗長化、バックアップ、DDoS対策、耐障害性のあるインフラストラクチャによって実現される
- **例**: DDoS攻撃から保護されたWebサービスは、攻撃中も到達可能であり続ける

## 真正性 {/*#authenticity*/}

通信相手の身元やデータの出所を検証できる。

- 当事者が名乗るとおりの者であること、およびデータが信頼できる出所に由来することを保証する
- デジタル証明書、署名、認証プロトコル(例:TLS、MFA)によって実現される
- **例**: TLS証明書は、Webサイトが記載された組織によって運営されていることを証明する

## まとめ {/*#summary*/}

| 目標            | 問い                                     | 解決策                     |
| --------------- | ---------------------------------------- | -------------------------- |
| 機密性          | 誰がこれにアクセスできるか              | 暗号化、アクセス制御       |
| 完全性          | これは改ざんされていないか              | ハッシュ、デジタル署名     |
| 可用性          | 必要なときにアクセスできるか            | 冗長化、バックアップ       |
| 真正性          | これは本当に名乗るとおりの者/ものか     | 証明書、MFA                |
