# ビッグO記法

## 概要 {/* #overview */}

ビッグO記法は、アルゴリズムの処理量が入力に応じてどのように増加するかを表す。秒単位の時間ではなく、その増加の形を示す。

入力サイズは**n**と呼ばれ、リストの要素数、文字列の文字数、テーブルの行数を表す。それぞれの計算量クラスは、次の問いに答えるものである。**nが2倍になると、ステップ数はどうなるか。**

| 記法 | 名称 | nが2倍になると、処理量は... | 例 |
| ---------- | ------------ | ------------------------------ | -------------------------------------------- |
| O(1)       | 定数 | 変わらない | インデックスによる配列アクセス |
| O(log n)   | 対数 | 1ステップ増える | 二分探索 |
| O(n)       | 線形 | 2倍になる | 線形探索 |
| O(n log n) | 線形対数 | 2倍をわずかに上回る | マージソート |
| O(n²)      | 二次 | 4倍になる | バブルソート、同じリストに対する入れ子のループ |
| O(2ⁿ)      | 指数 | 2乗になる | 集合のすべての部分集合を試す |

O(2ⁿ)では、要素が1つ増えるだけで処理量が2倍になる。

---

## 数値で見る増加 {/* #growth-in-numbers */}

n個の要素の入力に対して各計算量クラスが必要とするステップ数(logは底2、丸め済み)。

| n         | O(1) | O(log n) | O(n)      | O(n log n) | O(n²)     | O(2ⁿ)         |
| --------- | ---- | -------- | --------- | ---------- | --------- | ------------- |
| 10        | 1    | 3        | 10        | 33         | 100       | 1,024         |
| 100       | 1    | 7        | 100       | 664        | 10,000    | ≈ 1.3 x 10³⁰  |
| 1,000     | 1    | 10       | 1,000     | 9,966      | 1,000,000 | ≈ 1.1 x 10³⁰¹ |
| 1,000,000 | 1    | 20       | 1,000,000 | ≈ 2 x 10⁷  | 10¹²      | ≈ 10³⁰¹⁰³⁰    |

1ステップあたり1マイクロ秒、要素数100万の場合、O(log n)のアルゴリズムは20 µs、O(n)のアルゴリズムは1秒、O(n log n)のアルゴリズムは約20秒、O(n²)のアルゴリズムは10⁶秒、すなわち約11.6日を要する。

## 形式的な定義 {/* #formal-definition */}

f(n)はアルゴリズムが必要とするステップ数、g(n)はnやn²のような単純な比較関数である。ある入力サイズ以降、fの増加が、gに固定の係数を掛けたもの以下である場合、f(n)はO(g(n))に属する。

形式的には、定数c > 0と閾値n₀が存在し、すべてのn ≥ n₀についてf(n) ≤ c x g(n)が成り立つ。

例: f(n) = 3n + 5はO(n)に属する。c = 4、n₀ = 5とすると、すべてのn ≥ 5について3n + 5 ≤ 4nが成り立つ。

- 定数係数はcに吸収される。`3n`、`n / 2`、`100n`はいずれもO(n)に属する。
- ビッグOは大きな入力のみを記述するため、n₀未満での挙動は無関係である。
- Oは上界である。厳密には、二分探索はO(n)にもO(n²)にも属する。実際には、当てはまる最小のクラスが示される。
- 下界はΩ (オメガ)と表記する。上界であり下界でもある境界はΘ (シータ)と表記する。

## 計算量クラスの判定 {/* #determining-the-complexity-class */}

計算量クラスは、最も頻繁に実行される操作(通常は最も内側のループにおける比較または代入)の回数をnの関数として数え、その結果を単純化することで決まる。

### 単一の文: O(1) {/* #single-statements-o1 */}

代入、算術演算、比較、インデックスによる配列アクセス、`RETURN`は、nに依存しない固定回数だけ実行される。

```text
first = list[0]
sum = a + b
```

### 入力に対するループ: O(n) {/* #loop-over-the-input-on */}

```text
FOR i = 0 TO n - 1
    sum = sum + list[i]
END FOR
```

`FOR`はn回実行される。`n / 2`回または`2n`回実行されるループも、同様にO(n)である。

### 入れ子のループ: 掛け算 {/* #nested-loops-multiply */}

入れ子のループの反復回数は掛け合わされる。両方のループが入力に対して実行される場合、n x nステップとなり、O(n²)になる。

```text
FOR i = 0 TO n - 1
    FOR j = 0 TO n - 1
        ...
    END FOR
END FOR
```

内側のループの反復回数が固定の場合、n x 7 = 7nステップとなり、したがってO(n)になる。

```text
FOR i = 0 TO n - 1
    FOR day = 1 TO 7        // 7 iterations, independent of n
        ...
    END FOR
END FOR
```

### 連続するブロック: 最大の項を残す {/* #consecutive-blocks-keep-the-largest-term */}

コードブロックが順に実行される場合、そのステップ数は加算される。和のうち最も速く増加する部分だけが、クラスを決定する。

```text
FOR i = 0 TO n - 1              // n steps
    ...
END FOR
FOR i = 0 TO n - 1              // n x n steps
    FOR j = 0 TO n - 1
        ...
    END FOR
END FOR
```

n + n²ステップはO(n²)となる。nが大きくなるほど、小さい方の部分の影響は小さくなる。

### 半分にする処理: O(log n) {/* #halving-olog-n */}

各ステップで残りの問題が半分になる場合、ステップ数は、1つの要素が残るまでnを半分にできる回数に等しい。その数はlog₂ nである。log₂ nとlog₁₀ nは定数係数しか異ならないため、ビッグOでは底を省略する。

```text
1,000,000 => 500,000 => 250,000 => ... => 1      20 halvings
```

二分探索は、ソート済みのリストに対してこのように動作する。

```text
low = 0
high = n - 1
WHILE low <= high
    mid = (low + high) DIV 2
    IF list[mid] == target THEN
        RETURN mid
    ELSE IF list[mid] < target THEN
        low = mid + 1
    ELSE
        high = mid - 1
    END IF
END WHILE
RETURN -1
```

### 分割統治: O(n log n) {/* #divide-and-conquer-on-log-n */}

マージソートは、個々の要素になるまでリストを半分に分割する。これにより、log n個のレベルが生じる。各レベルでは、n個すべての要素が1回ずつマージされる。log nレベル x レベルあたりnステップで、O(n log n)となる。

### 2つの入力: 2つの変数 {/* #two-inputs-two-variables */}

アルゴリズムが、サイズnとmの2つの独立した入力を扱う場合、結果には両方が現れる。

```text
FOR EACH customer IN customers          // n customers
    FOR EACH product IN products        // m products
        ...
    END FOR
END FOR
```

入れ子のループはn x mステップとなり、したがってO(n x m)になる。2つのループが連続する場合はO(n + m)になる。n + n²とは異なり、2つの入力のどちらが大きいか分からないため、どちらの項も省略できない。

## 最良、平均、最悪のケース {/* #best-average-and-worst-case */}

同じアルゴリズムでも、入力によって必要なステップ数は異なる。

- **最良ケース:** 最も有利な入力。線形探索では、先頭の位置にある値が1回の比較で見つかる場合である。最良ケースは幸運な偶然を表すものであり、典型的な挙動についてはほとんど何も語らない。
- **平均ケース:** すべての入力にわたる期待される処理量。線形探索では、n / 2回の比較であり、O(n)となる。
- **最悪ケース:** 最も不利な入力。線形探索では、最後の位置にある値、または存在しない値であり、n回の比較を要する。最悪ケースは、アルゴリズムが決して超えない保証である。

修飾語なしで示された計算量は、最悪ケースを指す。平均ケースと最悪ケースでは、クラスが大きく異なる場合がある。クイックソートは平均でO(n log n)を要するが、ピボット要素が常に最小値または最大値になる場合はO(n²)となる。

## 空間計算量 {/* #space-complexity */}

同じ記法で、アルゴリズムが入力に加えて必要とするメモリ量も表せる。

- **O(1):** 固定数の変数。例: リスト内で要素を交換する(インプレース)バブルソート。
- **O(log n):** 問題を半分にする再帰では、log n個の呼び出しが同時にスタック上に保持される。
- **O(n):** 入力に応じて増える補助的な構造。例: マージソートの一時リストや、見た値すべての集合。

時間とメモリは、しばしば互いにトレードできる。[具体例](#worked-example-finding-duplicates)は、そのようなトレードを示している。

## 一般的なアルゴリズムのクラス {/* #classes-of-common-algorithms */}

### 探索 {/* #searching */}

| アルゴリズム | 最良ケース | 平均ケース | 最悪ケース | 追加の空間 | 前提条件 |
| ------------- | --------- | ------------ | ---------- | ----------- | -------------------------------- |
| 線形探索 | O(1)      | O(n)         | O(n)       | O(1)        | なし |
| 二分探索 | O(1)      | O(log n)     | O(log n)   | O(1)        | インデックスでアクセスできるソート済みデータ |

### ソート {/* #sorting */}

| アルゴリズム | 最良ケース | 平均ケース | 最悪ケース | 追加の空間 | 安定 |
| -------------- | ---------- | ------------ | ---------- | ----------- | ------ |
| バブルソート | O(n)¹      | O(n²)        | O(n²)      | O(1)        | はい |
| 選択ソート | O(n²)      | O(n²)        | O(n²)      | O(1)        | いいえ |
| 挿入ソート | O(n)²      | O(n²)        | O(n²)      | O(1)        | はい |
| マージソート | O(n log n) | O(n log n)   | O(n log n) | O(n)        | はい |
| クイックソート | O(n log n) | O(n log n)   | O(n²)      | O(log n)    | いいえ |

¹ スワップのないパスの後に停止する早期終了がある場合のみ。これがなければ、バブルソートは常にO(n²)を要する。

² すでにソート済みのリストでは、各要素が直前の要素と1回比較されるだけで、その場にとどまる。

ソートが**安定**であるとは、等しいキーを持つ要素が元の順序を保つことをいう。キーとは、リストをソートする基準となる値である。名前ですでにソートされた人のリストを、年齢で安定ソートすると、同じ年齢の人は名前の順に並んだままとなる。

一度に2つの要素のみを比較するソートは、最悪の場合、少なくともおよそn log n回の比較を必要とする。したがって、マージソートは比較に基づくソートで最良のクラスに達している。値を直接利用するソート(例: 小さな整数に対する計数ソート)だけが、それより高速になりうる。

## 具体例: 重複の検出 {/* #worked-example-finding-duplicates */}

ある関数が、リストに同じ値が2回含まれているかどうかを調べる。

### バリアント1: すべての組を比較する {/* #variant-1-compare-every-pair */}

```text
FUNCTION hasDuplicates(list)
    n = LENGTH(list)
    FOR i = 0 TO n - 2
        FOR j = i + 1 TO n - 1
            IF list[i] == list[j] THEN
                RETURN true
            END IF
        END FOR
    END FOR
    RETURN false
END FUNCTION
```

最悪ケースは重複のないリストであり、すべての組が比較される。

```text
i = 0        n - 1 comparisons
i = 1        n - 2 comparisons
...
i = n - 2    1 comparison

Total:  (n - 1) + (n - 2) + ... + 1  =  n x (n - 1) / 2  =  0.5n² - 0.5n
n = 5:  4 + 3 + 2 + 1                =  5 x 4 / 2        =  10
```

小さい方の項`0.5n`と定数係数`0.5`を落とすと、**O**(n²)が残る。内側のループはパスごとに短くなるが、平均するとリストの半分にわたって実行される。n = 1,000では499,500回の比較、n = 2,000では1,999,000回となり、4倍である。

### バリアント2: 先にソートし、隣同士を比較する {/* #variant-2-sort-first-then-compare-neighbours */}

```text
FUNCTION hasDuplicates(list)
    n = LENGTH(list)
    sort(list)                          // O(n log n)
    FOR i = 0 TO n - 2                  // O(n)
        IF list[i] == list[i + 1] THEN
            RETURN true
        END IF
    END FOR
    RETURN false
END FUNCTION
```

ソート後は等しい値が隣り合うため、隣接する組に対する1回のパスで十分である。O(n log n) + O(n)で**O**(n log n)となる。関数がコピーをソートしない限り、渡されたリストの順序が変更される。コピーにはO(n)のメモリがかかる。

### バリアント3: 見た値を記憶する {/* #variant-3-remember-seen-values */}

```text
FUNCTION hasDuplicates(list)
    seen = empty set
    FOR EACH value IN list              // n iterations
        IF seen CONTAINS value THEN     // O(1) average
            RETURN true
        END IF
        ADD value TO seen               // O(1) average
    END FOR
    RETURN false
END FUNCTION
```

ハッシュに基づく集合は、「含まれているか」に平均して定数時間で答える。反復n回、各O(1)で**O**(n)となる。集合は追加でO(n)のメモリを要する。

### 比較 {/* #comparison */}

| バリアント | 時間 | 追加の空間 | n = 1,000,000のステップ数 |
| ------------- | ---------- | ---------------------- | ----------------------- |
| 1: すべての組 | O(n²)      | O(1)                   | ≈ 5 x 10¹¹              |
| 2: 先にソート | O(n log n) | O(1)、コピーありならO(n) | ≈ 2 x 10⁷               |
| 3: 集合 | O(n)       | O(n)                   | ≈ 10⁶                   |

この例が示すこと:

- クラスを改善するのは、異なるアプローチだけである。バリアント1の内側のループを最適化しても、変わるのは定数係数だけである。
- バリアント3は、メモリと引き換えに速度を得ている。

## 一般的な誤り {/* #common-mistakes */}

1. **すべての入れ子のループをO(n²)と数える:** クラスは、各ループが何回実行されるかによって決まる。反復回数が固定の内側のループ(例: 1週間の7日間にわたるもの)は、定数係数を掛けるだけであり、結果はO(n)のままである。
2. **異なる2つの入力をnと表記する:** n人の顧客に対するループと、m個の製品に対するループが入れ子になっている場合は、O(n x m)である。O(n²)は両方の入力が同じサイズであることを前提とし、どちらが処理量を左右しているかを隠してしまう。
3. **定数と小さい項を残す:** O(2n + 5)とO(n² + n)は形式的には正しいが、単純化されていない。クラスはそれぞれO(n)とO(n²)である。大きなnでは、定数と小さい項は増加に影響しないためである。
4. **ビッグOを秒単位の実行時間として読む:** この記法は定数係数を隠すため、O(n²)のアルゴリズムが、小さなnではO(n log n)のアルゴリズムより高速になることがある。挿入ソートは短いリストではマージソートに勝る。そのため、Timsortのような実用的なソート実装は、短い区間に挿入ソートを用いる。
5. **ソートされていないデータに対する二分探索:** O(log n)は、インデックスでアクセスできるソート済みデータに対してのみ成り立つ。事前のソートにはO(n log n)がかかり、同じデータを何度も検索する場合にのみ見合う。
6. **log nとn log nの混同:** O(log n)は線形より増加が遅く、要素数よりはるかに少ないステップで済む。O(n log n)は線形より増加が速く、要素ごとにlog n回のステップを実行する。
7. **最良ケースを計算量として示す:** 線形探索の最良ケースはO(1)であり、典型的な入力については何も語らない。修飾語なしの計算量は、最悪ケースを指す。
