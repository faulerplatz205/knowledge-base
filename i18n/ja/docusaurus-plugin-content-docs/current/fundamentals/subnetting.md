# サブネット化(IPv4)

## サブネット化の基本 {/*#subnetting-basics*/}

サブネット化は、大きなネットワークをより小さく管理しやすいサブネットワーク(サブネット)に分割する。これにより、パフォーマンス、組織化、セキュリティが向上する。

| 用語             | 記号/参照  | 定義                                                         | 例                     |
| ---------------- | ---------- | ------------------------------------------------------------ | ---------------------- |
| **IPアドレス**   | IP         | ネットワーク上のデバイスの一意のアドレス。                   | `192.168.1.10`         |
| **サブネットマスク** | Netmask | ネットワーク部とホスト部を区別する。                         | `255.255.255.0`        |
| **CIDR**         | スラッシュ表記 | マスクの短縮形式(「1」のビットの数)。                    | `/24`                  |
| **ネットワークID** | Net ID   | 「通りの名前」。サブネットの最初のアドレス。                 | `192.168.1.0`          |
| **ブロードキャスト** | Bcast  | *すべて*のデバイスへの呼びかけ。最後のアドレス。             | `192.168.1.255`        |
| **ホスト**       | Host       | サブネット内のデバイス(PC、ルーター)。                     | `.1`から`.254`         |
| **ネットワークビット** | Net-Bits | IPアドレスのうち、ネットワークを識別するビット。           | `/24` => 最初の24ビット |
| **ホストビット** | Host-Bits  | IPアドレスのうち、ネットワーク内のホストを識別するビット。   | `24` => 最後の8ビット    |

**規則:** IPv4アドレスは**32ビット**で構成され、4つのオクテット(各8ビット)に分けられる。  
**形式:** `x.x.x.x`(10進数)または`11000000.10101000.00000001.00001010`(2進数)

---

## サブネットマスクとCIDRの理解 {/*#understanding-subnet-masks--cidr*/}

サブネットマスクは、IPのどの部分が**ネットワーク**(通り)で、どの部分が**ホスト**(番地)であるかをコンピューターに伝える。

### CIDR表記(Classless Inter-Domain Routing) {/*#cidr-notation-classless-inter-domain-routing*/}

CIDR(例:`/24`)は、マスクの**有効なビット**の数を左から数えるだけである。

| CIDR | 10進数のサブネットマスク | 2進数のサブネットマスク(最初のオクテット) | サブネットあたりのホスト数* |
| ---- | ------------------- | --------------------------------- | ----------------- |
| /8   | 255.0.0.0           | `11111111.00000000...`            | 16,777,214        |
| /16  | 255.255.0.0         | `11111111.11111111...`            | 65,534            |
| /24  | 255.255.255.0       | `11111111...11111111.0`           | 254               |
| /25  | 255.255.255.128     | `11111111...1.10000000`           | 126               |
| /26  | 255.255.255.192     | `11111111...1.11000000`           | 62                |
| /30  | 255.255.255.252     | `11111111...1.11111100`           | 2                 |

**注:** 総アドレス数から2を引く(ネットワークIDに1、ブロードキャストに1)。

## 計算方法 {/*#calculation-methods*/}

### 1. サブネットサイズ(ホスト数)の計算 {/*#1-calculating-subnet-size-number-of-hosts*/}

サブネットには(すべてのオクテットを通じて)**合計でいくつのIPアドレス**が含まれるか

```text
Formula (Total Addresses): 2^(Host-Bits) = Total Addresses
Formula (Usable Hosts): 2^(Host-Bits) - 2 = Usable Hosts

Host-Bits = 32 - (CIDR)
```

#### 例:/24ネットワーク {/*#example-24-network*/}

1. **ホストビット:** 32 - 24 = 8ビット
2. **計算:** 2⁸ = 256
3. **使用可能:** 256 - 2 = **254ホスト**

#### 例:/26ネットワーク {/*#example-26-network*/}

1. **ホストビット:** 32 - 26 = 6ビット
2. **計算:** 2⁶ = 64
3. **使用可能:** 64 - 2 = **62ホスト**

---

### 2. 「マジックナンバー」(対象オクテットでのブロックサイズ)の求め方 {/*#2-finding-the-magic-number-block-size-in-the-interesting-octet*/}

マジックナンバーは、サブネット化が行われるオクテット内での**ステップサイズ**を表す。

**重要:** マジックナンバーは「対象のオクテット」(サブネットマスクが0でも255でもないオクテット)にのみ適用される。

```text
Method 1 (Binary Place):
Look at the last bit set to '1' in the subnetmask. Its value is the Magic Number.

Method 2 (Subtraction):
256 - (Last non-zero octet of the mask) = Magic Number
```

#### どのオクテットが「対象」か {/*#which-octet-is-interesting*/}

- `/24 - /32`: **第4オクテット**が変化する
- `/16 - /23`: **第3オクテット**が変化する
- `/8 - /15`: **第2オクテット**が変化する

#### 方法[1](#1-calculating-subnet-size-number-of-hosts)と[2](#2-finding-the-magic-number-block-size-in-the-interesting-octet)の関係 {/*#relationship-between-methods-1--2*/}

- **`/24+`(第4オクテットでのサブネット化)の場合:** マジックナンバー = 2^(ホストビット) ✔
- **`/23-`(それより前のオクテットでのサブネット化)の場合:** 両者は異なる。
  - **サブネットサイズの計算:** 総アドレス数は複数のオクテットにまたがる
  - **「マジックナンバー」の求め方:** マジックナンバーは1つのオクテット内のステップサイズにすぎない

#### 例:/26マスク => 255.255.255.192 - 第4オクテットでのサブネット化 {/*#example-26-mask--255255255192---4th-octet-subnetting*/}

- **対象のオクテット:** 192
- **計算:** 256 - 192 = **64**
- **結果:** ネットワークは64ずつ増加する(0、64、128、192)。

#### 例:`/18`マスク => 255.255.192.0 - 第3オクテットでのサブネット化 {/*#example-18-mask--2552551920---3rd-octet-subnetting*/}

**総サイズ:**

- ホストビット: 32 - 18 = 14
- 総アドレス数: 2^14 = **16,384**

**マジックナンバー(第3オクテットでのステップサイズ):**

- マスク: `255.255.192.0`
- 対象のオクテット: 第3(192)
- マジックナンバー: 256 - 192 = **64**
- 意味: 第3オクテットが64ずつ増加する(0、64、128、192)

**両者の関係:**

- 64は第3オクテットでのステップである
- 各ステップには256個のアドレス(第4オクテット全体)が含まれる
- 合計: 64 × 256 = 16,384 ✔

---

### 3. サブネット数の計算 {/*#3-calculating-number-of-subnets*/}

ネットワークをサブネット化する際には、ホスト部からビットを「借りて」、より多くのネットワークを作る。

```text
Formula: 2^(Borrowed Bits) = Number of Subnets

Borrowed Bits = New CIDR - Original CIDR
```

#### 例:/24から/26へ {/*#example-from-24-to-26*/}

**シナリオ:** `192.168.1.0/24`があり、これを`/26`のサブネットに分割したい場合。

1. **元のネットワーク:** `/24`(合計256アドレス)
2. **新しいサブネットサイズ:** `/26`
3. **借りたビット:** 26 - 24 = **2ビット**
4. **サブネット数:** 2² = **4サブネット**

**結果:** 各64アドレス(使用可能なホストは62)の4つのサブネットが得られる。

| サブネット # | ネットワークID | 最初のホスト  | 最後のホスト  | ブロードキャスト |
| -------- | ------------- | ------------- | ------------- | ------------- |
| 1        | 192.168.1.0   | 192.168.1.1   | 192.168.1.62  | 192.168.1.63  |
| 2        | 192.168.1.64  | 192.168.1.65  | 192.168.1.126 | 192.168.1.127 |
| 3        | 192.168.1.128 | 192.168.1.129 | 192.168.1.190 | 192.168.1.191 |
| 4        | 192.168.1.192 | 192.168.1.193 | 192.168.1.254 | 192.168.1.255 |

#### 例:/16から/24へ {/*#example-from-16-to-24*/}

**シナリオ:** ISPから`10.0.0.0/16`が割り当てられ、部門用に`/24`のネットワークが必要な場合。

1. **元:** `/16`
2. **新:** `/24`
3. **借りたビット:** 24 - 16 = **8ビット**
4. **サブネット数:** 2⁸ = **256サブネット**

**結果:** 256個の部門ネットワークを作成できる(10.0.0.0/24、10.0.1.0/24、...、10.0.255.0/24)。

## 段階的な計算例 {/*#step-by-step-example-calculation*/}

**課題:** IP `192.168.10.150`をマスク`255.255.255.192`(/26)で分析する。

### ステップ1:マジックナンバー(ブロックサイズ)を求める {/*#step-1-find-the-magic-number-block-size*/}

- マスクは`/26`である。変化は第4オクテットで起こる。
- 第4オクテットのマスク: `192`
- マジックナンバー: `256 - 192 = 64`

### ステップ2:サブネットの範囲を決定する {/*#step-2-determine-subnet-ranges*/}

IPアドレス(`150`)を超えるまで64ずつ増やす。

- サブネット1: `0 - 63`
- サブネット2: `64 - 127`
- サブネット3: `128 - 191`  (150はこの範囲に入る)
- サブネット4: `192 - 255`

### ステップ3:アドレスを計算する {/*#step-3-calculate-addresses*/}

IP `192.168.10.150`は`.128`サブネットに属する。

| 種類           | 計算                 | 結果               |
| -------------- | -------------------- | ------------------ |
| **ネットワークID** | ブロックの開始   | **192.168.10.128** |
| **最初のホスト** | ネットワークID + 1 | **192.168.10.129** |
| **最後のホスト** | ブロードキャスト - 1 | **192.168.10.190** |
| **ブロードキャスト** | 次のブロック(192) - 1 | **192.168.10.191** |

## クイックリファレンス:一般的なサブネット {/*#quick-reference-common-subnets*/}

| CIDR    | マスク(.x) | マジックナンバー | 使用可能ホスト数 | 典型的な用途                     |
| ------- | --------- | ------------ | ------------ | -------------------------------- |
| **/24** | .0        | 256          | 254          | 標準的なLAN(家庭/オフィス)       |
| **/25** | .128      | 128          | 126          | LANを半分に分割する              |
| **/26** | .192      | 64           | 62           | 部門のネットワーク               |
| **/27** | .224      | 32           | 30           | 小規模なチーム                   |
| **/28** | .240      | 16           | 14           | ごく小さなグループ               |
| **/29** | .248      | 8            | 6            | 転送ネットワーク(ルーター間)   |
| **/30** | .252      | 4            | 2            | ポイントツーポイントリンク       |
| **/32** | .255      | 1            | 1            | 単一ホストのIP(ループバック)     |

## よくある落とし穴 {/*#common-pitfalls*/}

- **ID/ブロードキャストの見落とし:** *使用可能な*ホスト数を得るには、常に2を引く。
- **誤ったステップ:** サブネットの範囲は端を含む。したがって、最初のサブネットは`start + block size − 1`で終わる。最初のサブネットが正しければ、以降のサブネットの終端は、直前のサブネットの終端にブロックサイズを加えるか、各サブネットのネットワークアドレスを使って同じ`start + block size − 1`の式を適用することで計算できる。
- **偶数/奇数:** ネットワークIDは通常偶数であり、ブロードキャストは通常奇数である。
- **誤ったオクテット:** `/18`のサブネットは、第4オクテットではなく*第3*オクテットで変化する。
- `/8 - /15`: 第2オクテットで変化
- `/16 - /23`: 第3オクテットで変化
- `/24 - /32`: 第4オクテットで変化
