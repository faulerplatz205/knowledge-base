# データベース開発のフェーズ

データベースの開発は、通常、連続する4つのフェーズに分けられ、各フェーズは前のフェーズよりも具体的な成果物を生み出す。

## 1. 外部フェーズ {/*#1-external-phase*/}

将来のすべてのユーザーとステークホルダーグループから要件を収集し、分析する。目標は、データベースをどのように構造化するかをまだ考えずに、システムがどのデータを管理し、どの操作をサポートしなければならないかを理解することである。

典型的な成果物は、要件定義書と、データおよびビジネスルールの非公式な記述である。

## 2. 概念フェーズ {/*#2-conceptual-phase*/}

要件を、実装に依存しない抽象的なデータモデルに変換する。そのための標準的なツールは[**実体関連モデル (ERM)**](./er-model.md)であり、エンティティ、その属性、およびそれらの間の関連を捉える。

概念モデルは技術に依存しない。データがどのような*形*をしているかを記述するものであり、*どのように*保存されるかは記述しない。

## 3. 意味フェーズ {/*#3-semantic-phase*/}

整合性制約、カーディナリティ、ビジネスルールを正確に定義して、概念モデルを精緻化し、形式化する。その後、ERMは[**リレーショナルデータベーススキーマ**](./database-schema.md)(テーブル、列、主キー、外部キー)へ変換される。

このフェーズには、冗長性と異常を排除する[**正規化**](./normalization.md)も含まれる。

## 4. 物理フェーズ {/*#4-physical-phase*/}

リレーショナルモデルを、具体的なDBMS(例: PostgreSQL、MySQL)に実装する。このフェーズでは、次のことを行う。

- 適切なデータ型を持つ`CREATE TABLE`文を記述する
- クエリ性能を最適化するためのインデックスを定義する
- 選択したDBMS固有のストレージパラメーターを設定する
- アクセス制御とセキュリティポリシーを設定する

物理モデルは対象システムと密接に結び付いており、DBMS製品によって異なることがある。
