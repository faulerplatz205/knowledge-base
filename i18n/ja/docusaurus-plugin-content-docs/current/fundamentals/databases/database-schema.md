# データベーススキーマ

データベーススキーマは、リレーショナルデータベースの構造、すなわちテーブル、データ型を持つ列、キー、テーブル間の参照を記述する。[ERモデル](./er-model.md)とは異なり、リレーショナルモデルに束縛される。リレーションシップは独立した要素としては存在せず、外部キーと連関テーブルによって表現される。スキーマは[データベース開発](./database-development-phases.md)の意味フェーズで作成され、物理フェーズで`CREATE TABLE`文によって実装される。

## 用語 {/*#terminology*/}

| リレーショナル用語 | 一般的な用語       | 意味                                                     |
| ------------------ | ------------------ | -------------------------------------------------------- |
| リレーション       | テーブル           | 同じ属性を持つ行の集合                                   |
| タプル             | 行、レコード       | テーブルの1つのエントリ                                  |
| 属性               | 列                 | テーブルのすべての行が持つ性質                           |
| ドメイン           | データ型           | 属性がとりうる値の集合                                   |
| リレーションスキーマ | テーブル定義     | テーブル名とその属性                                     |
| データベーススキーマ | データベース構造 | データベースのすべてのリレーションスキーマとその制約     |

## キー {/*#keys*/}

- **候補キー:** すべての行を一意に識別する属性の最小の集合。テーブルは複数持つことができる。例:`CustomerID`と`Email`。
- **主キー(PK):** 行を識別するために選ばれた候補キー。一意でなければならず、`NULL`であってはならない。
- **複合キー:** 複数の属性で構成されるキー。例:`(OrderID, LineNumber)`。
- **外部キー(FK):** 別のテーブルまたは同じテーブルの主キーを参照する1つ以上の属性。連関テーブルや弱エンティティのテーブルのように、主キーの一部になることもある。
- **自然キー:** データ自体から取られるキー。例:ISBN。
- **代理キー:** データベースの外では意味を持たない人工的なキー。通常は自動採番の数値またはUUID。

## 表記法 {/*#notation*/}

### テキスト表記 {/*#textual-notation*/}

各テーブルは、その名前の後に括弧で属性を並べて記述する。

| 印                                               | 意味                                                       |
| ------------------------------------------------ | ---------------------------------------------------------- |
| 下線                                             | 主キー。複合キーの場合はすべての構成要素に下線を引く       |
| 先頭の`#`または`↑`、場合により破線の下線 | 外部キー                                                   |
| 接尾辞`PK`または`FK`                       | 下線を引けない場合の、プレーンテキストでの代替表記         |

主キーかつ外部キーである属性には、下線を引き、`#`を付ける。

### テーブル図 {/*#table-diagram*/}

- **ボックス:** 1つのテーブル。ヘッダーにテーブル名、線の下に列を記載する
- **`PK`と`FK`:** 列の前に付ける印。`PK FK`は両方に該当する列を示す
- **線:** 2つのテーブル間の外部キーによる参照
- **線の端:** カーディナリティ。`1`または`N`

## ERモデルからの変換 {/*#transformation-from-an-er-model*/}

| ERの要素                          | データベーススキーマ                                                                              |
| --------------------------------- | ------------------------------------------------------------------------------------------------- |
| エンティティ型                    | テーブル                                                                                          |
| 属性                              | 列                                                                                                |
| キー属性                          | 主キー                                                                                            |
| 複合属性                          | 下位属性ごとに1列。例:`Street`、`City`、`ZIP`                                                    |
| 多値属性                          | 所有者への外部キーを持つ別テーブル。例:`PhoneNumbers (#CustomerID, Number)`         |
| 導出属性                          | 通常は保存せず、クエリ内で計算する                                                                |
| 1:1リレーションシップ             | 2つのテーブルのいずれかに、`UNIQUE`制約を持つ外部キー                                              |
| 1:Nリレーションシップ             | N側のテーブルの外部キー                                                                           |
| N:Mリレーションシップ             | 両方のテーブルへの外部キーで主キーが構成される連関テーブル                                        |
| リレーションシップの属性          | 外部キーを持つテーブルの列。N:Mの場合は連関テーブルの列                                           |
| 弱エンティティ                    | 所有者の主キー(外部キーでもある)と部分キーを組み合わせた主キーを持つテーブル                      |
| N側の全面的参加                   | `NOT NULL`として宣言された外部キー                                                                   |

リレーションシップの属性`EnrolledOn`を持つ、学生とコースの間のN:Mリレーションシップ:

```text
Students    (StudentID, Name)
             ─────────
Courses     (CourseID, Title)
             ────────
Enrollments (#StudentID, #CourseID, EnrolledOn)
             ──────────  ─────────
```

## 参照整合性 {/*#referential-integrity*/}

すべての外部キーの値は、参照先テーブルに存在する主キーの値と一致するか、列が許す場合は`NULL`でなければならない。この規則に違反する挿入または更新は、DBMSによって拒否される。参照される行が削除された場合(`ON DELETE`)や、その主キーが変更された場合(`ON UPDATE`)の動作は、外部キーごとに設定する。

| オプション               | 参照される行を削除した場合の効果                                        |
| ------------------------ | ----------------------------------------------------------------------- |
| `RESTRICT` / `NO ACTION` | 参照する行が存在する間、削除は拒否される(デフォルト)                    |
| `CASCADE`                | 参照する行も削除される。例:削除された注文の明細                         |
| `SET NULL`               | 外部キーが`NULL`に設定される。列は`NULL`を許可していなければならない  |

## 例:注文管理 {/*#example-order-management*/}

[ERモデル](./er-model.md)の例は3つのテーブルになる。1:Nリレーションシップ`places`は、`Orders`の外部キー`CustomerID`になる。識別リレーションシップ`contains`により、`OrderID`は`OrderItems`の主キーの一部になる。

```text
Customers  (CustomerID, Name, Email)
            ──────────
Orders     (OrderID, #CustomerID, OrderDate)
            ───────
OrderItems (#OrderID, LineNumber, Quantity)
            ────────  ──────────
```

```text
┌─────────────────────┐          ┌──────────────────────┐
│ Customers           │          │ Orders               │
├─────────────────────┤          ├──────────────────────┤
│ PK     CustomerID   │1        N│ PK     OrderID       │
│        Name         ├──────────┤ FK     CustomerID    │
│        Email        │          │        OrderDate     │
└─────────────────────┘          └──────────┬───────────┘
                                            │ 1
                                            │
                                            │ N
                                 ┌──────────┴───────────┐
                                 │ OrderItems           │
                                 ├──────────────────────┤
                                 │ PK FK  OrderID       │
                                 │ PK     LineNumber    │
                                 │        Quantity      │
                                 └──────────────────────┘
```

```sql
CREATE TABLE Customers (
    CustomerID INT          PRIMARY KEY,
    Name       VARCHAR(100) NOT NULL,
    Email      VARCHAR(255) NOT NULL UNIQUE
);

CREATE TABLE Orders (
    OrderID    INT  PRIMARY KEY,
    CustomerID INT  NOT NULL,
    OrderDate  DATE NOT NULL,
    FOREIGN KEY (CustomerID) REFERENCES Customers (CustomerID)
);

CREATE TABLE OrderItems (
    OrderID    INT NOT NULL,
    LineNumber INT NOT NULL,
    Quantity   INT NOT NULL,
    PRIMARY KEY (OrderID, LineNumber),
    FOREIGN KEY (OrderID) REFERENCES Orders (OrderID) ON DELETE CASCADE
);
```

## よくある間違い {/*#common-mistakes*/}

1. **外部キー列のない線:** N側のテーブルに外部キー列がない限り、2つのテーブル間の線は参照を作らない。
2. **1側の外部キー:** `Customers`の列`OrderID`は、顧客ごとに1件の注文しか保持できない。
3. **連関テーブルのないN:M:** 外部キー列は1行につき1つの値しか保持しないため、どちらかのテーブルに外部キーを置くと、その側は1つの相手に制限される。
4. **代理キーのみの連関テーブル:** 外部キーのペアが主キーでも`UNIQUE`でもない場合、同じ学生が同じコースに2回登録できてしまう。
5. **スキーマでのER表記:** ひし形、属性の楕円、リレーションシップ名はER図に属する。スキーマにはテーブル、`PK`と`FK`の印、参照を示す。
6. **予約語のテーブル名:** `ORDER`と`GROUP`はSQLの予約語であり、テーブル名として使う場合はすべての文で引用符で囲むか、別の名前に置き換えなければならない。
