# データベース概要

## 概要 {/*#overview*/}

データベースは、データベース管理システム (DBMS) によって管理される、構造化されたデータの組織的な集合である。2つの主要なパラダイムは、**リレーショナル (SQL)** データベースと**非リレーショナル (NoSQL)** データベースである。

## リレーショナルデータベース (SQL) {/*#relational-databases-sql*/}

データは、行と列を持つ**テーブル**に保存される。各レコードは**主キー**によって一意に識別され、テーブルは**外部キー**を通じて結び付けられ、構造化されたスキーマを形成する。

- データは**SQL** (Structured Query Language) を用いてクエリされる
- スキーマは事前に定義され、データベースによって強制される
- 明確な関係を持つ構造化データに最も適している

**一般的なシステム**: PostgreSQL、MySQL、SQLite、Microsoft SQL Server、Oracle DB

### 主要な概念 {/*#key-concepts*/}

**[正規化](./normalization.md)**: データの冗長性を減らすためのテーブルの整理:

- **第1正規形**: 原子値であり、繰り返しグループがない
- **第2正規形**: 複合キーへの部分従属がない
- **第3正規形**: 推移的従属がない

**ACID特性**: 信頼性の高いトランザクションのための保証:

- **原子性 (Atomicity)**: トランザクションは、完全に成功するか、完全に失敗するかのどちらかである
- **一貫性 (Consistency)**: データは常に、1つの有効な状態から別の有効な状態へ移行する
- **分離性 (Isolation)**: 同時実行されるトランザクションが互いに干渉しない
- **永続性 (Durability)**: コミットされた変更は、クラッシュ後も保持される

## 非リレーショナルデータベース (NoSQL) {/*#non-relational-databases-nosql*/}

非構造化または半構造化データを、柔軟かつスケーラブルに保存するために設計されている。固定のスキーマは不要である。

| 種類          | 説明                                 | システム例  |
| ------------- | ------------------------------------------- | ---------------- |
| ドキュメント      | JSON形式のドキュメントを保存する                  | MongoDB, CouchDB |
| キーバリュー     | 単純なキー => 値のペア                   | Redis, DynamoDB  |
| カラムファミリー | 列指向の読み書きに最適化されている         | Apache Cassandra |
| グラフ         | 関係性の多いデータのためのノードとエッジ | Neo4j            |

## リレーショナルとNoSQLの比較 {/*#relational-vs-nosql*/}

|                | リレーショナル                     | NoSQL                                      |
| -------------- | ------------------------------ | ------------------------------------------ |
| スキーマ         | 固定、事前定義              | 柔軟 / スキーマレス                     |
| クエリ言語 | SQL                            | 製品により異なる(例: MongoDB Query Language)      |
| スケーリング        | 垂直(スケールアップ)            | 水平(スケールアウト)                     |
| 一貫性    | 強い (ACID)                  | 多くの場合、結果整合性                 |
| 最適な用途       | 構造化データ、複雑な結合 | 大規模、柔軟または階層的なデータ |
