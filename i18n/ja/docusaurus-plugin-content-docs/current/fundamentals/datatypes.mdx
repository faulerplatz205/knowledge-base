# データ型

## 概要 {/* #overview */}

データ型は、すべての変数、引数、戻り値について次の3点を定める。

- **値の範囲:** どの値が有効か。例: 真偽値の `true` と `false`
- **メモリ使用量:** 1つの値のために何バイトが確保されるか
- **演算:** 値に対して何ができるか。例: `+` は数値では加算を、文字列では連結を意味する

| カテゴリ | 保持するもの | 例 |
| ------------- | --------------------------------- | ------------------------------------ |
| **プリミティブ** | 分割できない値を1つだけ | `int`, `double`, `boolean`, `char`   |
| **複合** | 1つの名前の下に複数の値 | 配列、タプル、レコード、オブジェクト、文字列 |
| **抽象** | 具体的な構造ではなく契約 | インターフェース、ジェネリック型パラメータ    |

:::info
以下の型名とサイズは、一般的なC/Java/C#系の言語に従う。他の言語では異なる。Pythonの整数は任意精度であり、JavaScriptには64ビット浮動小数点数に基づく単一の `number` 型しかなく、Goでは型がビット幅で命名される(`int32`, `uint64`)。
:::

## プリミティブデータ型 {/* #primitive-data-types */}

### 整数型 {/* #integer-types */}

整数は小数部のない整数値を格納する。値の範囲はビット数 `n` から直接決まる。

```text
signed:    -2^(n-1)  to  2^(n-1) - 1
unsigned:         0  to  2^n - 1
```

| ビット数 | 一般的な名称 | 符号付きの範囲                                            | 符号なしの範囲                  |
| ---- | ------------ | ------------------------------------------------------- | ------------------------------- |
| 8    | `byte`       | -128 ~ 127                                             | 0 ~ 255                        |
| 16   | `short`      | -32,768 ~ 32,767                                       | 0 ~ 65,535                     |
| 32   | `int`        | -2,147,483,648 ~ 2,147,483,647                         | 0 ~ 4,294,967,295              |
| 64   | `long`       | -9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807 | 0 ~ 18,446,744,073,709,551,615 |

**補足:**

- 符号付き整数では1ビットが符号の表現に使われるため、符号付きの範囲は符号なしのおよそ半分になる。
- 0が非負の値の1つとして数えられるため、負の側は正の側よりも1つ分だけ広い。

### 浮動小数点型 {/* #floating-point-types */}

浮動小数点型は、小数部を持つ数値をIEEE 754に従い、符号、仮数、指数として格納する。

| ビット数 | 一般的な名称      | 有効桁数(10進) | おおよその大きさ |
| ---- | ----------------- | -------------------------- | --------------------- |
| 32   | `float`, `single` | 約7桁                    | 最大 3.4 x 10^38     |
| 64   | `double`          | 約15~16桁             | 最大 1.8 x 10^308    |

仮数が2進数であるため、`0.1` のような10進小数は正確に表現できない。

```text
0.1 + 0.2 = 0.30000000000000004
```

**このことから導かれる重要な注意点:**

- 浮動小数点値は `==` で比較せず、小さな許容誤差に対して比較する
- 金額は `float` や `double` では保存せず、[固定小数点型](#fixed-point-types)またはセント単位の整数として保存する

### 固定小数点型 {/* #fixed-point-types */}

固定小数点型は、固定された桁数の小数部を格納する。内部的には、値は10のべき乗でスケーリングされた整数として保持される。たとえば `12.34` はスケール2の `1234` として保持される。そのため、浮動小数点型にはできない10進小数の正確な表現が可能になる。

**例:**

`DECIMAL(10, 2)` は全体で10桁、そのうち小数点以下が2桁であることを意味し、小数点より前は8桁となる。

この正確さの代償として、演算は `double` よりもかなり遅くなり、メモリ使用量も大きくなる。したがって固定小数点型は、正確さが必須の場面、とりわけ金額、税率、請求書の合計に用いられ、測定値やグラフィックスには用いられない。

### 真偽値 {/* #boolean */}

真偽値は、2つの真理値 `true` と `false` のいずれか一方を保持し、すべての比較演算と論理演算(`&&`, `||`, `!`)の結果型となる。1ビットで足りるが、メモリはバイト単位でアドレス指定されるため、通常は少なくとも1バイトが確保される。

### 文字 {/* #character */}

文字型は1文字を保持し、文字エンコーディングの数値コードポイントとして格納される。

| エンコーディング | 1文字あたりのサイズ   | 範囲                                    |
| -------- | -------------------- | ---------------------------------------- |
| ASCII    | 1バイト(7ビット使用) | 128文字、ウムラウトなし               |
| UTF-8    | 1~4バイト         | Unicode全体、ASCII互換           |
| UTF-16   | 2または4バイト         | Unicode全体、JavaとC#の `char` で使用 |

**豆知識:** 文字は数値として格納されるため、算術演算や比較が可能である。`'A' + 1` は `'B'` になり、`'a' < 'b'` は `true` である。

## 複合データ型 {/* #composite-data-types */}

### 文字列 {/* #string */}

文字列は文字の並びである。実装を分ける設計上の判断は2つある。

- **長さ:** 固定(アプリケーションコードでは稀)または可変
- **可変性:** Java、C#、Pythonでは不変、C++とRustでは可変

文字列が不変である場合、変更のたびに新しいオブジェクトが作られる。したがって、ループ内で連結を繰り返して文字列を組み立てると、毎回テキスト全体がコピーされるため、ビルダー型(`StringBuilder`, `StringBuffer`)に置き換えられる。

### 配列 {/* #array */}

配列は、**同じ型**の固定数の要素を1つの名前の下に格納し、0から始まるインデックスでアクセスする。

```text
scores = [17, 42, 8, 23]

scores[0] = 17
scores[3] = 23
```

特徴:

- サイズは作成時に固定されるため、拡張には新しい配列の作成とコピーが必要になる
- アドレスが `start + index x elementSize` として計算されるため、インデックスによるアクセスは定数時間で行われる
- 多次元配列(`matrix[row][column]`)は表やグリッドを表現する

### タプル {/* #tuple */}

タプルは、**異なる型でもよい**固定数の値を固定された順序でまとめる。要素は名前ではなく位置で指定される。

```text
point    = (3, 7)
httpCall = ("GET", "/users", 200)
```

タプルは、専用の型を宣言せずに関数から複数の値を返す場合に便利である。位置の説明が必要になった時点で、レコードのほうが適している。

### レコード、構造体、オブジェクト {/* #record-struct-and-object */}

レコード(構造体、またはクラスのオブジェクトとも呼ばれる)は、異なる型の値を**名前付き**フィールドの下にまとめる。

```text
Customer {
    id:      int
    name:    string
    active:  boolean
    revenue: decimal
}
```

タプルとは異なり、すべてのフィールドが名前を持つため、各値の意味が明確になり、既存の位置を壊さずに型を拡張できる。

### 列挙型 {/* #enumeration */}

列挙型(enum)は、許可される値の固定された名前付きの集合を定義する。

```text
enum OrderState { NEW, PAID, SHIPPED, CANCELLED }
```

マジックナンバーや緩い文字列定数に対する利点は、集合外の値をコンパイラが拒否し、有効な状態がすべて1か所に文書化されることである。

### コレクション {/* #collections */}

リスト、集合、マップ、キューは、言語のコアではなく標準ライブラリが提供する複合型である。これらはデータ構造の項で別途扱われる。{/* TODO: add link to datastructures.md here once it exists */}

## 型変換 {/* #type-conversion */}

ある型から別の型への値の変換は、**暗黙的**(コンパイラが自動的に実行)か、**明示的**(キャストや変換関数によってソースコード内で要求)のいずれかである。

| 方向     | 意味                            | 例         | リスク                 |
| ------------- | ---------------------------------- | --------------- | -------------------- |
| **拡大変換**  | 変換先の範囲が変換元の範囲を含む | `int` => `long` | なし、損失なし       |
| **縮小変換** | 変換先の範囲が小さい            | `long` => `int` | オーバーフロー、切り捨て |

```text
implicit widening:   long total = 42;          // int fits into long
explicit narrowing:  int  count = (int) 42L;   // cast required
truncation:          int  n     = (int) 3.99;  // yields 3, not 4
```

文字列と数値の間の変換は、メモリ上の表現が完全に変わるため、キャストではなく**パース**または**フォーマット**である。パースは入力に依存するため失敗することがあり、そのためエラーを返すか例外をスローする。

## よくある落とし穴 {/* #common-pitfalls */}

- **整数オーバーフロー:** 最大値に1を加えると、ほとんどの言語ではエラーにならず最小値に巻き戻る
- **整数除算:** 両方のオペランドが整数である限り、`7 / 2` は `3.5` ではなく `3` になる
- **浮動小数点の比較:** `0.1 + 0.2 == 0.3` は `false` と評価される
- **金額を浮動小数点で扱うこと:** 丸め誤差が多数の演算にわたって蓄積する
- **縮小変換時の切り捨て:** 浮動小数点値を整数にキャストすると小数部が切り捨てられ、丸められることはない
- **デフォルトで大きすぎる型を使うこと:** `byte` で足りる場面での `long` は、大きな配列やレコードでメモリを無駄にする

## データ型の選び方 {/* #choosing-a-data-type */}

1. **値の範囲:** 想定される増加も含め、正当に発生しうる最大値と最小値
2. **精度:** 小数部が必要かどうか、また正確である必要があるか(金額)、近似でよいか(測定値)
3. **メモリと性能:** 大きな配列、組み込みシステム、ネットワーク転送では重要であり、個々の変数では無視できる
4. **意味付け:** 無効な値を型自体で排除できるか。例: 文字列の代わりに列挙型、`0` と `1` の代わりに真偽値を使うことで、誤った値がコンパイル時に失敗する
