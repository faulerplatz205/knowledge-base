# プロジェクトフェーズ

## 概要 {/* #overview */}

5つのプロジェクトフェーズは、チームがプロジェクトを組織的に計画、実行、完了するための構造化されたフレームワークを提供する。各フェーズは前のフェーズの成果の上に成り立つ。

フェーズは、プロジェクトが明確な終了日を持つ一回限りの取り組みか、すでに本番環境で使用されながら継続的に開発される製品かによって、多少異なる。

## フェーズ {/* #phases */}

### 1. 初期化 / 分析 {/* #1-initialization--analysis */}

初期化フェーズでは、プロジェクトのアイデアを評価し、その実現可能性を査定する。目的は、多くのリソースを投入する前に、プロジェクトに取り組む価値があるかどうかを判断することである。

- プロジェクトの目標と期待される成果を定義する
- フィージビリティスタディを実施する
- 主要なステークホルダーを特定する
- 初期のリスク評価を行う
- 大まかな費用対効果分析を作成する

このフェーズは、通常、プロジェクト憲章またはGo/No-Goの決定で完了する。

### 2. 計画 {/* #2-planning */}

計画フェーズでは、チームがプロジェクトをどのように実施するかについて詳細なロードマップを作成する。後の問題を防ぐうえで最も重要なフェーズである。

- プロジェクトのスコープと成果物を定義する
- 作業分解構成図(WBS)を作成する
- 時間、コスト、リソースを見積もる
- スケジュールを作成する(例: ガントチャート  {/* (./gantt.md) */} やネットワーク図 {/* (./network-plan.md) */} を使用)
- マイルストーンと品質基準を定義する
- リスク軽減策を計画する
- 役割と責任を割り当てる

### 3. 実装 / 実行 {/* #3-implementation--execution */}

実装フェーズでは、計画に従って実際の作業が行われる。プロジェクトマネージャーはチームを調整し、プロジェクトが軌道に乗り続けるようにする。

- プロジェクト計画で定義されたタスクを実行する
- チームメンバーと外部パートナーを調整する
- ステークホルダーに進捗を伝える
- 変更管理プロセスを通じて変更を管理する
- 決定事項と計画からの逸脱を文書化する

### 4. テスト / モニタリング {/* #4-testing--monitoring */}

テストとモニタリングのフェーズは、多くの場合、[実装フェーズ](#3-implementation--execution)と並行して進む。その目的は、成果物が定義された品質基準を満たしていることを確認することである。

- 受け入れ基準に照らして成果物を検証する
- 主要な指標(予算、タイムライン、スコープ)で進捗を追跡する
- 逸脱を早期に特定して対処する
- 品質保証とテストを実施する
- 定期的にステークホルダーへ状況を報告する

### 5. 完了 / 運用 {/* #5-completion--operation */}

最終フェーズはプロジェクトの種類によって異なる。

**一回限りのプロジェクト**は、正式なクローズで終了する。

- 成果物をクライアントまたはエンドユーザーに引き渡す
- 正式な受け入れと承認を得る
- 将来のプロジェクトのために教訓を文書化する
- プロジェクト文書をアーカイブする
- リソースを解放し、契約を終了する

**継続的な製品**は、運用フェーズへ移行する。

- 製品を本番環境にデプロイする
- 運用チームまたはサポートチームに引き継ぐ
- モニタリングと保守のプロセスを確立する
- 今後のイテレーションと改善を計画する
