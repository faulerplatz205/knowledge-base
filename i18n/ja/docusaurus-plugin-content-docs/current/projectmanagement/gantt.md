# ガントチャート

## 概要 {/*#overview*/}

ガントチャートは、プロジェクトスケジュールを時間軸に沿って可視化する横棒グラフである。プロジェクトのタイムラインをチームやステークホルダーに伝えるために最も広く使われているツールの1つである。

## 構成 {/*#structure*/}

- **行**: 個々のタスクまたはワークパッケージ
- **列**: 時間軸(日、週、月)
- **バー**: 開始日と終了日に基づく個々のタスクの期間
- **依存関係**: 矢印や重なりでタスク間の依存関係を示せる

## 特徴 {/*#characteristics*/}

- 技術者でないステークホルダーにとっても理解しやすく、作成しやすい
- タスク数が管理可能な範囲にある短期プロジェクトに適している
- リソース配分よりも時間ベースの計画に重点を置く
- 通常、ウォーターフォール型またはフェーズ型のプロジェクトで使用される
- 静的な表現であり、計画時点のスナップショットを反映するもので、リアルタイムの進捗は反映しない

## 利点 {/*#advantages*/}

- 読みやすく、ステークホルダーに伝えやすい
- プロジェクト全体のタイムラインを明確に把握できる
- 並行して進むタスクと順次進むタスクが分かる
- 小規模から中規模のプロジェクトでは作成と保守が容易である

## 欠点 {/*#disadvantages*/}

- クリティカルパスを特定できない
- タスクが多い大規模プロジェクトでは扱いにくくなる
- 1つのタスクを変更すると、依存するタスクを手作業で調整する必要がある

## 例 {/*#example*/}

小規模なチームが、5週間後の製品ローンチに向けてランディングページを構築する。プロジェクトマネージャーはタイムラインを計画するためにガントチャートを作成する。

1. **要件定義**(第1週): チームがマーケティング部門から要件を収集し、ページの内容を定義し、スコープに合意する
2. **デザイン**(第1週から第2週): 要件の最終化と並行してデザイナーがモックアップの作成を開始し、最初のフェーズとわずかに重なる
3. **実装**(第2週から第4週): デザインの方向性が固まった後、開発者がページの構築を開始する。これが最も長いフェーズである
4. **テスト**(第4週): 開発が継続中のうちに、QAが完成した部分のテストを開始する
5. **デプロイ**(第5週): 最終承認後、ローンチ日に先立ってページが本番環境にデプロイされる

ガントチャートにより、どのフェーズが重なっているか、どこで引き継ぎが発生するか、5週間という期限が現実的かどうかをチームが容易に把握できる。
